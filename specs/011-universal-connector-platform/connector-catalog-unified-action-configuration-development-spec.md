# 接入类型统一业务动作配置与零代码使用开发规格

> 状态：待评审修订、待开发
> 日期：2026-07-26

> 适用范围：UCP 接入类型管理、接入系统、业务能力、流程编排、动作测试与试运行
> 原子任务：X0253 ～ X0260

## 1. 背景与目标

### 背景

当前 UCP 已有接入类型目录、系统实例、凭证、业务能力、流程画布和试运行基础能力，但存在以下问题：

- 接入类型下的预置业务能力仍暴露 HTTP 方法、相对路径、输入/输出 JSON Schema，不符合点选式配置目标。
- 系统详情存在“扩展能力/新增业务能力”方向，导致同一类系统的动作定义可能分散到不同实例，产生版本漂移、权限扩大和流程复用困难。
- 动作测试表单未完整按字段类型渲染；映射缺少真实样本、点击填充、智能匹配和稳定回显。
- 条件和试运行仍有技术化表达，未完全转化为业务人员可理解的交互与错误提示。

### 核心产品决策

**所有新建业务动作统一归属“接入类型管理”，不得在某个已接入系统实例下新建专属动作。**

```text
接入类型管理
  └─ 定义接入策略、系统实例表单、预置业务动作、版本与发布
        ↓
接入系统
  └─ 选择接入类型、绑定凭证、填写实例差异字段、启用和测试已发布动作
        ↓
流程编排
  └─ 选择已启用动作、配置业务参数、映射、条件、试运行
```

同一接入类型的多个实例，例如“飞书正式环境”和“飞书测试环境”，共享同一套已发布业务动作。实例差异只能通过凭证、环境、企业/应用标识、资源标识等系统实例配置处理。

### 决策替代范围与分类边界

本规格替代 `connector-catalog-system-extension-development-spec.md` 中“系统级自定义业务能力”的**新建、编辑、导入、提交和发布**设计；该旧规格中接入类型目录、系统接入、资源管理、凭证、安全策略和历史运行兼容设计仍继续适用。不得将“替代系统级动作”理解为删除历史数据、模板或既有 Pipeline。

所有可被**新建 Pipeline**选择的业务动作必须为类型级动作：`UcpOperationDefinition.package_id` 必填、`system_id` 必须为空、`scope=PACKAGE`。分类边界固定如下：

| 接入类型分类 | 新建业务动作 | 系统实例职责 | 资源与例外处理 |
|---|---|---|---|
| `STANDARD_SAAS` | 仅在接入类型包内定义、测试、审批和发布。 | 绑定凭证、填写环境/企业/应用标识，启用和测试已发布动作。 | 不允许新增系统专属动作。 |
| `CONTROLLED_API` | 仅在受控 API 接入类型包内定义、测试、审批和发布；即使该包当前只服务一个业务域或租户也不例外。 | 填写经过 Schema 约束的实例配置并绑定凭证，不得覆盖动作定义。 | 不再使用 `supports_custom_operations` 作为新建系统动作开关；接口或 Schema 确有差异时，应创建独立接入类型包/版本，或先开发 Adapter。 |
| `INSTANCE_RESOURCE` | 不定义独立 HTTP 业务动作。 | 不得作为独立系统创建；资源必须挂在既有系统的资源管理下并继承父系统凭证和安全策略。 | 类型级动作或 Adapter 可受控引用资源标识；不得在资源详情新增任意 HTTP 动作。 |

动作、实例和单次调用数据必须严格分层：

| 数据归属 | 内容 | 示例 |
|---|---|---|
| 接入类型动作定义 | 方法、相对路径、输入输出字段、分页、错误规则、脱敏规则、风险等级。 | “查询候选人”。 |
| 系统实例配置 | 凭证、环境、企业 ID、应用 ID、固定资源标识。 | “飞书招聘生产环境”。 |
| 流程节点或测试表单 | 本次调用的业务数据。 | 姓名、手机号、审批人、通知内容。 |

历史 `scope=SYSTEM` 动作统一标记为 `LEGACY_SYSTEM_OPERATION`，采用以下兼容规则：

| 历史状态/引用 | 允许操作 | 禁止操作 | 迁移方式 |
|---|---|---|---|
| 草稿、测试通过、待审批 | 查询、审计、查看测试记录。 | 编辑、导入、提交、发布、复制为新的系统动作。 | 平台管理员可显式“复制为类型级草稿”，并在目标接入类型下重新测试、审批和发布。 |
| 已发布系统动作 | 查询、审计、按原引用运行。 | 编辑、复制、停用后重新发布、创建同类系统动作。 | 仅通过显式复制创建新的类型级版本；不得自动提升。 |
| 已发布 Pipeline 的旧动作引用 | 按原 `operation_id` 继续运行和排障。 | 静默替换为类型级动作。 | 流程维护者在编辑时明确选择升级，并完成映射、条件和试运行验证。 |

旧写接口必须统一返回 `409 OPERATION_SCOPE_RETIRED`，提示“业务动作必须在接入类型管理中统一创建并发布”。保留历史查询、运行、审计和只读投影接口；不得通过仅隐藏前端入口规避后端写入限制。

### 目标

- 平台管理员可通过前端可视化配置已支持协议和认证模型的接入类型及业务动作。
- 系统管理员可在现有 `接入系统` 页面完成系统接入、凭证绑定、动作启用和动作测试。
- 流程使用人员可在现有流程设计器中选择中文业务动作，通过样本驱动映射、结构化条件和业务化试运行反馈完成编排。
- 业务人员路径中不得暴露 URL、Path 表达式、Header、Token、JSON 或代码输入框。
- 保持既有接入类型、系统实例、凭证、API 模板、Pipeline 和已发布流程兼容。

### 非目标 / 不做范围

- 不新增顶层“业务动作配置/使用”页面。
- 不允许普通用户填写任意 URL、请求头或 Token 后调用外部系统。
- 不新增第二套 HTTP 执行器、API 模板库、凭证中心、Pipeline 引擎或数据映射存储模型。
- 不再新增系统专属动作；历史动作仅做只读查询、运行和审计兼容，必须通过“复制为类型级草稿”显式迁移，禁止自动提升或静默替换既有 Pipeline。
- 不保留 `CONTROLLED_API` 的系统专属动作例外，也不允许在 `INSTANCE_RESOURCE` 下新增任意 HTTP 动作。
- 不通过前端表单支持私有签名、复杂 OAuth 刷新、mTLS、SDK、SOAP、WebSocket/长连接等协议；此类能力先开发后端 Adapter。
- 本期不支持任何写操作；写操作需另立需求并满足目录级开关、审批、幂等、无副作用试运行、审计、回滚和权限要求。

## 2. 用户场景

### 平台管理员：维护接入类型和预置业务动作

- **入口**：`数据连接 → 接入类型管理`。
- **操作**：新建/编辑接入类型；配置允许域名、认证策略、凭证字段和系统字段；用可视化表单定义中文业务动作、请求参数、返回字段、分页、脱敏与错误规则；选择已验证系统实例测试、保存样本、审批发布。
- **系统反馈**：显示接入类型的草稿/已发布/已弃用状态，以及动作的草稿/测试通过/待审批/已发布/已停用状态；校验失败时定位至字段和页签。
- **成功结果**：已发布类型可在新增系统时选择；已发布动作可被该类型任意合规系统实例启用。
- **失败/空态/无权限**：无有效测试系统时提示创建目录测试实例或选择已验证实例；无权限隐藏入口并返回 `403`；Secret、Token、完整 Authorization Header 永不回显。

### 系统管理员：接入系统并启用已发布动作

- **入口**：`数据连接 → 接入系统 → 添加系统`，以及 `系统详情 → 业务能力`。
- **操作**：选择已发布接入类型，填写实例差异字段，绑定凭证并验证；在业务能力中启用、停用和测试已发布动作。
- **系统反馈**：Host、认证和安全限制显示为“继承接入类型”，不可编辑；测试只要求填写业务参数。
- **成功结果**：已启用且凭证可用的动作可供流程编排选择。
- **失败/空态/无权限**：`401` 显示“授权已过期，请重新授权后再试”；`404` 显示“业务动作不存在或已停用，请联系平台管理员检查接入类型配置”；动作为空时显示“当前接入类型尚未发布可用业务动作”。

### 流程使用人员：选择动作并完成零代码编排

- **入口**：`数据连接 → 流程编排`。
- **操作**：选择有权限且已启用的中文动作；通过真实脱敏样本映射字段；使用三段式条件；试运行查看右侧结果抽屉。
- **系统反馈**：不展示 URL、Header、Path、JSON、表达式或代码；仅显示业务字段、样本值、动作名称和中文状态。
- **成功结果**：流程保存后按已发布动作版本运行。
- **失败/空态/无权限**：无样本时引导平台管理员完成动作测试并保存样本；参数错误高亮业务字段；无编辑权限时返回 `403`。

## 3. 功能范围

| 功能项 | 是否本期实现 | 说明 |
|---|---|---|
| 接入类型目录与发布 | 是 | 复用现有目录模型，补齐可视化字段定义、校验和发布约束。 |
| 预置只读业务动作定义 | 是 | 本期所有新动作仅在接入类型管理中创建、测试、审批和发布；仅支持 `GET` 和查询型 `POST`。 |
| 系统实例接入 | 是 | 复用添加系统向导，动态渲染实例字段和凭证字段。 |
| 动作启用与测试 | 是 | 系统实例仅启用、停用、测试已发布动作。 |
| 系统专属动作新增 | 否 | 取消目标态入口；历史数据仅兼容读取和运行。 |
| 可视化参数 Schema | 是 | 前端以表格/表单编辑，后端存储为受控 Schema。 |
| 测试样本与中文错误规则 | 是 | 保存脱敏样本，支持错误码/字段错误转换。 |
| 样本驱动字段映射 | 是 | 支持样本预览、点击填充、智能匹配、保存回显。 |

| 试运行结果抽屉 | 是 | 节点状态、耗时、脱敏预览、错误高亮与建议。 |
| 写操作（创建/更新/停用） | 否 | 另立需求；必须先完成目录级开关、审批、幂等键、无副作用试运行、审计、回滚和权限验收。 |
| 新协议/复杂认证 Adapter | 否 | 另立需求，由后端开发后再注册到接入类型。 |

## 4. 技术设计

### 4.1 数据库 / 数据模型

| 模型 | 本次字段与约束 | 兼容策略 |
|---|---|---|
| `UcpConnectorPackage` | `auth_policy`、`system_schema`、`host_allowlist`、`feature_flags`、`status`、`version` | 继续作为接入类型唯一归属。 |
| `UcpOperationDefinition` | `package_id` 必填；新建动作的 `system_id` 必须为空；`id` 为不可变动作版本 ID，补 `supersedes_operation_id`、`template_version_id`、`schema_hash`；规范 `input_schema`、`output_schema`、`pagination_rule`、`error_rules`、`masking_rules`、`scope`、`risk_level`、`status` | 历史 `system_id` 非空动作标记为 `LEGACY_SYSTEM_OPERATION`，只读兼容。 |
| `UcpApiTemplate` / `UcpApiTemplateVersion` | 动作定义保存业务 Schema 与规则；API 模板保存受控请求执行配置；发布动作必须指向不可变模板版本快照。 | 不重建执行器；同一已发布动作版本不得原地修改模板快照。 |
| `UcpSystemCapability` | `(system_id, operation_id)` 唯一；规范 `enabled`、`credential_id`、`test_status`、`last_test_at` | 仅表示系统实例启用某个已发布动作版本；发布新版本不得自动替换既有启用关系。 |
| `UcpOperationSample`（新增） | `id`、`operation_id`、`system_id`、`schema_hash`、`sample_version`、`is_current`、`request_sample_masked`、`response_sample_masked`、`field_catalog`、`source_run_id`、`expires_at`、`created_by`、`created_at` | 每个动作版本和系统实例最多一个当前有效样本；替换必须在一个事务内撤销旧样本的 `is_current`。 |

可视化字段 Schema 示例。后端可以 JSON 存储和版本化，但前端业务路径不得展示 JSON 编辑器：

```json
{
  "key": "mobile",
  "label": "手机号",
  "type": "string",
  "location": "body",
  "required": true,
  "format": "mobile",
  "enum_source": null,
  "description": "员工手机号",
  "sensitive": true
}
```

- `type` 仅允许：`string`、`number`、`integer`、`boolean`、`date`、`datetime`、`enum`、`array`、`object`。
- `location` 仅允许：`path`、`query`、`body`；认证和技术 Header 只能由认证策略、Adapter 或受控模板静态配置生成，不得成为表单字段。
- `enum_source` 支持 `static`、`operation_sample`、`upstream_context`。
- 新 migration 新增 `ucp_operation_sample` 表、当前样本唯一约束和样本版本索引；为旧动作补 `risk_level=READ_ONLY`、`error_rules=[]`、`masking_rules=[]`。
- 新建动作强制 `package_id` 非空；后端拒绝新建 `system_id` 非空动作。既有 `scope=SYSTEM` 动作统一标记为 `LEGACY_SYSTEM_OPERATION`，不自动删除、迁移、提升或替换既有 Pipeline。
- `downgrade` 删除新增样本表、索引和字段；不得删除既有动作、模板、系统能力和流程定义。

### 4.1.1 动作状态、版本与首次测试闭环

#### 动作状态机

| 当前状态 | 允许操作 | 目标状态 | 不变量 |
|---|---|---|---|
| `DRAFT` / `FAILED` | 编辑、测试、删除草稿 | `TESTED` / `FAILED` | 仅草稿或测试失败版本可编辑；编辑后必须重新测试。 |
| `TESTED` | 提交审批、再次测试 | `PENDING_APPROVAL` / `TESTED` / `FAILED` | 必须关联成功的目录测试或合规系统测试记录。 |
| `PENDING_APPROVAL` | 审批发布、驳回 | `PUBLISHED` / `DRAFT` | 审批人与提交人必须满足职责分离；发布前再次校验包策略和模板快照。 |
| `PUBLISHED` | 复制为新版本、停用 | `DISABLED` 或新的 `DRAFT` 版本 | 已发布版本不可原地编辑；Pipeline 与系统能力均按不可变 `operation_id` 引用。 |
| `DISABLED` | 查询、审计、复制为新版本 | 新的 `DRAFT` 版本 | 不可被新系统启用或新 Pipeline 选择；既有已发布 Pipeline 是否继续执行由显式退役策略控制，不得静默改变。 |

- 新版本必须创建新的 `UcpOperationDefinition.id`，通过 `supersedes_operation_id` 建立谱系；不得覆写已发布版本。
- Pipeline 节点保存 `system_id + operation_id + schema_hash + template_version_id`。更新动作时，流程维护者必须显式选择新版本、重新校验映射/条件并通过试运行；旧版本引用保持可执行，直至显式退役。
- 动作发布、停用、退役、版本升级和历史动作复制均写入审计；默认只读动作不支持运行时副作用。

#### 目录测试实例（解决首次接入闭环）

平台管理员可在接入类型为 `DRAFT` 时创建**目录测试实例**并绑定测试凭证。目录测试实例仅用于动作定义、连接验证和样本生成，具有以下强约束：

1. 仅 `ucp.connector_catalog` 有权限的管理员可创建、查看和使用；普通系统管理员和流程使用者不可见。
2. 它不出现在“添加系统”选择、系统能力启用列表或 Pipeline 动作选择器中，不能被 Pipeline 引用或作为生产运行目标。
3. 流程固定为：`接入类型草稿 → 目录测试实例/测试凭证 → 动作草稿 → 受控测试与脱敏样本 → 动作审批发布 → 接入类型发布 → 新建或显式提升为正式系统实例`。
4. 标准 SaaS 和受控 API 接入类型发布前至少存在一项已发布只读动作；`INSTANCE_RESOURCE` 不参与该流程。
5. 测试实例使用生产凭证时必须有显式风险确认和审计；不得保存凭证明文、原始请求或原始响应。

### 4.1.2 样本、映射、条件与试运行契约

#### 样本与字段目录

- 样本保存前必须由后端依据 `masking_rules`、字段敏感标记和凭证规则脱敏；采用默认拒绝策略，未被明确允许的原始响应字段不得持久化或返回。
- `field_catalog` 中每个字段至少包含 `field_id`、`label`、`type`、`sensitive`、`parent_field_id`、`ordinal`；`field_id` 为稳定内部标识，中文标签仅用于展示。
- `schema_hash` 由发布动作版本的输入/输出 Schema 生成。动作 Schema、脱敏规则或字段目录不兼容变化后，当前样本立即失效；必须重新测试才可用于新映射。
- 样本读取同时校验系统范围、Pipeline 编辑权限和字段敏感权限；无字段权限时只返回允许字段，不能以空值或错误信息泄露字段存在性。

#### 映射 DTO（X0258）

新映射统一保存为以下受控结构，不保存 JSONPath、模板表达式或任意代码：

```json
{
  "version": 1,
  "source_operation_id": 1201,
  "source_schema_hash": "sha256:...",
  "target_operation_id": 1301,
  "target_schema_hash": "sha256:...",
  "rules": [
    {
      "target_field_id": "employee_name",
      "source_kind": "upstream_field",
      "source_field_id": "candidate_name"
    }
  ]
}
```

- 本期只支持标量字段一对一映射；数组、对象、拆分、聚合和转换必须由已发布 Adapter 或后续专门能力提供。
- 前端显示业务标签，后端按稳定 `field_id` 保存和校验；字段改名只更新显示，字段删除或类型不兼容必须阻止保存并要求重新配置。
- 智能匹配仅使用同名/别名、类型和格式兼容的确定性规则生成建议与置信度；不向外部模型发送样本，建议未经用户确认不得保存或覆盖人工映射。
- 旧映射继续按旧引擎只读执行；编辑旧流程时必须完成可转换性校验，不能转换时引导人工重新配置，不得静默改写。

#### 条件 AST（X0259）

条件只接受版本化结构化规则：`{ version, mode, rules }`。`mode` 仅允许 `ALL` 或 `ANY`；每条规则包含 `left_field_id`、`operator` 和 `right`（固定值或上游字段引用）。

- 支持运算符：`EQ`、`NE`、`CONTAINS`、`GT`、`GTE`、`LT`、`LTE`、`IS_EMPTY`、`NOT_EMPTY`。
- 日期必须是 ISO-8601，数值不得与字符串隐式互转；数组仅支持 `CONTAINS`，对象不能直接比较。
- 缺失字段、无权限字段、类型不匹配、未知运算符或非法 AST 一律校验失败；运行时按 fail closed 处理，且将可定位的中文错误写入节点结果。
- 本期不支持任意表达式、函数调用、跨节点路径字符串和无限嵌套条件组。旧 `ctx.*` 条件可继续在已发布旧流程中运行；一旦编辑，必须迁移为 AST 或明确保持旧流程只读。

#### 无副作用试运行（X0260）

- `/pipeline-templates/{code}/dry-run` 必须复用正式 Pipeline 引擎的校验、映射、条件和节点编排，传入固定 `dry_run=true` 运行上下文；不得复制第二套执行器。
- 仅已发布的只读动作可调用外部系统；写资源、通知、审批、外部账号变更和其他副作用节点不得执行，统一返回 `SKIPPED_SIDE_EFFECT` 节点状态。
- 节点结果统一为 `{ node_id, status, duration_ms, output_summary?, field_errors?, error_code?, message?, suggested_action? }`；仅管理员可通过独立审计查询关联 `trace_id`。
- 试运行不保存完整输入/输出载荷，只保存脱敏摘要、状态、审计关联和必要的错误码；结果访问遵循 Pipeline、系统和字段权限。

### 4.2 后端接口

本节 URL 均为外部完整路径，统一使用 `/api/v1/ucp/*`。前端 `api` 客户端的 `baseURL=/api/v1`，因此 `ucp.ts` 内仅传递相对 `/ucp/*` 路径。优先扩展既有接口，不另建平行资源。

| URL | Method | Request Schema | Response Schema | 权限 | 状态码与错误处理 |
|---|---|---|---|---|---|
| `/connector-packages/{code}` | `PATCH` | 基础信息、认证策略、系统表单 Schema、开关、变更说明 | 接入类型详情与版本 | `ucp.connector_catalog:U` | `400` Schema 不合法；`403`；`409` 版本冲突 |
| `/connector-packages/{code}/operations` | `GET` | `status`、`keyword`、`limit`、`offset` | 类型级动作列表及总数 | `ucp.connector_catalog:R` | `403` |
| `/connector-packages/{code}/operations` | `POST` | `operation_code`、名称、只读方法、相对路径、字段 Schema、分页、错误/脱敏规则 | `DRAFT` 动作版本 | `ucp.connector_catalog:C` | `422` 路径/字段/策略不合法；`409` 编码或版本冲突 |
| `/connector-packages/{code}/operations/{id}` | `PATCH` | 同创建，附 `change_note` | 更新后的草稿版本 | `ucp.connector_catalog:U` | `409` 非草稿/测试失败版本不可原地覆盖 |
| `/connector-packages/{code}/operations/{id}/test` | `POST` | `system_id`、可选 `credential_id`、`parameters`、`save_sample` | 状态、耗时、脱敏预览、字段目录、错误对象 | `ucp.connector_catalog:U` | `401/403` 凭证或权限；`422` 参数；`424` 第三方失败 |
| `/connector-packages/{code}/operations/{id}/samples/current` | `GET` | `system_id` | 当前脱敏样本、字段目录、`schema_hash` | `ucp.systems:R` 或 `ucp.pipelines:U` | `404` 无有效样本；`403` 无系统/字段范围权限 |
| `/connector-packages/{code}/operations/{id}/submit` | `POST` | `change_note` | 待审批动作版本 | `ucp.connector_catalog:U` | `409` 未测试成功、样本过期或策略告警 |
| `/connector-packages/{code}/operations/{id}/publish` | `POST` | `approval_note` | 已发布动作版本与模板快照 | `ucp.connector_catalog:A` | `409` 审批或版本前置不满足 |
| `/systems/{system_id}/capabilities` | `GET` | 状态、关键词 | 可启用/已启用类型级动作 | `ucp.systems:R` | 历史专属动作标记只读兼容 |
| `/systems/{system_id}/capabilities/{operation_id}` | `PUT` | `enabled`、`credential_id` | 系统能力详情 | `ucp.systems:U` | `409` 动作未发布、类型不匹配或凭证不可用 |
| `/systems/{system_id}/capabilities/{operation_id}/test` | `POST` | 业务参数 | 脱敏结果、耗时、中文错误 | `ucp.systems:U` | 不返回裸第三方错误 |
| `/pipeline-templates/{code}/dry-run` | `POST` | `context` | 节点状态、耗时、输出摘要、错误命中信息 | `ucp.pipelines:U` | 固定为无副作用试运行；节点失败返回业务错误对象 |

旧的 `/systems/{system_id}/custom-operations` 写接口（`POST`、`PATCH`、OpenAPI 导入、`submit`、`publish`、`disable`）不再用于新建或变更，统一返回 `409 OPERATION_SCOPE_RETIRED`：`业务动作必须在“接入类型管理”中统一创建并发布。` 历史查询、运行、审计和只读投影接口保留兼容。现有客户端必须先迁移到上述类型级嵌套路由；不新增根级 `/operations/{id}/*` 平行路由。

所有失败响应统一为 `{ code, message, field_errors?, suggested_action?, trace_id? }`：`trace_id` 仅有审计查看权限的管理员可见；第三方原始状态、请求头、Token、原始响应和内部堆栈不得进入该对象。

### 4.3 业务逻辑

| 配置内容 | 唯一归属 | 示例 |
|---|---|---|
| 接口定义 | 接入类型 | 动作名称、相对路径、方法、入参、出参、分页、错误规则、脱敏规则 |
| 系统实例差异 | 接入系统 | 凭证、环境、企业 ID、应用 ID、固定 Report ID、资源标识 |
| 单次业务数据 | 流程或测试表单 | 姓名、手机号、审批人、订单状态、通知内容 |

1. 平台管理员仅在 `STANDARD_SAAS` 或 `CONTROLLED_API` 接入类型管理中创建动作草稿；`INSTANCE_RESOURCE` 只能在既有系统下新增资源。后端校验包状态、允许域名、路径、方法、字段、读写风险和认证策略。
2. 后端生成或更新既有 API 模板，并记录接入类型策略快照。
3. 管理员使用该类型下已验证系统实例与有效凭证测试；成功响应经脱敏后生成字段目录，可保存为映射样本。
4. 只有“测试通过 + 风险策略满足 + 审批通过”的动作可发布；发布事务同步锁定模板版本、刷新能力发现缓存并写审计。
5. 添加系统按接入类型动态渲染实例和凭证字段；系统管理员只建立动作启用关系，不可修改动作定义。
6. 只有“动作已发布 + 系统能力已启用 + 凭证可用”的动作可被流程选择。
7. 映射保存为扁平结构，前端仅显示“候选人.姓名”等业务标签；智能匹配只给建议和置信度，未经确认不得保存。
8. 条件使用结构化“字段 + 运算符 + 固定值/上游字段”规则，后端负责编译安全执行，不接受任意表达式字符串。

### 4.5 权限、安全与外部系统

| 权限点 | 角色 | 能力 |
|---|---|---|
| `ucp.connector_catalog:R/C/U/A` | 平台管理员 | 管理、测试、发布、弃用接入类型与类型级动作。 |
| `ucp.systems:R/C/U` | 系统管理员 | 创建系统实例、管理凭证、启用/停用/测试已发布动作。 |
| `ucp.pipelines:U` | 流程使用人员 | 选择已启用动作、配置映射/条件、试运行。 |

- 查询、测试和草稿编辑角色可由同一人员兼任；生产动作发布必须由与提交人不同的审批身份完成，不允许自审批。
- Secret、Token、密码、Authorization Header、完整敏感响应不得进入前端状态、浏览器日志、样本、审计正文或测试结果。
- 实际 URL 由后端根据接入类型允许域名和相对路径拼装，并执行协议限制、DNS/IP 校验和 SSRF 防护。
- 本期写操作一律禁用；后续写操作需求必须满足类型级开关、风险等级、审批、幂等键、无副作用试运行、审计和回滚共同要求后才可发布。
- 样本访问遵循系统、数据范围和字段敏感权限；无权限仅返回摘要或 `403`。

## 7. 验收标准

### 用户验收

- 平台管理员无需编辑 JSON 即可完成接入类型和类型级动作的定义、测试、审批和发布。
- 系统管理员可在既有接入系统中绑定凭证、启用和测试已发布动作，但无法创建新动作。
- 流程使用人员可基于脱敏样本完成映射和条件配置，并得到业务化试运行反馈。

### 开发验收

- 新动作唯一归属 `UcpConnectorPackage`；新建系统专属动作被后端拒绝。
- HTTP 执行器、API 模板、凭证、安全策略、审计和 Pipeline 均复用，无平行实现。
- 历史系统专属动作继续可运行，但新入口禁止创建、编辑和复制。
- 目录测试实例不能被 Pipeline 或正式系统能力引用；已发布 Pipeline 固定引用不可变动作/模板版本，升级必须显式完成。
- 本期仅允许只读动作；所有写方法、Header 表单字段和原始表达式均被后端拒绝。

### 测试验收

- 原子任务覆盖正常、异常、权限、空数据、迁移、旧数据兼容、构建和回归。
- 401、404、422、超时和第三方异常均转为中文业务错误；业务人员不看到裸技术错误。
- 样本、日志、试运行结果不含凭证明文或未脱敏敏感数据。
- 首次接入闭环、审批职责分离、样本失效、旧映射/旧条件兼容和无副作用试运行均有自动化测试。

### UI/交互验收

- 接入类型、系统接入、流程映射和试运行均覆盖加载、空态、错误、禁用、无权限和成功状态。
- 业务人员路径不出现 URL、Path、Header、Token、JSON 或代码输入框。
- 动态表单按字段类型渲染；映射支持样本预览与保存回显；条件使用三段式控件；试运行使用结果抽屉。

### 上线验收

- 灰度一个标准 SaaS 接入类型及至少两个系统实例，验证同一类型动作可被多个实例启用。
- 灰度一个目录测试实例到正式系统实例的提升或重建流程，验证测试实例不能被 Pipeline 选择。
- 历史系统专属动作和既有流程继续运行。
- 监控动作测试成功率、授权失效率、试运行失败率、错误规则未命中率、历史动作占比和敏感数据审计告警。

## 8. 风险与兼容性

| 风险 | 等级 | 影响 | 应对方案 |
|---|---|---|---|
| 历史系统专属动作仍被依赖 | 高 | 移除入口后可能误伤生产流程 | 禁止新建和变更；保留只读运行兼容；仅允许显式复制为类型级草稿，禁止自动提升或静默替换 Pipeline。 |
| 将实例差异错误建模为动作差异 | 高 | 类型级动作膨胀、难以复用 | 明确接口定义/实例差异/运行数据三层归属；评审时强制检查。 |
| 样本包含敏感数据 | 高 | 个人信息或凭证泄露 | 后端强制脱敏、权限裁剪、审计与样本截断。 |
| 前端表单不能覆盖复杂协议 | 中 | 用户误以为平台可配置 | 标注“需 Adapter”；禁止创建不受支持类型。 |
| 旧 Schema 与新可视化 Schema 不兼容 | 中 | 旧动作或流程不可用 | 兼容转换、只读保留、升级前完整回归。 |
| 智能匹配误绑定字段 | 中 | 数据错配 | 仅建议不自动保存；用户确认；显示置信度。 |
| 错误规则不完整 | 中 | 用户仍看到难理解错误 | 通用兜底文案、Trace 辅助、持续补充错误规则。 |
| 任务范围较大 | 中 | 开发周期与回归风险上升 | 按 X0253 → X0260 顺序交付，先完成类型级动作定义与系统启用闭环。 |
