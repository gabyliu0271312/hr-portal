# 接入类型目录与系统扩展能力运行手册

## 上线顺序
1. 备份数据库，并确认当前版本为 `0130` 或更早。
2. 部署后端、执行 `alembic upgrade head`，确认版本为 `0131`。
3. 部署前端；新路由为“接入类型管理”。
4. 由平台管理员创建草稿接入类型，完成校验后发布。
5. 业务管理员从“接入系统”选择已发布类型，配置系统与凭证。
6. 对受控 API 系统，在“扩展能力”中创建只读操作，测试、提交审批、发布。

## 回滚
- 先停用所有已发布的系统扩展业务能力。
- 执行 `alembic downgrade 0130`。
- 迁移会阻止仍存在已发布 SYSTEM scope 操作时的回滚，避免运行期能力丢失。

## 安全核验
- 受控 API 目录必须配置维护人、域名白名单与认证策略。
- 扩展业务能力只接受安全相对路径，以及 GET 或查询型 POST。
- 运行时从已绑定系统凭证读取密钥；页面与模板不返回明文密钥。
- Pipeline 仅展示已启用、已验证、已发布且审批完成的能力。
