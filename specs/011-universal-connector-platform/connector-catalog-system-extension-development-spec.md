# 接入类型目录与系统扩展业务能力开发规格

> 版本：v1.1  
> 日期：2026-07-25  
> 状态：待评审、待开发

## 1. 背景与目标

### 背景

当前 `数据连接 → 接入系统 → 添加系统` 已提供标准系统下拉框。前端通过 `GET /ucp/standard-packages` 获取已发布连接器能力包，选择后预填系统编码、名称、类型和预置操作。该能力证明标准系统目录已有后端数据来源，但存在以下缺口：

- 平台管理员没有可见入口维护接入类型目录和连接器能力包。
- 标准 SaaS、实例资源、受控自定义 API 没有在添加系统入口按同一模型清晰分流。
- 已接入飞书等系统后，管理员无法在系统上下文内扩展业务能力；隐藏的 API 模板库未自动继承系统的凭证、允许域名、认证策略和归属。
- API 模板、操作定义、系统能力卡和系统实例之间没有明确归属与发布契约，容易形成平行配置。

用户需求：

1. 平台管理员可在前端配置添加系统时可选的接入类型目录，包括标准 SaaS、实例资源、受控自定义 API。
2. 接入系统后，符合条件的系统可由集成管理员配置或扩展业务能力。
3. 已接入飞书等系统时，新增接口复用 Host、凭证、认证与安全策略；管理员主要补充业务名称、方法、路径、输入输出 Schema、Scope 与测试参数。
4. 上述能力抽为统一组件和统一对象模型，不得为飞书、滴滴、北森分别建设独立页面或二套表单。

### 目标

- 建立平台级接入类型目录，发布后作为添加系统向导唯一数据来源。
- 将系统实例、连接器能力包、操作定义、API 执行模板、系统能力卡分层管理。
- 在系统详情业务能力区域提供管理员扩展入口，复用现有 API 模板的编辑、OpenAPI 导入、测试和发布能力。
- 支持受控流程：选择接入类型 → 配置系统实例 → 绑定凭证 → 验证连接 → 启用或扩展能力 → 流程编排引用。
- 保持既有 `UcpSystem`、`UcpResource`、`DataSource`、Pipeline、凭证和已发布流程兼容，不自动迁移或中断生产连接。

### 非目标 / 不做范围

- 不允许普通用户填写任意 URL、请求头或 Token 后直接调用外部系统。
- 不建设无边界的通用 iPaaS。
- 不将表格、报表、数据库和文件等实例资源强行包装为业务能力。
- 不将复杂 OAuth 刷新、私有签名、SDK、SOAP、长连接等复杂协议完全降级为前端表单。
- 不自动将系统级自定义能力提升为全局标准能力。
- 不重写 API 模板库，不复制第二套 HTTP 执行器。

### 目录分类与配置路径校正（2026-07-25）

三类分类是平台管理员维护目录时的治理分类，不是业务管理员“添加系统”的三条并列路径：

```text
接入类型目录
├─ 标准 SaaS：添加系统时选择，创建父系统实例
├─ 受控自定义 API：添加系统时选择，创建独立 API 系统；也可在已有系统内扩展能力
└─ 实例资源：必须先选择已接入父系统，再在“系统详情 → 资源管理”中新增
```

- 飞书报表、飞书多维表、员工表等均为实例资源；它们必须依附飞书系统实例并继承该系统的凭证与安全策略。
- `添加系统` 不展示或接受 `INSTANCE_RESOURCE`；后端也必须拒绝将资源型能力包创建为 `UcpSystem`。
- `接入类型管理` 继续维护三类目录，但必须明确标示每类的配置位置，不能把“实例资源”描述为独立系统。

## 2. 用户场景

### 平台管理员维护接入类型

- 入口：`数据连接 → 接入类型管理`。
- 操作：新建或编辑接入类型，配置类别、名称、图标、认证策略、系统配置 Schema、允许域名、能力与资源开关、负责人和版本；保存草稿、校验、发布或弃用。
- 系统反馈：草稿不进入添加系统选择器；发布成功后目录可被向导查询；弃用类型仍可查看既有系统但不能新增实例。
- 成功结果：业务管理员选择已发布类型并获得匹配的配置向导。
- 失败、空态、无权限：无权限不显示入口且接口返回 403；无发布类型显示空态；无效 Schema、重复编码、策略缺失时阻止保存并定位字段。

### 业务管理员新增系统实例

- 入口：`数据连接 → 接入系统 → 添加系统`。
- 操作：选择接入类型卡片，再选择已发布标准 SaaS 包或受控 API 模板，填写系统实例信息与凭证，执行连接验证。
- 系统反馈：标准 SaaS 显示启用业务能力；实例资源显示添加资源；受控自定义 API 显示待审批的初始操作或进入能力扩展。
- 成功结果：创建系统实例并绑定凭证；标准能力按选择启用；系统详情显示状态、能力或资源。
- 失败、空态、无权限：连接失败区分凭证无效、Scope 缺失、域名不允许、需要测试参数、第三方服务异常；Secret 不回显。

### 集成管理员扩展已接入系统能力

- 入口：`数据连接 → 接入系统 → 系统详情 → 业务能力 → 新增业务能力`。
- 操作：系统自动带入归属、允许域名、默认凭证和认证策略；管理员填写业务名称、对象、方法、路径、输入输出 Schema、分页与错误规则，或导入 OpenAPI；使用当前系统凭证测试，提交发布审批。
- 系统反馈：草稿、测试通过、待审批、已发布、已停用状态清晰可见；未发布能力不可被流程选择。
- 成功结果：发布后的系统扩展能力出现在当前系统业务能力列表与 Pipeline 能力选择器中。
- 失败、空态、无权限：不支持扩展的类型不显示入口；路径不符合允许域名或认证策略不匹配时拒绝保存；无测试凭证时提示先绑定并验证。

### 流程设计者引用能力

- 入口：`数据连接 → 流程编排 → 节点配置`。
- 操作：选择已接入系统后选择已发布、已启用、已验证的标准能力或系统扩展能力。
- 系统反馈：展示业务名称、版本、风险、输入字段和最近验证状态。
- 成功结果：流程保存能力版本，运行时通过既有执行器调用。
- 失败、空态、无权限：草稿、停用、未验证、无 Scope 的能力不可选；旧流程继续引用旧版本直到明确升级。

## 3. 功能范围

| 功能项 | 是否本期实现 | 说明 |
|---|---|---|
| 接入类型目录管理 | 是 | 平台管理员维护并发布标准 SaaS、实例资源、受控自定义 API。 |
| 添加系统动态分流 | 是 | 添加系统页只消费已发布目录，按类型展示向导。 |
| 标准 SaaS 系统实例创建 | 是 | 复用已发布连接器包、凭证 Schema 与预置操作。 |
| 实例资源依附系统创建 | 是 | 在已接入系统的资源管理中新增，继承父系统凭证与安全策略。 |
| 系统级自定义业务能力 | 是 | 在允许扩展的已接入系统内创建草稿、测试、审批、发布能力。 |
| API 模板库复用 | 是 | 作为操作定义编辑、OpenAPI 导入、测试执行底座。 |
| 标准能力包全局提升 | 否 | 后续独立治理能力。 |
| 写操作、复杂认证、SDK 运行时 | 否 | 保持既有 Phase 3/4 边界。 |
| 自动迁移既有系统或资源 | 否 | 仅兼容投影，不做破坏性迁移。 |

## 4. 技术设计

### 4.1 数据库 / 数据模型

#### 对象关系

```text
UcpConnectorPackage 接入类型或连接器能力包
  ├─ UcpOperationDefinition 标准操作定义，scope 为 PACKAGE
  ├─ CredentialPolicy 凭证策略与字段 Schema
  └─ SystemOnboardingSchema 系统实例配置 Schema

UcpSystem 系统实例
  ├─ package_id 指向已发布接入类型
  ├─ UcpCredential 凭证
  ├─ UcpSystemCapability 已启用能力卡
  └─ UcpOperationDefinition 系统级扩展操作，scope 为 SYSTEM
       └─ UcpApiTemplate 技术执行模板
```

| 表或模型 | 本期字段与约束 | 兼容策略 |
|---|---|---|
| `UcpConnectorPackage` | 规范 `category`、编码、名称、图标、认证策略、系统 Schema、允许域名、特性开关、状态、版本、负责人、发布时间和弃用时间。类别仅允许 `STANDARD_SAAS`、`INSTANCE_RESOURCE`、`CONTROLLED_API`。 | 既有标准包映射为 `STANDARD_SAAS`；缺失字段提供安全默认值。 |
| `UcpSystem` | 新增可空 `package_id`、`catalog_version`、`connection_mode`；保留 `system_type` 兼容字段。 | 旧系统保留 `package_id = null`，页面以旧配置只读投影展示，不影响运行。 |
| `UcpOperationDefinition` | 新增 `scope`、可空 `system_id`、`executor_template_id`、`source_type`、`approval_status`、输入输出 Schema、所需 Scope、风险、版本。`PACKAGE` 必须绑定包；`SYSTEM` 必须绑定包和系统。 | 既有操作默认 `PACKAGE`，能力关联不变。 |
| `UcpApiTemplate` | 新增可空 `package_id`、`owning_system_id`、`operation_definition_id`、策略快照。 | 旧模板不自动挂接系统，继续在模板库访问。 |
| `UcpSystemCapability` | 保持系统与操作定义启用关系；补齐启用时间、启用人、连接状态、最近验证和凭证引用。 | 不改既有 `system_id + operation_id` 唯一约束。 |
| `UcpConnectorAuditLog` | 记录目录发布、弃用、系统扩展创建、测试、审批、发布、停用和删除尝试。 | 新表，不影响旧数据。 |

索引、migration 与回滚：

- `UcpConnectorPackage` 增加 `(category, status)` 与 `package_code` 唯一索引。
- 系统扩展操作增加 `(system_id, status)`、`(package_id, scope, status)` 索引；同系统内操作编码唯一。
- API 模板增加 `owning_system_id`、`operation_definition_id` 索引。
- migration 仅新增列、表和安全默认值；回填既有标准包和操作定义，不修改旧系统执行配置。
- downgrade 必须阻止静默删除已发布系统扩展能力；要求先完成明确迁移或停用确认。

所有接口使用 `/ucp` 前缀，遵循既有分页和错误格式；写接口记录审计日志。

### 4.2 后端接口

所有接口使用 `/ucp` 前缀，遵循既有分页和错误格式；写接口记录审计日志。

#### 4.2.1 接入类型目录接口

| URL | Method | Request Schema | Response Schema | 权限 | 状态码与错误 |
|---|---|---|---|---|---|
| `/connector-packages` | GET | `category`、`status`、`keyword`、分页可选 | `items`、`total`、目录元数据 | `ucp.connector_catalog:R` | 200；非法筛选 422 |
| `/connector-packages` | POST | 编码、名称、类别、认证策略、系统 Schema、特性开关、负责人必填 | 草稿包详情 | `ucp.connector_catalog:C` | 201；重复编码 409；非法 Schema 422 |
| `/connector-packages/{package_code}` | GET | 无 | 包、版本、操作摘要 | `ucp.connector_catalog:R` | 200；不存在 404 |
| `/connector-packages/{package_code}` | PATCH | 草稿字段与变更说明 | 更新后草稿 | `ucp.connector_catalog:U` | 200；已发布字段受限 409 |
| `/connector-packages/{package_code}/validate` | POST | 可选测试样例 | Schema、域名、策略、操作校验结果 | `ucp.connector_catalog:U` | 200；不合规 422 |
| `/connector-packages/{package_code}/publish` | POST | 版本、变更说明 | 已发布包 | `ucp.connector_catalog:A` | 200；未通过校验 409 |
| `/connector-packages/{package_code}/deprecate` | POST | 原因、生效时间 | 弃用状态 | `ucp.connector_catalog:A` | 200；影响阻断 409 |
| `/standard-packages` | GET | 无 | 仅已发布且可新建实例的包与操作摘要 | `ucp.systems:R` | 200；保持现有接口兼容 |

`auth_policy` 至少包含认证方式、凭证字段 Schema、Secret 标识、Scope 校验和 Token 刷新插件标识。  
`feature_flags` 至少包含 `supports_capabilities`、`supports_resources`、`supports_custom_operations`、`supports_openapi_import`、`allow_write_operations`。

#### 4.2.2 系统级扩展业务能力接口

| URL | Method | Request Schema | Response Schema | 权限 | 状态码与错误 |
|---|---|---|---|---|---|
| `/systems/{system_id}/custom-operations` | GET | 状态、分页可选 | 系统级操作、模板、测试、发布摘要 | `ucp.systems:R` | 200；系统不存在 404 |
| `/systems/{system_id}/custom-operations` | POST | 编码、名称、对象、方法、相对路径、输入输出 Schema、Scope、风险、凭证 | 草稿操作与草稿模板 | `ucp.system_capabilities:C` | 201；不支持扩展 409；路径不合规 422 |
| `/systems/{system_id}/custom-operations/openapi/preview` | POST | OpenAPI 文档、可选操作列表 | 可导入与拒绝操作 | `ucp.system_capabilities:C` | 200；文档不合法 422 |
| `/systems/{system_id}/custom-operations/openapi/import` | POST | 文档、操作列表 | 批量草稿操作 | `ucp.system_capabilities:C` | 201；写操作或未知认证 422 |
| `/systems/{system_id}/custom-operations/{operation_id}` | PATCH | 草稿可编辑字段、变更说明 | 更新后草稿 | `ucp.system_capabilities:U` | 200；非草稿 409 |
| `/systems/{system_id}/custom-operations/{operation_id}/test` | POST | 凭证、输入、是否保存样例 | 脱敏请求摘要、响应样例、Scope 和策略检查 | `ucp.system_capabilities:U` | 200；凭证无效 422；Scope 缺失 403 |
| `/systems/{system_id}/custom-operations/{operation_id}/submit` | POST | 变更说明 | 待审批操作 | `ucp.system_capabilities:U` | 200；未测试 409 |
| `/systems/{system_id}/custom-operations/{operation_id}/publish` | POST | 审批意见 | 已发布操作和已启用能力卡 | `ucp.system_capabilities:A` | 200；审批不通过 409 |
| `/systems/{system_id}/custom-operations/{operation_id}/disable` | POST | 原因 | 停用结果和影响摘要 | `ucp.system_capabilities:U` | 200；已发布流程影响提示 |

Pipeline 能力发现接口必须返回 `scope`、`source_type`、`system_id`、`version`、`approval_status`、`last_verified_at`；流程只接受 `PUBLISHED + enabled + credential_verified` 能力，并保存操作和版本。

### 4.3 业务逻辑

#### 单一事实来源与复用边界

- `UcpConnectorPackage` 是添加系统类型目录唯一事实来源；前端不得维护飞书、滴滴、北森硬编码下拉项。
- 既有 `app.connectors.catalog`、AdapterDefinition、API 模板库必须通过兼容投影或引用接入能力包，不新增平行目录。
- API 模板是技术执行定义；操作定义是业务能力定义；系统能力卡是系统实例启用状态。三者不得互相替代。
- 数据仓库入仓来源复用目录图标、说明、认证策略、链接解析和 Schema，但保持入仓来源、数据资产与 UCP 系统实例独立。

#### 添加系统分流

```text
选择已发布接入类型
  ├─ STANDARD_SAAS
  │   └─ 系统信息 → 凭证 → 连接验证 → 启用标准能力 → 完成
  ├─ INSTANCE_RESOURCE
  │   └─ 系统信息 → 凭证 → 连接验证 → 添加具体资源 → 完成
  └─ CONTROLLED_API
      └─ 系统信息 → 凭证 → 连接验证 → 创建或导入受控操作 → 提交审批
```

- 标准 SaaS 系统编码、名称、认证策略由包预填，仅编辑包声明为可编辑的实例字段。
- 实例资源配置由目录 Schema 动态渲染；资源必须绑定具体实例标识，例如表格链接、Report ID、数据库实例或文件位置。
- 受控自定义 API 默认没有可运行操作，必须先创建系统级操作并发布。
- 已弃用包不得新建系统；已有系统可继续查看、运行既有发布流程和管理凭证，但显示弃用提示。

#### 系统级扩展能力

- 仅当 `supports_custom_operations = true` 时展示扩展入口。
- 创建时后端从系统包读取允许域名、认证策略、读写限制和默认风险；客户端不得覆盖 Host 或认证类型。
- `path` 只能为相对路径，禁止协议、域名、IP、用户名密码片段和路径跳转；最终 URL 由受控 Host 拼装并执行既有 SSRF 校验。
- 手工创建与 OpenAPI 导入都创建 `DRAFT` 操作和 API 模板；测试成功后才能提交审批。
- 发布事务同时完成操作发布、模板版本锁定、启用能力卡、刷新发现缓存、记录审计。
- 停用不删除历史；新流程不可选择，旧流程按版本继续运行或要求管理员确认影响。

#### 禁止重复建设

- 不复制 API 模板库的 OpenAPI 解析、HTTP 校验、测试执行、样例脱敏、审批发布服务。
- 不在 `SystemsTabView` 中硬编码任一系统的凭证字段、URL、操作清单或业务字段。
- 不新增第二套流程能力选择器；既有 Pipeline 节点通过能力发现接口消费新字段。

### 4.4 前端与 UI/交互

#### 页面与导航

| 页面路径 | 名称 | 可见角色 | 说明 |
|---|---|---|---|
| `/ucp/connector-catalog` | 接入类型管理 | 平台管理员 | 管理目录、版本、策略和操作定义。 |
| `/ucp/systems` | 接入系统 | 业务管理员、集成管理员 | 添加系统消费已发布目录；系统详情管理能力或资源。 |
| `/ucp/api-templates` | API 模板库 | 平台管理员、集成管理员 | 保留高级入口；从系统详情进入时自动带入系统上下文。 |
| `/ucp/pipelines/designer` | 流程设计器 | 流程设计者 | 只显示可运行能力。 |

主导航仅对有目录权限的用户显示 `接入类型`；API 模板库可保持普通菜单隐藏，作为高级入口和系统能力编辑器的复用页面。

#### 接入类型管理 UI 示意


#### 新增业务能力抽屉

```text
┌ 新增业务能力：飞书招聘 / 生产环境 ─────────────────────────────────────┐
│ 步骤：基础信息 → 接口定义 → 输入输出 → 测试 → 提交发布                 │
│ 基础信息：业务名称、业务对象、风险等级、负责人                         │
│ 接口定义：Host 继承只读；认证继承只读；方法；相对路径；所需 Scope       │
│ 输入输出：入参 Schema、响应 Schema、分页、错误处理、脱敏字段           │
│ 测试：选择已验证凭证；填写样例参数；查看脱敏请求和响应                  │
│                                                    [保存草稿] [提交审批] │
└──────────────────────────────────────────────────────────────────────┘
```

- 支持手工配置和导入 OpenAPI 两种模式。导入先预览安全只读操作，再选择操作创建草稿。
- Host、认证、允许域名展示为继承信息；改变策略必须回到接入类型管理修改并发布新版本。
- 测试前必须选有效凭证；测试期间禁用重复提交；请求和响应严格脱敏。
- 提交审批前必须有成功测试且无高风险策略告警；失败保留非敏感输入。

### 4.5 权限、安全与外部系统

| 权限点 | 角色 | 能力 |
|---|---|---|
| `ucp.connector_catalog:R/C/U/A` | 平台管理员 | 管理、发布、弃用接入类型目录。 |
| `ucp.systems:C/U/R` | 业务管理员 | 创建和管理系统实例及凭证。 |
| `ucp.system_capabilities:C/U/R` | 集成管理员 | 创建、编辑、测试系统扩展能力。 |
| `ucp.system_capabilities:A` | 审批管理员 | 发布或拒绝系统扩展能力。 |
| `ucp.pipelines:U` | 流程设计者 | 选择已发布且可用能力。 |

- Secret、Token、完整 Authorization 头、完整敏感响应不得写入前端状态、审计正文、测试结果或日志。
- Host 由包允许域名决定，后端实施 DNS 与 IP 校验、协议限制和 SSRF 防护；前端校验不能替代后端。
- 默认仅允许只读 GET 与查询型 POST。写操作必须同时满足目录开关、审批、幂等、试运行和运行审计，超出本期范围。
- Scope、凭证连通、测试、发布状态必须独立；不得将接口不支持或缺少测试参数误标为无权限。
- 目录编辑、能力发布、停用、模板导入、测试执行均记录操作者、时间、对象版本、结果摘要和 Trace 引用。

## 7. 验收标准

### 用户验收

- 平台管理员可维护和发布接入类型，业务管理员在添加系统中只看到已发布类型。
- 业务管理员能理解标准 SaaS、实例资源、受控自定义 API 的区别：实例资源必须先依附已接入系统。
- 已接入飞书系统的集成管理员可在业务能力页创建受控扩展能力，无需重新输入 Host、凭证或认证配置。
- 流程设计者能看到可用能力的业务名称、来源、版本、风险和验证状态。

### 开发验收

- 目录、包、系统、操作、模板、能力卡各有单一职责与明确外键关系。
- 现有 `/standard-packages`、系统、凭证、资源、模板和 Pipeline 接口保持兼容或提供明确版本迁移。
- 新增能力复用现有 API 模板、HTTP 执行器和安全策略，不出现二套执行逻辑。

### 测试验收

- 第 6 节全部场景通过，前端、后端、构建和容器验收有可复现记录。
- 标准 SaaS、实例资源、企业内部只读 API 三类真实链路均可走通，异常和权限路径有覆盖。

### UI / 交互验收

- 添加系统仅选择可创建系统的类别与包；实例资源只能在系统详情的资源管理中新增。
- 系统详情将预置能力和扩展能力明确区分；实例资源不被误导为业务能力。
- 加载、空态、无权限、校验失败、发布失败、弃用状态均有业务化中文反馈。

### 上线验收

- migration 可升级，回滚有保护；旧系统、旧资源、旧流程不中断。
- 敏感数据、Secret、Token、测试响应均遵循脱敏与审计要求。
- 发布后容器资产与构建一致，监控可定位目录、凭证、测试、发布和运行失败。

## 8. 风险与兼容性

| 风险 | 等级 | 影响 | 应对方案 |
|---|---|---|---|
| 目录配置膨胀为任意连接器开发器 | 高 | 安全与维护失控 | 限定声明式字段；复杂认证和 SDK 只能绑定已发布插件。 |
| 自定义 API 绕过安全策略 | 高 | SSRF、凭证泄露、越权调用 | Host 继承包策略，相对路径校验，后端 DNS/IP 与域名白名单校验，审计。 |
| 标准与系统扩展能力混淆 | 高 | 错误复用和跨企业污染 | `scope`、`source_type`、`system_id` 强约束，UI 来源标签，能力发现按系统过滤。 |
| API 模板和操作定义平行维护 | 高 | 配置漂移、发布不可追溯 | 模板是执行定义、操作是业务定义，使用外键绑定和发布事务。 |
| 新模型影响旧系统 | 高 | 生产中断 | 新字段可空、兼容投影、双路径回归、不自动迁移。 |
| Scope 与真实可调用混淆 | 高 | 配置后运行失败 | 连接、Scope、测试、发布状态独立展示和校验。 |
| OpenAPI 质量不足 | 中 | 导入草稿不可运行 | 预览拒绝不安全操作、人工选择、测试后发布。 |
| 写操作误执行 | 高 | 外部业务副作用 | 本期只读默认；写操作后置并独立审批、幂等和试运行。 |
