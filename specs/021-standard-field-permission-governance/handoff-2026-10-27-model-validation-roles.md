## 1. 今天已经确认的业务口径

### 1.1 标准字段只负责稳定定义和确认映射

标准字段的目标能力是：

- 稳定标准字段 ID、字段编码、名称、业务定义、数据类型、必要枚举值域；
- 敏感字段分类；
- 来源物理列/数据集输出与标准字段的确认映射；
- 来源身份、类型漂移、引用保护和当前敏感分类的检查。

标准字段**不再承担**：

- 语义版本创建、切换、弃用、归档；
- 字段定义审批、审批后启用；
- 用户访问授权、数据集 ACL 或报表 ACL；
- 来源转换批准或报表执行器切换。

版本/审批历史可以保留作只读审计证据，但不能继续作为正式消费链依赖。

### 1.2 权限配置的分工

不要在建模页面再造一套用户授权。权限职责如下：

| 能力 | 权威来源 |
| --- | --- |
| 用户能操作哪些功能 | 系统设置的角色与菜单操作权限 |
| 用户能否访问数据集 | 数据集 ACL |
| 用户能否查看报表 | 报表 ACL/报表可见性 |
| 用户能看到哪些人员/组织/成本中心 | 系统设置中的用户范围、组织/中心权限标签及现有范围裁决 |
| 字段是否可用于模型和查询 | 标准字段直接身份、确认映射、类型与敏感分类 |
| 当前模型允许哪些事实和汇总用途 | 模型的事实与权限用途声明 |
| 当前请求是否实际放行 | 服务端运行时按当前主体重新裁决 |

标准字段映射解决“这列是什么”；用户范围和 ACL 解决“谁能看什么”。两者不能互相替代。

## 2. 建模校验页各区块的正确职责

当前页面保留第五步，但名称和提示应以“建模校验”为准，不再把它解释成用户要单独批准的执行资格。

### 2.1 字段与结构

保留。检查：

- 输出字段是否绑定有效标准字段；
- 人员键是否绑定人员范围标准字段；
- 成本中心键是否绑定成本中心范围标准字段；
- 物理类型、输出类型和标准字段类型是否兼容；
- 标准字段是否停用、映射是否歧义、来源身份是否漂移；
- 敏感分类是否完整、输出是否继承来源字段保护；实际使用者的字段权限在查询、预览和导出时裁决。

提示必须说明缺项和修复入口，例如：

- `输出字段 employee_no 尚未绑定有效标准字段，请到来源映射确认`
- `成本中心字段 cc_code 尚未绑定成本中心授权锚点，无法启用中心汇总`
- `字段 amount 的物理类型与标准字段类型不一致`
- `同一标准字段绑定了多个输出，无法唯一解析`

### 2.2 来源转换证据

保留自动检查，但重新评估“转换批准”这个人工操作。

转换证据用于确认：

- 最近成功的来源→目标加工运行；
- 来源/目标结构和血缘是否仍一致；
- 转换规则是否变化；
- 来源/目标数据指纹和行数是否变化；
- 当前结果是否仍对应当前数据集结构。

当前代码还有 `conversion_approval` 记录和“批准转换”按钮。它不是用户授权，也不是标准字段审批。下一张优化卡的目标方向是：

> 保留转换证据校验和失败阻断；优先把页面收口为“来源转换证据”只读反馈，评估并退役独立“批准转换”写操作，除非业务明确要求某角色对转换结果承担人工签字责任。

在这张优化卡完成前，不要直接删除转换批准表、审计记录或服务端校验。

### 2.3 权限字段与关联路径校验（2026-10-28用户澄清）

建模负责关联权限管控字段，不评估当前建模者能看哪些业务数据。检查：

- 事实身份与事实键、人员键、成本中心键是否存在；
- 人员/成本中心键是否有唯一、有效、已确认的标准字段映射和对应权限锚点语义；
- 来源身份、映射类型和实际物理类型是否一致；
- 来源别名、关联键与关联路径是否完整、连通；
- 事实与权限用途声明是否有效且与当前模型结构一致。

人员/组织/中心范围由系统设置维护。实际预览、查询、运行、导出仍按当次主体执行ACL、范围、字段保护及权限树检查；不能通过建模校验授予数据权。校验元数据和发布操作仍受既有功能权限及数据集资源访问控制，但发布不依赖建模者的业务数据范围，也不编译建模者的限定汇总查询。

本澄清替代此前“保留当前主体运行检查作为建模校验”的表述；旧运行接口和真实消费权限保护保留，本卡只解除建模反馈及发布对它的依赖。

### 2.4 隔离证明

保留，定位为**变更影响分析**而不是授权配置。它展示：

- 目标表和来源表；
- 其他数据集复用目标/来源表的数量；
- 来源加工出的其他目标；
- 活跃外部推送出口；
- 仍启用的自动写入任务。

它回答“这次发布会不会影响其他消费者”，不回答“当前用户能不能看数据”。共享不应被界面简单等同为用户无权；实际发布门禁仍需按既有影响分析规则处理。

### 2.5 事实与权限用途声明（原“授权合同状态”）

当前“授权合同状态”名称不清晰，容易与用户授权、数据集 ACL、报表 ACL、标准字段确认和执行授权混淆。后续页面应改名为：

> **事实与权限用途声明**

副标题：

> 这里声明本模型使用的事实、字段和汇总用途，不直接给任何用户授予数据权限；用户范围由系统设置、数据集 ACL 和报表 ACL 决定。

它保留的业务信息包括：

- 事实角色和事实身份；
- 事实键、人员键、成本中心键；
- 是否允许中心汇总；
- 是否允许人数指标；
- 缺失范围的处理方式；
- 当前声明是否仍与模型结构一致。

它不应继续承担：

- 给用户授予访问权；
- 替代系统设置中的用户范围；
- 替代数据集 ACL 或报表 ACL；
- 让用户选择执行器；
- 作为标准字段语义版本审批的替代物。

建议状态文案改为：

- `未配置事实与权限用途声明`
- `草稿：尚未生效`
- `已生效：人员范围`
- `已生效：人员范围 + 中心汇总`
- `已失效：模型结构已变化`
- `阻断：标准字段映射不完整`
- `阻断：来源转换证据失效`
- `阻断：权限字段或关联路径不可解析`
