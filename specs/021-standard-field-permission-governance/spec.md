# 标准字段与报表授权治理及可配置 HR 主数据底座

## 1. 背景、优先级与范围

### 1.1 已确认的业务决策

1. **先让现有报表的字段口径和授权可靠，再建设可配置主数据平台。**交付包 A 不依赖通用实体、北森主数据接管或组织构树入口切换；交付包 B 在 A 验收后复用其字段、映射及权限底座。全部建设范围保留，不把后交付写成取消。
2. **人员范围授予人员明细与范围内汇总；成本中心范围只授予批准的汇总能力。**员工 A 不在 HRBP 的人员范围，但分摊到其获授权中心时，A 的该中心分摊必须参与汇总，不能因此返回 A 的逐人记录或员工档案。
3. **分析维度不等于授权条件。**成本中心、组织、期间、人员类型等获准维度可组合分组或业务筛选；增加组织分组不自动增加组织范围 AND，也不能随意增加授权外字段。
4. 对同一批准的人员关联事实，明细使用人员范围；汇总使用人员范围与该事实获准的成本中心汇总范围的**事实集合并集**。双路径命中的事实只算一次。此规则不等于所有表、所有权限标签无差别 OR。
5. 使用者不在报表、工具或每次调用中声明“人员还是成本中心”。授权能力在数据产品底座登记一次，服务端根据实际查询粒度自动裁决；客户端不能通过策略参数、aggregate 标志或隐藏姓名扩权。
6. 保持现有功能、资源 ACL、字段分类/隐藏/脱敏；人员行权限不自动授予薪酬、身份证等字段原值。成本中心汇总不是字段权限豁免。
7. 本期不加组内人数通用门槛。单人汇总仍按已批准汇总规则；这不是零再识别/差分推断风险的承诺，012 对 DWS 敏感小样本的既有要求仍有效。
8. 存量报表分版本迁移；外部 API、主动推送、实时视图/快照暂不迁移，不把内部完成称为全渠道完成。
9. **交付平台限定PC浏览器。**用户确认本系统面向PC，本期A/B均不要求手机适配或移动端验收；手机走查仅保留历史观察，不作为开发/上线阻塞。PC窗口尺寸变化、宽表滚动、键盘、权限与错误态仍须验证；不撤销012其他功能的移动端要求。
10. **数据集权限与报表权限保持两层独立。**数据集权限是报表创建、改绑、查看（非owner特例）、运行和导出的必要前置；报表仍按private/scoped/public及ReportAcl独立控制可见性。拥有数据集权限不自动获得所有报表权限；报表ACL只能收紧、不能扩大数据集授权。public表示报表所有者显式允许全部有权数据集用户访问，不是数据集授权自动公开报表。创建或切换报表数据集时，前端只显示当前用户可访问数据集，后端必须再次校验，不能靠直传dataset_id绕过。

### 1.1.1 经2026-10-23业务澄清后的A交付主线

A不是重建HR权限系统，也不以完整字段治理平台作为第一交付。近期业务顺序固定为：

1. **数据产品一次授权、报表独立授权。**数据集决定谁能使用这类数据及产品能力；报表继续使用private/scoped/public和ReportAcl独立控制可见性。数据集权限是必要条件，不自动授予所有报表权限；报表权限只能收紧、不能扩大数据集授权。
2. **人员主授权、成本中心辅助汇总资格。**人员范围决定员工明细及其范围内汇总；成本中心范围不是平级的人员授权，只决定哪些中心的事实可额外参与已批准汇总，永不授予员工档案、逐人记录或下钻。
3. **标准字段服务授权锚点和B。**A优先确认人员、组织、成本中心及必要事实键/业务输出，用于可靠授权；B复用这些标准属性建立Person/Employment主数据，不因字段同义认定记录同一。

现有`scope_strategy`仅作为legacy兼容，不再作为新对象的业务选择器；新授权由数据产品合同和实际查询形态自动裁决。完整A任务仍保留为阶段性质量/扩展范围，但不能重新阻塞上述顺序中的每日可验收MVP。

V10.0 提出同义字段多命名、多源冲突、期间/时点混用、历史取值、粒度和权限管理问题。021 先交付语义目录、映射治理及当前报表授权；多源权威值裁决、历史事件流和时间轴继续后置，不以“统一主数据”声称这些问题已解决。

- 已有 TableColumn/RegisteredTable、数据集及输出字段/ACL、报表/ACL、组织与成本中心树、范围标签、字段分类/脱敏、ODS→DWD 标准化、MappingWorkspace/adapter，以及通用列表和手工记录维护。不能把这些能力说成从零缺失。
- reports/sql_builder.py::run_dataset_query 在显式策略下跳过 can_resolve_scope_strategy=False 的别名；现有 test_report_scope_filter_skips_alias_that_cannot_resolve_explicit_strategy 还验证旧行为。修复须改变测试预期，测试通过不等于业务规则正确。
- scope_filter 当前从物理列 scope_role 和花名册穿透解析范围，多标签 OR；它不是新的“明细人员、汇总双路径”合同。报表/数据集/表的单值 scope_strategy 需兼容保留，不能无版本重释。
- 0043_drop_global_fields 删除旧全局字段及认领入口；迁移说明记载其未投入使用，生产状态仍待核实。新目录要证明真实消费而非恢复空字典；005 的旧全局继承描述不得当现状。
- DWD 标准化刷新删除重建 TableColumn/DatasetOutputField 并自动发布，表/数据集旧默认状态也可为 published。稳定引用、准入和批准输出须显式改造刷新，不能只加绑定列。
- ODS 同步会排除某些 UUID/辅助字段、规范化年月及处理本地维护列；落库表不是完整原始报文。技术噪音与未知业务列须分类，合法未知业务列保留来源标识和可追溯值。
- 现有员工字段契约、员工档案字段配置及工具消费仍依赖 emp_realtime_roster。标准目录负责含义，消费方配置只管展示/用途；A不强制迁移这些入口，但不得形成第二语义源或新查询旁路。

生产报表数量、分类赋值、授权样本及出口目标未盘点，以上不等同于生产复现。上轮评估五组既有单元测试为73 passed、1 warning，主要是模拟会话/纯函数基线，非 PostgreSQL、生产或021功能验收。

| 交付包 | 必须交付 | 独立完成条件 |

### 1.4 非目标与兼容边界

- 不建设完整HR系统：入转调离审批、合同审批、薪酬计算、员工自助、员工/组织本地权威写入切换不在本期。B的新配置实体基础记录在范围内，但首批员工/组织仅external_sync写入。
- 不做事件流SCD、组织生效时间、月度历史权限树、多源自动权威裁决。新授权按当前树/当前请求；历史业务金额/期间/组织属性不能自动改实时口径，旧月度字段用法保留。
- A保持org_unit→org_tree及成本中心路径，B才切换组织主数据投影；成本中心仍沿旧链路。不新建第二权限树，不以手工报表替代系统内置维度。
- 不把ODS/DWD改成可写主库；B单独建受控主数据。禁止master→DWD→master环；不复制standardization_rules正文、UCP凭证/Pipeline、角色/字段分类或平行report_configs。
- 未映射业务源列可留ODS；不要求改外部字段名，不物理重命名旧列/报表/API/PushTarget映射。旧资产不因published默认值整体下线。
- 外部暂缓不是安全背书。共享查询可能改变出口结果，迁移前按3.8隔离或阻断试点，不能只比列名。
- 不扩展AI/BI/UCP业务查询，不承诺固定工期、30字段数量或十年历史存储目标。

## 2. 用户场景与业务验收矩阵

### 2.1 固定的三条事实样例

以下是测试说明而非真实员工：F1=员工A/组织1/中心1/100；F2=员工B/组织2/中心1/200；F3=员工C/组织1/中心2/300。各有唯一事实身份，组织分组口径已批准，不含额外薪酬敏感分类。

| 用户授权/操作 | 期望结果 | 明确禁止 |
| --- | --- | --- |
| 只有组织1人员范围，查分摊明细 | F1、F3，不要求中心1/2授权 | 中心无授权挡住有权员工，或带出F2 |
| 只有中心1，查员工档案/逐人分摊 | 拒绝：无人员明细授权 | 返回A/B工号/姓名/逐行金额，或匿名逐行金额 |
| 只有中心1，按中心汇总 | 中心1=300，F1/F2均参与 | 先按人员过滤成0，或返回F1/F2明细 |
| 只有中心1，按中心×组织汇总 | 中心1×组织1=100，中心1×组织2=200 | 组织分组再AND组织范围，或员工下钻 |
| 只有中心1，业务筛选组织1后汇总 | 100；筛选限定内容，不需要组织1人员授权 | 把业务筛选当授权或绕过字段白名单 |
| 组织1+中心1，查明细 | 仍仅F1/F3，中心路径不参与明细 | 两条授权OR扩权到F2 |
| 组织1+中心1，汇总同一分摊事实 | 并集F1/F2/F3，总额600；中心1=300、中心2=300，F1只算一次 | 两份SUM相加得700；冒称全公司总额 |
| 无可用范围/资源ACL不通过 | 明确无权 | WHERE 1=1或伪装真实业务空表 |
| 中心汇总后下钻 | 重新执行人员明细裁决；仅中心授权拒绝 | 复用参与汇总人员集合返回明细 |
| 组织分组仅一人 | 仍汇总，保留无通用人数门槛及推断风险 | 输出未聚合事实或宣称完全匿名 |

混合授权下某中心可能只有有权人员贡献，另一中心含全中心贡献。UI显示“当前授权范围内汇总/人员范围与成本中心汇总范围合并”，不能伪称全量。不能因选择组织分组静默改成人员口径、选择中心分组改成中心口径。

## 3. 核心合同：语义、授权与查询

### 3.1 职责分离

| 层次 | 唯一职责 | 不负责 |
| --- | --- | --- |
| 标准字段/版本/绑定 | 含义、类型、识别风险、敏感属性、稳定身份、候选锚点 | 用户范围、运行粒度、报表聚合方式 |
| 数据产品授权合同 | 事实身份、人员关联、批准汇总路径、字段/指标/筛选/关联/维度白名单 | 每个调用方可选的单值策略 |
| 查询与角色/范围 | 当前授权、实际粒度、各事实范围、聚合与字段裁决 | 从列名猜关联，分组域自动变权限域 |
| 系统维度 | 当前树编码/父子/状态/标签节点，获准分组参考属性 | 因维度可见就放行事实/员工 |
| B可配置主数据 | 实体身份、关系、受控记录写入与当前态 | ODS留存、分析JOIN、复杂HR流程 |

permission_domain是字段语义，不直接授予或要求行范围。public不代表行公开；org不代表组织分组必须AND组织授权；salary/personal继续既有敏感分类。is_permission_anchor只标候选资格，实际路径由底座验证。

### 3.2 标准字段目录、生命周期与稳定身份

#### 3.2.1 MVP属性

| 属性 | 本期合同 |
| --- | --- |
| field_code/field_name/business_definition | 全局唯一编码、名称和无歧义定义；发布编码不可原地改，同名异义不强合 |
| data_type | 受控基本类型；绑定不兼容必须受控转换并验证，金额明确必要量纲 |
| grain_level | 分组/标识为coarse/fine/identifying，度量不适用；是识别风险提示，不是只看依赖就判明细的算法 |
| permission_domain/is_permission_anchor | 语义与候选锚点，不取代产品授权合同/字段分类 |
| owner/status/version/时间/操作人 | draft→active→deprecated→archived；审核、版本和审计可追溯 |
| value_domain | 记录编码/含义/范围或未维护；不承诺公共值列表执行器、自动别名转换或来源裁决 |

工号标准编码使用**employee_no**，不能将工号改叫employee_id。source_record_id、旧物理行id、employee_no与B内部master_record_id分开；旧API的employee_id原义保持。staff_id/empId是否工号须有证据，不能按名字认领。

首批包括工号/姓名、组织/中心编码与名称、用工类型/主体、分摊度量及真实敏感字段。姓名即使不唯一也为identifying；名称只展示，候选编码锚点与树匹配。不以30字段为门槛，但试点必要字段和全部新消费业务输出不能缺确认。

#### 3.2.2 绑定、刷新与消费方归属

绑定含资产/源字段稳定标识、物理列/输出逻辑身份、标准ID及语义版本、unmapped/suggested/confirmed/invalid、确认人/时间/证据；一列不可双重确认冲突语义，建议不参与授权。源字段失效/变类型/消失告警并阻断，不按中文名称猜补。

**X2127先改稳定引用，再让发布和查询消费。**普通刷新对未变列差量更新，不删除重建全部元数据；保留TableColumn/DatasetOutputField/绑定ID、分类、审核、标签、顺序和报表列实例。物理身份变化经迁移关联旧逻辑身份，不自动转移审核；移除字段影响分析/失效标记。刷新不自动批准新列或发布新schema/授权版本。

标准目录是语义唯一源；TableColumn管物理/显示，DatasetOutputField管批准输出，员工字段契约是兼容消费者，EmployeeProfileFieldSetting只保留展示/用途。A不改未授权的AI/工具功能，但登记语义同步与冲突边界；显示名/可查询开关/同名建议不得变成第二授权源。

拟发布派生业务输出须有批准标准身份/依赖/类型；临时报表列实例只是已批准语义的展示，不需每次重复创建相同定义。目录运营明确owner、审核者/替补、同义检索、批量审核、积压可见；草稿可留ODS，不能绕过受控发布。

#### 3.2.3 生命周期与版本安全

- warehouse.assets V/C/U/D及审核操作人/原因可追溯；是否要求创建审核分离由X2104冻结，不新造审批系统。
- 类型/粒度/域/锚点/值域影响变更新版本，列出资产/数据集/报表/规则/出口，差异核准；被引用禁止硬删。
- **语义冻结不冻结授权。**撤权、敏感性升级、路径失效、禁止用途下次请求立即生效；安全降级重新审核，回滚不能减去现行限制。

### 3.3 底座授权能力：配置一次，使用时自动继承

数据产品保存普通消费方不可任意改写的版本合同：

- 实际事实表/别名、稳定事实键、人员关联；P(u)是组织及人员条件裁决后的可见员工集合。
- 各事实是否启用成本中心**汇总**路径及实际编码锚点；C(u)是当前授权中心集合。人员产品不能因某列存在自动获得此能力。
- 每条路径的键/编码/基数/树验证、缺失与无归属行为、可用操作粒度；由管理员审批，不是每个报表选策略。
- 分组/过滤/排序/指标函数/关联/输出白名单，公共参考、人员桥接、独立事实分类；员工属性投影不授予员工详情。
- 合同/语义版本、准入状态、批准人/原因及现有ACL。新产品默认无特许成本汇总能力。

对批准的人员关联事实f：

```text
D(u,f) = f.employee_key ∈ P(u)
S(u,f) = D(u,f) OR (该事实已批准成本汇总能力 AND f.cost_center_code ∈ C(u))
明细只用D；汇总只用S；业务筛选再与获准范围AND。
```

- 人员范围内事实可跨所有中心；人员范围外的中心事实只能参与批准汇总，匿名不能启用S明细出口。
- 同一事实使用OR/受控EXISTS生成集合，避免两份SUM相加；同域标签仍保持单标签组织段AND人员段、多标签OR，不拆散重组条件。
- 多事实分别裁决，不把某事实路径用于另一敏感事实；未批准穿透不能借同员工JOIN放行。基数/数值拆分须防金额放大。
- 某路径未启用或用户无该域授权，不影响另一有效路径；**启用路径配置失效不等于无该域授权**，须阻断受影响合同，不静默忽略、少算或降级public。
- 无范围条件为false；无可用操作范围明确denied_scope；有权但业务筛选无命中才是空结果。

### 3.5 执行、JOIN与结果一致性

1. 校验功能、Report/DataSet ACL、批准状态/版本及当前用户；物理表绑定不是普通业务旁路。
2. 实际计划覆盖投影/筛选/分组/排序/指标/计算/JOIN/名单/透视归并/运行时覆盖。无关表可不参与，改变基数/筛选的JOIN不能因未选列而任意移除。
3. 判粒度、逐事实选择获准路径，验证稳定绑定/schema/树/敏感字段/准入；缺失拒绝。
4. 事实先D或S，后业务筛选/受控关联/聚合。中心汇总不得先D丢掉跨组织贡献。**跨组织原始明细不进入普通用户响应/预览/导出/调试/审计，内部只投影必要获准依赖。**复用SQL构建器/受控执行层，不让前端聚合全量明细。
5. 公共参考仅豁免自身行过滤，不豁免事实；员工桥接/组织参考为获准最小投影，不能整张员工表公共化。每个别名须明确授权或获准参考/穿透角色，否则拒绝。
6. LEFT JOIN对获准参考用受控投影/子查询，无匹配的授权事实保留到批准未知桶；不能全局WHERE给参考组织加人员限制而删事实。独立受控事实各自过滤，缺路径拒绝；INNER缺匹配排除须明确；RIGHT/FULL两侧先受控再关联，NULL/保留侧有样例。不允许自动笛卡尔积。
7. 多事实指标按事实键核对，一对多须获准去重/拆分；不得靠JOIN带入未授权事实或重复金额。
8. 字段权限在依赖解析及投影即校验，隐藏/脱敏字段不得用于反推；最终展示处理不替代前置检查，S也不能用无权薪酬指标。
9. SELECT/COUNT/分组总数/预览/CSV/XLSX同一用户、范围及聚合计划。汇总COUNT计获准分组，不泄露额外底层明细数；人数指标另定义。撤权下次生效。
10. 无权403，配置/关系失效或准入不足用稳定业务错误码及安全提示，参数400/422、资源404、并发409；真实有权空数据200。普通用户不见隐藏元数据，管理员有定位。

#### 4.1.1 已确认身份模型：自然人为主对象，雇佣关系为子对象

- HR主数据中的“员工”以自然人 `Person` 为唯一主对象；同一自然人允许存在多段 `Employment` 雇佣关系，形成 `Person 1:N Employment`，不能把自然人与某一段雇佣关系压成一条永久记录。

- `employee_no` 是 `Employment` 的业务属性，不是自然人的内部主键；工号变更或复用必须沿来源身份保留稳定ID并记录冲突/变更，不能按新工号新建自然人或按姓名自动合并。
- 外部来源通过 `source_system + source_record_id` 及经批准的稳定键映射到 `Person`/`Employment`；无法证明两条记录属于同一自然人或同一雇佣关系时，进入待核验/拒绝状态，不自动合并。
