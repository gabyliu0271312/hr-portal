## 1. 问题与已确认决定

### 1.1 为什么调整顺序

现有A侧已使用实时花名册、组织树和成本中心树，但其权限消费仍与具体来源结构关联。继续先完成所有报表权限迁移，再建立HR主数据身份与关系，会增加二次迁移风险。另一方面，B首轮维护也需要权限保护，不能要求先完成整个A才允许建设基础。

用户确认调整为：**保留A现有安全保护和必要修复 → 前置B最小公共基础、人员/雇佣、组织树、成本中心树 → 验证一条主数据到原报表的权限消费闭环 → 继续A整合及B后续能力。**

本决定替代此前“A独立整体验收后才启动B”的统一门槛；替代的是排期依赖，不取消A/B任何既有安全需求、生产批准或最终验收。

### 1.2 基础的含义

“基础可用”必须同时具备：稳定身份、明确来源和写者、受控关系、持续更新、查询维护入口、权限拒绝、变更追溯，以及供用户范围配置引用的稳定对象。只有空实体、维护页面、来源表复制或更换菜单名称，均不构成交付。

主数据说明“对象是谁、当前属于什么组织、中心怎样关联”；授权配置决定“谁能操作、谁能查看什么”；运行时执行这些授权。HR属性不能自动变成数据访问权。

### 1.3 本轮文档授权

本轮只整理规格及原文档衔接，不开发、不连接生产、不切换来源、不迁移数据、不提交或推送。本专项后续逐卡授权执行；一张卡通过不能自动启动整条路线。

## 2. 范围、角色与业务边界

### 2.1 本阶段范围

| 范围 | 必须交付 | 完成边界 |
| --- | --- | --- |
| 公共基础 | 实体定义、同一标准字段归属、必要记录约束、稳定身份、业务关系与维护权限 | 用一个受控非内置实体证明复用，不先做全类型/全关系平台 |
| 人员/雇佣 | Person与Employment分离，雇佣关联组织，既有来源受控接管、持续更新、授权查询 | 工号不是自然人永久身份；一人多雇佣不合并；不建设专业入转调离流程 |
| 组织树 | 稳定节点身份、编码、父子、状态、检索、后代、来源与更新 | 复用现有树能力；正式权限投影切换须单独对照批准 |
| 成本中心树 | 复用同一树能力，独立确认来源、编码、关系、写者及更新 | 不是仅用合成树证明复用；实际业务来源接管另卡验收；不随组织树自动切换 |
| 权限配置衔接 | 原用户管理/范围标签选择稳定人员、雇佣、组织或中心对象，保存后正确解析 | 不另建授权入口，不因创建主数据对象自动授予范围 |
| 返回A的首个消费者 | 一份原报表以相同配置和当前身份验证范围、字段、计数、分页及导出 | 先一个人员明细，再一个中心汇总实例；不捆完整六表或所有渠道 |

### 2.2 本阶段不做

- 本轮不实施完整历史平台、历史权限重算、双时态或通用SCD，不补造来源未留存历史。部门/职级/工作地等必要业务时间轴已追加为需求，按主规格§4.4.1生效日期+同日序号规则另行具名实施，不再将必要时间轴整体排除。
- 薪酬结果接收、员工分摊结果服务、内部薪酬核算；FR-B14–FR-B16及B21–B25仍有效，后续排期。
- 全部扩展实体、所有字段/关系类型、职位职级专用流程、完整主数据平台。
- 全量报表迁移、全渠道权限统一、平行执行器整体退役。
- 自动把现网组织/中心权限输入切到新来源，或把存量报表全部重新绑定。

必要时间轴尚未实施不等于允许改变既有期间数据含义。本阶段验证优先使用当前状态样例或隔离数据；涉及历史报表含义的真实消费者，保留原口径并另行核准。

### 2.3 角色与职责

| 角色/对象 | 职责 | 不能自动获得的能力 |
| --- | --- | --- |
| 主数据配置管理员 | 配置获准实体、字段、关系和来源，查看校验与影响 | 不因可配置而获得全部员工或薪酬数据 |
| 获准维护者 | 在明确local维护范围内新增、编辑、停用记录 | 不能覆盖external_sync托管字段或改变其他实体 |
| 同步服务写者 | 按已确认来源更新托管记录，记录运行结果 | 身份由服务端确定，不能由客户端自报或绕过校验 |
| 权限管理员 | 在原系统设置入口维护用户的授权范围 | 主数据可见、职位或主管关系本身不等于授权 |
| 报表使用者 | 按功能、资源、记录范围与字段权限消费 | 中心汇总资格不等于员工明细权 |

首批人员与组织沿用external_sync方向；成本中心来源和维护方式在B00.a冻结，不预设本地编辑。任何对象只能有明确的权威写者；如按字段划分写者，必须逐字段可检查，不能双向任意覆盖。

## 3. 用户场景与验收

以下细化原US-B01/B02/B03/B04/B05/B06/B07及US-A01/A02，不另造场景编号。

### 场景一：定义一类可维护对象（US-B01、US-B06）

- Given 配置管理员具有目标实体的维护资格，When 创建实体定义并选择其归属标准字段，Then 属性直接引用同一实体ID与标准字段ID。
- Given 定义已发布且维护者获准，When 创建、编辑或停用一条记录，Then 可在业务入口查到，记录ID保持不变。
- Given 定义未发布、字段无权、唯一值重复或提交版本过期，When 绕过页面直接提交，Then 明确拒绝且不部分写入。

### 场景二：维护组织和中心树（US-B07）

- Given 已确认一类树的维护方式，When 查看、检索和展开节点，Then 编码、父子、状态、层级与后代一致。
- Given 节点为local且维护者获准，When 修改父子或状态，Then 影响可见，身份不变；被引用停用须说明影响并受控处理。
- Given 托管节点、跨树父节点、循环、孤儿或重复编码，When 提交修改或接收批次，Then 拒绝目标操作，保留仍安全的现有状态，不清空权限树。

### 场景三：从既有来源接管人员/雇佣（US-B02、US-B03）

- Given 稳定来源键及同人依据已核准，When 接管或重试同一来源记录，Then 关联原有内部身份，不重复创建。
- Given 同一自然人存在两段获准雇佣，When 查询详情，Then 显示一个Person、两个独立Employment，并正确关联当前组织。
- Given 同名不同人、身份冲突或组织引用缺失，When 预检/接收，Then 显示可定位原因或进入受控待核验，不按姓名、相似工号或物理行号猜合并。

### 场景四：来源变化可靠反映到业务入口（US-B03）

- Given 当前对象已接管，When 来源更新并成功处理，Then 业务入口在该处理完成后显示新值，内部ID及有效引用保持。
- Given 接收失败或重复通知，When 重试，Then 结果可恢复且没有重复对象或半批公开。
- Given 来源缺字段、增量缺行或异常空批次，When 处理，Then 不据此清值、删对象或批量停用；完整快照消失须另有完整性依据。

### 场景五：原用户管理引用HR对象（US-A01、US-A02、US-B04）

- Given 权限管理员获准配置一个用户的范围，When 从原选择器选择组织、人员/雇佣或中心并保存，Then 保存的引用可重新打开、解析和追溯到同一稳定对象。
- Given 对象改名或源端编码合法变化，When 重新查看配置，Then 授权仍指向同一对象；若无法核准身份变化则阻断，不转授给另一个对象。
- Given 只创建了主数据或只配置账号的人员关联，When 用户请求数据，Then 不自动产生组织、中心或全员授权。

### 场景六：一份原报表证明基础可用（US-A01、US-A02、US-B05）

- Given 人员范围与两层资源权限有效，When 查询、分页和导出一份原明细报表，Then 只返回获准人员，表头、计算和输出口径保持。
- Given 仅中心范围，When 请求员工明细，Then 拒绝；独立中心汇总实例按既有D/S含义验收。
- Given 授权已撤销或对象引用失效，When 再次请求，Then 下次请求生效，不能沿用旧范围、缓存结果或旧批准放行。

## 5. 关键业务对象与规则

### 5.1 身份与关系

| 对象 | 稳定身份与当前关系 | 约束 |
| --- | --- | --- |
| 实体定义/标准字段 | 各有稳定ID；字段归属引用同一实体定义 | 无第二字段字典，存量未归属不按名称自动回填 |
| Person | 自然人稳定ID | 姓名、工号、账号均不作为自然人永久ID |
| Employment | 独立雇佣ID，关联一个Person及明确当前组织 | 同一人允许多雇佣；未知组织不能挂根兜底 |
| 组织节点 | 稳定节点ID及明确业务编码、父节点、状态 | RootOrg不计业务一级；编码变更须有身份核准依据 |
| 成本中心节点 | 独立稳定ID及其树、父节点、编码、状态 | 不与组织节点因同名合并；不假定人员组织唯一决定分摊中心 |
| 来源身份 | 来源系统+来源记录ID，或已核准等价稳定键 | 重试同源同ID；无法证明映射则待核验/拒绝 |
| 授权范围引用 | 原权限配置引用的稳定对象及必要投影 | 改名不改授权对象；身份歧义不能扩大可见范围 |
| 登录账号 | 既有账号ID；必要时明确关联人员身份 | 关联本身不授予数据权，不要求每个账号属于员工 |

工号、组织编码、中心编码可以作为既有消费合同中的业务键保留，通过受控映射衔接内部稳定ID；不要求一轮替换全部报表字段，也不允许仅字符串相等即认定同一身份。

### 5.2 当前态与同步

当前已实现/已验内容与新增时间轴需求分别登记；必要业务时间轴沿[主规格§4.4.1](spec.md#441-业务生效日期同日序号与期间结果2026-10-28确认)承接：同对象同状态链同生效日序号从1递增，最大有效序号代表当日最终状态，旧记录保留；按日先选最近生效日再取最大有效序号。系统记录ID不等于生效序号，业务生效日不等于录入日，操作审计不替代时间轴。工资等期间结果按真实粒度/批次/修正版本保存，不套同日取末条规则。新增需求不代表本轮已开发或授权历史平台。

同步复用已有来源落库及持久任务。每个来源分别核准全量/增量、显式空值、顺序依据及失败重放方式；安全策略可以是拒绝自动覆盖，不能猜时间戳顺序。没有完整快照证明，不启用“未返回即停用”。

来源失败时，只有证明旧状态仍安全才继续供消费；若失败涉及身份、停用或权限归属且不能保证安全，应阻断受影响用途，不能无限沿用旧状态授予访问。

### 5.3 树及正式输入

组织是通用树首个实例，成本中心是本阶段必须验收的非组织实例。两者的来源、维护方式、节点身份及权限输入独立核准；不得因组织通过就宣布中心通过。

开发隔离样例可验证复用，但不替代真实来源和正式投影验收。生产切换按一个树/一个消费用途逐次批准；没有安全停止和回退方案不切换。不因本阶段建设自动改现网树、标签、选择器引用或报表绑定。

## 6. MVP交付闭环与依赖

本节定义各MVP的业务合同；开发复选框、执行顺序、状态和证据只在[mvp-tasks.md §3.1任务清单](mvp-tasks.md#31-当前专项开发任务清单)维护。每项完成约定验收并补齐证据后，必须在同一次更新中勾选对应任务并同步状态；代码完成但必需验收未通过时不勾选。本规格不复制进度复选框，避免两处状态不一致。复用原卡的具名实例，不一次执行父模板全部范围。除准备卡和总核验外，每张卡同轮包含必要持久化、服务端校验、权限负例及PC用户入口；不拆成“只有建表/接口，UI以后再补”。

### 6.1 B00.a：冻结首实例与四类基础对象的来源/写者边界（准备卡）

- 角色/动作：配置管理员核查现有实体、花名册、组织树、中心树和来源证据；首版统一Person并建立Employment基础定义，工作地enum归Person。按主规格§4.4.2调查实际花名册字段→标准字段复用/新增→对象归属/时间模式/写者，再冻结首张实体与字段定义卡；不以代码子集冒充完整字段调查。
- 依赖：已有安全机制可用于开发隔离范围，不要求A整体验收；未证实可用的人员范围不得默认全量放行。
- 成功：明确每类对象的来源、稳定键、权威写者、当前关系、业务入口及现有能力复用点；列出账号与人员身份的必要关联，不强制建设新账号系统。
- 拒绝/停止：成本中心来源、人员同人依据等查不清时将对应接管实例标阻塞，不猜选；不阻塞已具备证据的无关实例。
- 产出：B00.a只读调查与准备合同已完成。实际52列元数据/来源键/标准映射/组织证据见[任务账§9.3](mvp-tasks.md#93-b00a实际调查结果2026-10-28本地只读数据库)，首版52列分流、工号/手机号/银行卡号标准string、时间分组、配置资源权与真实数据权分离及B01.a正负验收见[§9.4](mvp-tasks.md#94-b00a收口首版personemployment与字段合同)。真实来源身份不足按对应接管停止处理，不猜键、不连生产；准备完成不等于字段或记录已实现。

### 6.2 B01.a / B01.b / B02 / B03：一类实体形成可操作基础

- B01.a：工作地已确认为Person基本信息中的enum字段，不是独立实体；字段和值域唯一维护入口为数据仓库标准字段目录，Person定义页只读展示同一字段引用；Person/Employment从首版统筹定义，花名册实际初始标准字段和其他字段归属先由B00.a调查冻结，逐实体卡实施，不把完整人员接管或全部初始字段塞进本卡；在核准实体定义中引用同一标准字段，重开能读回归属与枚举值域；未知/无权实体、冲突归属及重复枚举编码拒绝。复用现有值域配置，不预填真实地点，不创建工作地实体或占位Person绕过身份核准；维护边界及必要时间轴衔接已在B00.a合同冻结，首卡不自动包办时间轴实现。
- B01.b：同一实体发布→新增一条获准local记录→列表/详情可查；未发布及无实体权直接请求拒绝。
- B02：同一记录编辑→停用，各自状态可核对、ID不变；无维护权、过期提交及受限引用拒绝。
- B03：仅补首实例需要的必填、类型或唯一约束，每次一种，带正常/非法/冲突及失败无半写证据。
- 停止：必要实体访问/记录范围无法安全控制时阻断该操作，不等A全功能完成，也不先开放数据。

### 6.3 B20.a / B06.org：组织树能力与已落库来源接管

- B20.a：在同一通用入口查看/检索/展开一个组织同结构实例；获准local样例可维护，托管样例只读；循环、孤儿、跨树父引用、重复编码及深度异常拒绝。
- B06.org：以核准稳定键接管一份已落库组织来源→业务入口查看父子、状态与来源结果→重跑保持节点身份；缺父或身份冲突拒绝且不影响现网权限输入。
- 依赖：必要实体/父引用能力及B00.a来源合同；B20.a通过后才做真实组织接管。
- 成功边界：来源接管与日常维护入口可用；正式权限树切换留B13.org/B14.org。

### 6.4 B20.b / B06.cc：成本中心复用与真实来源维护

- B20.b：配置一个成本中心树实例→同一入口检索、展开并按维护模式操作；不增加中心专属CRUD，组织同样的树负例必须生效。
- B06.cc：按FR-B17核准的来源/写者接管一份实际成本中心数据；若确认local权威，则在同一通用入口完成获准新增/编辑/停用与引用检查；不开放external_sync节点手工覆盖。
- 依赖：B20.a共享能力、中心来源/键/写者合同；不依赖组织生产切换。
- 成功：真实中心数据可维护/可更新，重跑同ID；代码重复、编码冲突或不明写者阻断。合成树复用通过不能替代B06.cc。

### 6.5 B04 / B07.people：人员与雇佣身份接管

- B04：用同一底座配置Person及Employment与1:N关系→查询一人两雇佣；获准工号修改不改变Person身份；伪造关系、无权选择及托管local写入拒绝。
- B07.people：按核准同人/同雇佣键接管一组已有人员数据→业务入口查询人员、雇佣与当前组织→重跑及并发保持身份。
- 依赖：必要实体约束/关系、组织接管与身份依据。成本中心不是雇佣默认组织，也不是人员接管的虚构必填外键。
- 停止：来源只能证明一条雇佣、不能证明自然人归并时，明确待核验，不批量猜并。

### 6.6 B08–B12：每类来源的一次可靠更新与恢复

- 对组织、中心、人员分别建立具名实例，每次只做一个来源的一种变化，记录为B08.org/cc/people等。
- B08：原来源更新→任务成功→主数据同ID显示当前值；重复通知不重复。
- B09：注入一次接收失败→从原任务入口重试→恢复同ID且无半批公开。
- B10：验证旧批不得覆盖新批；无可靠顺序依据时明确拒绝自动覆盖。
- B12：按实际必要分别验证缺字段与显式空值、工号/编码变化或源键冲突。
- B11：仅支持完整快照且确有停用推断需求的来源实施；否则明确不适用并持续禁止缺行停用。不能把未知完整性标为通过。

### 6.7 B05.scope：原权限配置选择并保存稳定HR对象

- 角色/动作：权限管理员在原用户管理/范围标签入口选择一个已接管的组织、人员/雇佣或中心对象→保存→重新打开。
- 依赖：目标对象身份/查询/维护模式验收通过；相应投影只用于隔离验证或已批准正式输入，不抢先切换生产。
- 成功：选择与回显指向同一对象；改名不换授权对象；账号身份关联不自动新增权限；保存、撤销和失效提示沿用原入口。
- 拒绝：无配置权、伪造目标、无权候选搜索/计数、失效对象及未知引用均受控；中心资格不能用于人员档案读取。
- 一次一个选择器类型，分B05.scope-org / scope-person / scope-cc验收；不把旧B05非内置实体关系验收一并勾完。

### 6.8 B13.org / B14.org 与 B13.cc / B14.cc：正式范围输入承接

- B13实例分别只读对照旧新code、存续ID、父子、path、后代、启停、标签及选择器引用，差异逐项可解释。
- B14实例分别在批准范围内切换一个正式输入；验证旧授权不扩权、目标引用保持；失败安全停止或回退且身份不丢。
- 组织使用原FR-B10，中心使用FR-B17；不修改FR-B10“组织切换不动中心”的边界。
- 开发演练可先行，生产输入只有B13及实际安全依赖通过、批准后才能切；组织和中心分别验收，不双写争抢。

### 6.9 B15.permission-d / B15.permission-s：返回A的首个权限消费闭环

- B15.permission-d：选择一个已核准原明细报表；主数据提供单向只读消费→原数据集关联权限字段→用户范围配置→运行/最终计数/分页/CSV/XLSX；同配置有权结果保持，撤权后下次拒绝。

## 7. 成功标准与非功能验收

| 标准 | 可复核指标 |
| --- | --- |
| 身份稳定 | 每类已接管来源至少首跑、相同批次重跑、一次当前值更新均保持原内部ID；同源并发不新增重复对象 |
| 人员关系正确 | 一个已核准自然人对应两条独立雇佣；同名不同人不合并；未知身份/组织不猜选 |

| 可靠维护 | 每类实际来源至少一次失败重试成功；失败无部分公开，重复不重复，缺行不自动停用；local写者的非法/并发/越权操作全部拒绝 |
| 权限衔接 | 组织、人员/雇佣、中心三个选择器分别保存/回显同一对象；名称变化不改授权对象；未知或停用引用明确受控 |

| 安全与隐私 | 选定验收矩阵无无权行、无权字段原值或越权候选泄漏；审计保留必要身份/动作，不记录敏感明文 |
| 可用性 | PC原业务入口可完成操作；无权、配置失效、来源失败、有权空结果可区分；验收记录角色、对象、环境和操作 |
| 性能 | 涉及的选择器及报表在同环境可比样本P95增幅目标≤20%；无有效基线只记录实测，不称性能通过 |
