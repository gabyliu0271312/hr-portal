# PM-T013 验收契约

## 结构

- 页面显示“通知设置”和“通知方式”。
- 卡片按标题、说明、飞书推送、邮件、辅助文案顺序展示。
- 复用 `PerformanceNotificationMethodsCard` 与 `PerformanceCheckbox`，不复制 checkbox SVG。

## 行为

### Given

页面有权限且 GET 返回默认配置。

### When

进入通知设置。

### Then

飞书推送显示已选中且 disabled；邮件显示未选中。

### Given

邮件当前关闭且用户有修改权限。

### When

勾选邮件。

### Then

发送 PATCH `{ "email_enabled": true }`，成功后保留选中状态并显示成功反馈。

### Given

PATCH 失败。

### When

用户切换邮件。

### Then

邮件回滚到变更前状态并显示错误反馈。

### Given

用户缺少 `performance.configuration.manage`。

### When

请求 GET/PATCH。

### Then

服务端返回 403，页面显示错误态，不伪造可编辑成功。

## 策略保存验收

- GET 成功后按返回的两组模式与三项开关显示；403/加载失败时不展示卡片。
- 每次实际切换只 PATCH 对应的一个字段，保存中阻止第二次请求，但下方另外两项不得改变原生 disabled、节点、样式或勾选状态；成功采用完整服务端响应，提示保存成功。
- PATCH 失败时恢复上次已保存值并提示；重新打开从数据库 GET 读取，而非使用前端默认值。
- 三个“编辑”按钮保持原生 disabled，摘要频率/时间/节假日规则本期不支持编辑。
- 已选中其他通知点击取消：先展示确认框，不立即 PATCH；“保留”/Esc 维持勾选且无请求；“确定”只 PATCH 对应字段 false。失败恢复勾选且保留弹窗允许重试，重复点击确认不得产生第二次请求。
- 单选保存中仍保持当前输入节点、焦点与正常文字颜色；阻止重复操作，结束后解除忙碌态。
- 下方每项从选中→未选中和反向切换时，未操作的两项 `input` 身份、checked、行 DOM/class 在请求前、保存中和完成后均不变；可见提示文案始终占相同高度。
- 某项保存为未勾选后，只有该项灰色通知摘要及编辑按钮从 DOM 中消失，复选框行仍在；点击“保留”、保存未完成或失败时不消失。再次勾选时仅恢复该项摘要与编辑按钮，保存失败则回滚隐藏。

### Given

### Then

### Then
