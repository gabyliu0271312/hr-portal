# PM-T009 UI 交互契约（草案）

视觉蓝图：[PM-T009-self-summary.md](../../ui-blueprints/PM-T009-self-summary.md)

## 1. 页面结构

```text
任务详情头部（64px）
├─ 返回
├─ 项目成员快照中的用户信息
└─ 禁用的翻译 / 全屏入口

页签栏（48px）
└─ 模板手动维护名称 / OKR（disabled）

自我总结表单
└─ 模板动态内容块
   └─ 填写项
      ├─ 复用富文本组件
      ├─ 评级轴 + 模板规则颜色
      └─ 标签多选 + 一个共用富文本补充输入框

底部固定操作栏
└─ 提交 / 取消
```

本期不实现 OKR、翻译、全屏填写和移动端。

## 2. 组件复用边界

- T009 只负责页面组装和模板适配；
- 现有富文本组件负责格式工具栏、编辑和 resize；
- 现有评级组件负责选项渲染和选中态；
- 现有复选框和富文本组件共同承载标签多选与共用补充输入框；
- 若现有组件缺少必要 props，应通过适配层扩展，不复制组件实现。

## 3. 交互规则

- 页面标题使用 API 返回的模板节点名称；表单按 API 的“内容块 → 填写项”两级 schema 动态渲染；
- 头部用户信息来自项目成员快照，不使用固定“当前用户”文案；
- 输入后实时自动保存；
- 保存失败保留输入并提示；
- 提交失败保留输入并展示原因；
- 校验失败滚动到第一个错误字段并聚焦；
- 必填评级由模板决定；
- 价值贡献必填时，至少选择一个标签且必须填写共用补充输入框；
- 模板内容块 `allow_multiple=true` 时，在该内容块底部显示统一的 `AddOutlined + 添加` 按钮；点击后复制整组填写项。
- 重复实例不显示“第 N 条”标题，也不绘制实例间分隔线；字段名称直接显示为“名称1、名称2……”；当实例数大于 1 时每条都显示公共删除图标，只剩最后一条时全部隐藏删除图标。
- 删除任意实例时，各字段答案按同一实例索引一起删除，且至少保留一条。
- `allow_multiple=false` 时不得显示添加、序号或删除入口，答案保持单值。
- 取消只关闭编辑态，不清除已保存内容；
- 截止后提交成功即切换只读。
- 工作总结提交后返回绩效评估页时，概览必须继续绑定刚提交的同一 `task_id`，侧栏显示“已完成”，白色内容区展示冻结表单结构对应的已提交答案；截止期内仍可编辑时提供“去修改”，不得继续显示“暂未填写”或“去完成”。

## 4. 视觉规则

- 评分评级内容块仅渲染最终选择的一个评估项；配置预览与填写页使用同一组规则等级和同一题目级展示方式。
- `PerformanceRatingControl` 是评级展示/输入唯一组件：评分评级弹窗、配置填写内容和绩效填写页共同复用；标签样式渲染连接标签，下拉样式渲染等级下拉框。
- 评级颜色使用模板评估规则颜色；
- 不根据等级文案自行推断颜色；
- 页面仅支持桌面端；
- 底部操作栏固定，滚动内容需预留底部空间。

## 5. 状态覆盖

必须设计并验证：loading、可编辑、保存中、保存失败、校验失败、提交中、提交失败、截止后可提交、提交后只读。

## 6. 重复填写组件边界

- `PerformanceAddAnotherButton`：统一承载 `AddOutlined + 添加` 的视觉和禁用态；模板预览与实际填写共同复用。
- `PerformanceRepeatableContent`：按 `section.allow_multiple` 管理实例容器、公共删除按钮、添加入口和插槽，不理解具体题型；不负责渲染序号或分隔线。
- `performanceRepeatableAnswers`：统一完成单值兼容、实例计数、字段数组读写、整组添加/删除和错误键生成。
- `PerformanceSelfSummaryForm`：只组合重复内容组件与富文本/评级/标签字段；后续其他绩效填写页复用前述两个组件和答案适配器，不复制索引规则。

## 7. 动态参考节点与未提交催办变体

- 填写页和成员完成侧边抽屉的附加页签只来自模板“内容设置 → 配置参考内容”中 `reference_kind=node` 的节点引用；`reference_kind=more`（OKR、更多参考、团队统计）本期排除。
- 参考页签是否显示只由模板配置决定。对应参考任务未完成时仍显示页签，不因为未提交隐藏。
- 参考任务已提交时，展示同一项目、同一成员快照、同一被评估人的冻结表单结构和真实答案，使用 `PerformanceTemplateRenderer mode=readonly`。
- 参考任务未提交时，沿用原有未完成状态图标，下方文案固定为“暂未提交”；不显示“去完成”，不填充其他任务答案。
- 当后端根据“其他权限设置 → 管理者权限 → 管理者可催办任务”和“可催办的环节类型”判定当前用户有权催办时，显示催办按钮；无权限时不显示。
- 催办按钮使用 `BellOutlined`，尺寸 80×32px，背景 `#C2D4FF`，文字/图标 `#1456F0`，圆角 6px，图标 14×14px；点击跳转催办占位页并携带项目、节点、任务和员工上下文。
- 本变体的真实催办提交、通知投递和完整像素 rendered contract 不在本期范围。

## 8. 上级评估完成成员侧边详情变体

- 入口：绩效评估 → 我团队的绩效 → 上级评估成员列表；成员任务 `status=completed` 时打开侧边详情，不改变当前成员列表页面。
- 待完成、已逾期未提交成员仍进入 `/performance/review/template-task`，使用原有编辑、自动保存和提交链路。
- 抽屉使用共享 `PerformanceDrawerShell`，默认宽度按采集状态约 720px，支持指针拖拽和键盘方向键调整；不得将 1084px 作为固定宽度。
- 抽屉头部展示项目成员快照中的头像、姓名、部门/职级/组织、直属上级和入职日期；翻译、复制链接和关闭入口沿用采集结构。翻译和更多参考业务本期不扩展。
- 抽屉页签由模板 `reference_kind=node` 配置动态生成，显示当前评估节点名称和参考节点名称；OKR、更多参考等 `reference_kind=more` 页签本期排除。
- 已提交内容使用现有 `PerformanceTemplateRenderer mode=readonly`，不得复制富文本、评级、标签题 renderer。
- 抽屉完成提示显示提交人、提交时间、截止时间和“编辑”入口；编辑必须重新打开同一个 `task_id` 的模板任务，不得切换到节点首个任务。
- 关闭抽屉不清除当前列表状态；重新点击其他已完成成员时替换为新的成员任务详情。
- 该变体已获用户定向门禁授权；缺少完整 rendered contract、resize/hover 状态证据时，结构和行为可以验收，像素状态保持 `blocked`。
