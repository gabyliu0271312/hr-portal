## 1. 需求背景与整体说明

### 1.1 背景

绩效系统进入多身份功能与数据权限验收阶段。HR Portal 目前仅向部分授权人员开放，用户管理维护的是 Portal 用户及其角色；绩效面向全体符合业务条件的员工，不能为测试或全员使用而要求每位员工新建 Portal 用户、领取密码、配置静态角色。

绩效中的被评估人、直属/间接上级、评估人等身份，主要由周期人员快照、汇报关系、项目和节点任务产生；HRBP 范围、项目管理员等依对应业务配置。登录者是谁与其在具体事项中能做什么必须分离。

仅用管理员预览全部人员，无法证明普通员工的数据权限正确；仅新建“测试上级”等空账号，也不能建立真实上下级关系。需要让少数被授权的 Portal 操作者选择绩效员工，在不创建目标员工 Portal 账号、不修改业务关系的条件下，按目标员工的实际权限验收。

### 1.2 目标闭环

```text
admin 在 Portal“权限管理 → 身份管理”按系统启用/停用其他用户的身份切换能力
  → 开启后由有角色维护权的人员显式授予“绩效用户切换”权限
  → 操作者在绩效右上角选择员工
  → 后端建立受控、可撤销的切换会话
  → 绩效按目标员工计算页面、数据与动作权限
  → 明示当前身份，随时恢复本人
  → admin 关闭开关，清空其他角色的切换授权并使非 admin 会话失效
  → 再开启仍需重新授权，旧授权和旧会话不自动恢复
```

内置 admin 始终可以切换，不受上述开关限制；但切换后的绩效业务权限仍按目标员工计算。

### 1.3 非目标

- 不为全员创建 Portal 用户、本地密码或一套新的绩效密码账号。
- 不开发、复用或改造用户另行维护的飞书 SSO 入口；本功能不代替正式 SSO 验收。
- 不主动同步飞书通讯录、不实现飞书 ID 预绑定；前期讨论的这些议题不是本功能需求。
- 不修改评分、分布、申诉、发布规则，不改变既有人员关系、任务归属、周期快照或历史证据。
- 不自动开放其他应用；只预留应用隔离边界，不建设通用插件平台。
- 不把“admin 永远可切换”解释为无需认证、可自动解禁或可绕过目标员工授权。

## 3. 角色、身份与功能需求

### 3.1 主体定义

- **真实操作者（operator）**：当前已认证 Portal 用户；用于检查切换资格、账号状态和审计。
- **目标员工（effective employee）**：所选员工编号；用于绩效身份、数据范围、任务和业务动作判定，不要求存在 Portal 用户。
- **内置 admin**：系统初始化的唯一管理主体，不等于显示名为 admin 的用户，也不等于任意超级管理员角色成员。固定身份锚定方式须 T01 核实并冻结。
- **普通授权操作者**：非内置 admin，拥有显式绩效切换授权，且公共开关开启的有效 Portal 用户。

### 3.2 功能需求

| 编号 | 需求 | 约束 |
|---|---|---|
| FR-01 | Portal 角色配置 → 绩效管理增加“绩效用户切换” | 与应用入口、后台管理权限独立；不是目标员工的业务角色 |
| FR-02 | 仅内置 admin 可进入“权限管理 → 身份管理”独立页面 | 表格固定系统名称、描述、状态、操作；本期只有绩效系统一行；按钮随状态为启用/停用。非 admin 超级管理员、直接路由/API 均拒绝，不增加可转授管理权 |
| FR-03 | 内置 admin 保留切换资格 | 开关开/关均可；仍校验原始登录、有效账号和会话安全 |
| FR-04 | 关闭时清空所有角色的切换授权 | 包含停用角色、当前无成员角色和超级管理员角色；保留普通业务权限、用户和审计 |
| FR-05 | 关闭使非 admin 已有切换会话失效，重开不恢复 | 不只隐藏菜单；旧页面保存、服务重启、升级、旧会话重放不能恢复授权 |
| FR-06 | 绩效右上角提供切换入口与恢复本人 | 复用现有人员选择方式，按姓名/员工编号查找，不限于 Portal 用户名单 |
| FR-07 | 目标员工无需 Portal 账号或密码 | 依绩效人员和周期/项目快照定位；没有业务记录时正常空态，不能伪造任务 |
| FR-08 | 切换后按目标员工执行真实业务授权 | 页面、列表、统计、详情、参考内容、导出及动作判定保持一致，不叠加操作者管理权限 |
| FR-09 | 保留 operator 与 effective employee 两种身份 | 原始 Portal 登录不覆盖；跨应用不串用切换会话；禁止前端任意 employee_no 冒充 |
| FR-10 | 切换与恢复清理旧数据和权限上下文 | 取消旧请求，迟到响应不得渲染；旧项目不可见则回工作台；不串标签页 |
| FR-11 | 审计可追溯 | 记录开关、授权变更、清空数量、创建/退出/撤销切换会话及切换内业务操作；不记密码或凭证 |
| FR-12 | 不改历史快照，不退回管理员预览 | 对现存无 portal_user_id 的目标员工也能识别；正常非切换请求保持既有行为 |
| FR-13 | 关闭与角色保存、会话创建及业务请求保持一致 | 关闭成功后新请求不能按旧授权继续；失败全回滚，不部分清除 |
| FR-14 | 保留应用级复用边界 | 当前 app_code 只允许 performance；其他应用未来单独授权和适配，不自动获得能力 |
| FR-15 | 原业务接收方始终禁投，默认仅记录 | admin 可开放受控测试投递；样例、汇总、异步和重试均不得回退原接收方，不影响正常通知 |
| FR-16 | 每次测试单独汇总，样式验证只发一条样例 | 受控投递时每批汇总 1 条、样式样例 1 条；默认模式只记录；与原通知人数无关 |

### 3.3 资格真值表

| 操作者 | 公共开关 | 显式切换授权 | 可切换 | 可管理开关 |
|---|---|---|---|---|
| 内置 admin，有效登录 | 关闭 / 开启 | 不需要 | 是 | 是 |
| 非 admin 超级管理员 | 关闭 | 有 / 无 | 否 | 否 |

## 4. MVP 交付模式与用例

### 4.1 当前 MVP：MVP-1 绩效身份切换与撤权完整闭环

必须同一轮交付：管理开关、角色授权、名单选择、无 Portal 账号员工切换、目标身份授权、恢复本人、全量撤权与旧会话失效、审计及真实页面验收。不能把“菜单能显示”“接口建好”独立宣布为业务 MVP 完成。

**2026-10-28 追加决定：**用户已选择开发与生产均支持真实业务操作，因此“先非生产只读”的起步建议不再作为本轮交付方案。MVP-1 必须包含 T09 的目标权限内业务写入；不得仅完成只读版。切换操作始终禁止向原业务接收方投递；默认仅记录，受控测试投递按第 10 章限量。生产功能支持不等于本轮获准部署生产。

### 4.2 写入闭环纳入 MVP-1（原条件增量调整）

Q01/Q02 的运行环境与可写方向已明确：开发与生产均支持操作。范围为目标员工本来允许的保存、提交、评价、校准、发布、复议等现有动作，不新增任何业务权力。逐项按节点时间、记录状态、对象授权验收，追加实际操作者信息；消息不因业务写入获准就自动获准发送，必须执行 Q07 已确认的通知隔离与测试策略。

T09 已纳入 MVP-1，同一闭环交付，不以只读版替代完整要求。其他应用接入不是本功能的交付任务。

## 5. 当前实现事实、复用点与影响分析

### 5.1 代码核查事实（不等于生产已验证）

以下代码路径均相对于仓库根目录。

- `hr-portal/backend/app/seed.py` 已注册 performance.app / performance.admin；`_ensure_super_role` 会给超级管理员补缺失菜单授权，不能照搬给身份切换。
- `hr-portal/backend/app/roles/router.py` 的角色保存会重建菜单授权，必须防止旧表单在关闭/重开后写回切换授权，其他菜单仍原样保存。
- `hr-portal/backend/app/performance/auth_context.py` 当前以 PORTAL_USER / SYSTEM_ACCOUNT 解析请求，周期内员工定位部分依赖快照 portal_user_id；需要新增受控 effective employee 分支，不可假装目标员工已有 Portal 用户。
- `hr-portal/backend/app/performance/projects_router.py` 部分查询使用成员 portal_user_id；必须逐条梳理为切换分支的可信员工条件，不能仅换右上角姓名。
- `projects_router.py` 当前项目管理员部分按显示姓名匹配；同名风险需 T01 列明。优先复用现有业务规则，不在本功能暗中改管理员名单格式；无法稳定识别时应阻塞相应用例并单卡修复，不能声称全量身份等价。
- `PerformanceLayout.vue` 已有右上角菜单；`PerformancePersonSelect.vue` 为可复用人员选择包装，数据必须仍取员工源而不是 users 表。
- 现有开发管理员预览可能扩大可见任务；切换请求必须禁用该特权路径，不删除原调试功能。
- 当前飞书回调仅绑定已有 Portal 用户，不提供本功能所需的全员独立员工访问上下文；本轮不修改该回调。

### 5.2 影响矩阵

| 层级 | 影响 | 允许范围 / 保护边界 |
|---|---|---|
| Portal 权限 | 是 | 新增 performance.identity_switch 使用权限，角色读写防恢复；不扩散普通业务权限 |
| Portal 用户 | 只读主体核验 | 原始账号状态与固定 admin；不批量建人、不改密码、既有角色不删除 |
| 绩效授权/API | 是 | 独立 employee 切换上下文、统一对象校验、读路径接入；不建第二套评分/授权引擎 |

## 6. 技术契约（已按第 12 章实际实现收敛）

### 6.1 复用与唯一事实来源

- 操作者认证：复用 Portal Bearer 登录；`/auth/me` 始终返回原操作者，不伪造成目标员工。
- 切换使用权：既有 RoleMenu，新增 `performance.identity_switch`，只用 V 表示可使用；C/U/D/E 不用于授予管理开关权；scope_dimension 固定 none。
- 开关管理：固定 admin 身份检查，不设可转授的菜单管理权限。建议固定主体锚定于受控安装记录，不用每次请求按名字匹配；具体锚点迁移必须核验现有 admin 唯一性。缺失/冲突则拒绝操作，不猜测账号。
- 人员与业务范围：员工实时花名册用于候选检索，周期/项目快照用于对应历史业务授权；候选选择可见不等于获得该员工全部历史数据。
- 控制状态和会话：数据库持久化，跨进程生效，不用 localStorage、进程内开关或只靠长效 JWT。

### 6.2 数据模型提案

| 对象 | 字段 / 约束 |
|---|---|
| app_identity_switch_settings | 单例 id=1；others_enabled=false；generation=0；revision=1；admin_operator_user_id 固定 FK（首次 seed 前可空）；test_delivery_enabled=false；test_receiver_user_id；updated_at；修改人记入审计；API 不可重绑 admin |
| app_identity_switch_sessions | UUID 字符串 id；operator_user_id FK；target_employee_no/display_name；secret_hash 唯一；generation；request_id（操作者内唯一）；created_at/expires_at/revoked_at；TTL 30 分钟。当前应用/模式固定为 performance/TARGET_POLICY，不为未来用途添加空列 |
| app_identity_switch_notification_runs | UUID id；session_id/operator_user_id/target_employee_no；request_id/source/environment；delivery_revision；items/original_receivers JSONB；sample_status/summary_status；delivery_error/delivery_requested_at/created_at；session+request 唯一 |
| RoleMenu | 复用新使用权限的映射，不新增平行人员授权表；关闭清除所有角色该权限的全部操作标志，不影响其他映射 |
| PerformanceAuditEvent | 复用审计；actor 为实际操作者，元数据含 effective_employee_no、app_code、switch_session_id；保留原业务操作者语义和前后状态，既有下游兼容；业务写入双身份 envelope 须 T01 冻结 |

目标员工不能以 FK 指向某一个可变周期快照：同一员工可以跨周期，不同周期各自验证业务记录。正式员工身份主键语义与员工编号复用风险由 T01 核实。会话密钥只存哈希，不写日志/URL；响应返回的 opaque 凭证只驻当前页内存，刷新后恢复本人，Portal token 不覆盖。

迁移初始 others_enabled=false、所有角色无显式授权；admin 仍有内置资格。仅新建迁移，revision/down_revision 开发时以实际唯一 Alembic head 为准，不预占编号、不编辑历史迁移。空库、已有库、持久库 upgrade/downgrade 只在隔离环境验证；生产不据此授权降级或删除审计。

### 6.3 API 提案

统一前缀 `/api/v1`；JSON 未知写入字段拒绝；身份从有效凭证解析，不接受客户端自行声明 operator 或 admin。以下路径均为拟新增，不宣称已存在。

| 方法 / 路径 | 输入 | 输出 / 权限 |
|---|---|---|
| GET /identity-switch/control | 无 | 内置 admin；others_enabled、revision、generation、显式授权角色/人数、非 admin 活跃会话数；人数去重 |
| PATCH /identity-switch/control | others_enabled、expected_revision、request_id；关闭另需 confirm_clear=true | 内置 admin；新状态、revision/generation、cleared_role_count、revoked_session_count；每个新关闭命令均清理遗留授权 |
| GET /performance/identity-switch/capability | 无 | 原始操作者；can_switch、can_manage_control、others_enabled、当前运行环境/模式、generation；不返回目标员工敏感字段 |
| GET /performance/identity-switch/people | q、page、page_size<=100 | 有切换资格；items[{employee_no,display_name,organization_label}]、total；不返回薪酬、手机号、邮箱；参数化查询 |
| POST /performance/identity-switch/sessions | employee_no、expected_generation、request_id | 有切换资格；201 {session_id,session_token,expires_at,effective_identity,mode}；切换新员工时先显式退出本页旧会话，失败不得假装成功 |
| GET /performance/identity-switch/session | 原始 Bearer + X-App-Switch-Session | 当前有效会话、operator 摘要、effective employee、mode；控制类接口不使用目标权限 |
| DELETE /performance/identity-switch/sessions/{id} | 原始 Bearer | 所属操作者；204，幂等恢复本人；不得撤销他人会话或切换其他应用 |
| GET/PUT /roles/{id} | 现有请求/响应可选附加 identity_switch_generation | 原有角色读写权限不变；提交/保留切换授权时要求当前 generation 且开关开启；缺版本或旧版本拒绝切换授权写回，不静默丢其他字段 |

POST sessions 不允许客户端自行指定 TARGET_POLICY 提升模式，模式由批准的环境策略控制。开关开启本身不授予任何角色；恢复本人必须允许在原切换已失效时完成本地清理。

错误 envelope 建议 `{detail:{code,message}}`，前端需保持现有错误解析兼容；T01 冻结，不能各接口自行用不同字符串。

| 状态码 | 稳定错误码 |
|---|---|
| 401 | OPERATOR_UNAUTHENTICATED / OPERATOR_DISABLED |
| 403 | SWITCH_CONTROL_ADMIN_ONLY / SWITCH_DISABLED / SWITCH_PERMISSION_DENIED / SWITCH_SESSION_OWNER_MISMATCH / SWITCH_READ_ONLY |
| 404 | SWITCH_TARGET_NOT_FOUND；业务对象复用已有不泄露存在性的 404 约定 |
| 409 | SWITCH_CONTROL_VERSION_CONFLICT / SWITCH_AUTHORIZATION_GENERATION_CONFLICT / SWITCH_IDEMPOTENCY_CONFLICT / SWITCH_TARGET_AMBIGUOUS |
| 410 | SWITCH_SESSION_EXPIRED / SWITCH_SESSION_REVOKED |
| 422 | SWITCH_VALIDATION_ERROR / SWITCH_APP_NOT_SUPPORTED |
| 503 | SWITCH_IDENTITY_SOURCE_UNAVAILABLE / SWITCH_ADMIN_ANCHOR_UNAVAILABLE |

### 6.4 开关、事务和并发

1. 初始关闭；开启仅改开关和 revision，不创建授权/会话。
2. 每个有效关闭命令在同一事务内锁设置行，核验 revision，关闭开关、generation+1、清除所有角色切换授权、撤销非 admin 会话、追加审计并提交；任一步失败整体回滚。重复 request_id 返回原结果，不重复增加 generation；相同 key 不同 payload 为 409。
3. admin 会话跳过公共开关、generation 和显式角色授予检查，但仍受真实账号状态、会话到期/退出、已批准运行环境/模式和正常业务授权约束。
4. 非 admin 创建和每次使用会话，都检查开关、generation、操作者有效状态及最新角色授权；撤销/停用角色、移出角色后下一请求失效。
5. 角色授权保存与关闭共享数据库串行化边界；旧角色页即使跨越关闭再开启，旧 generation 仍为 409，不能还原勾选。原有不含切换授权的角色客户端保持兼容。
6. 如批准写入，切换业务写事务必须与关闭建立一致锁序/线性化边界：关闭提交前已完成的业务提交不回滚；关闭成功后不得再按旧会话提交。只读在途响应由 UI 撤销/丢弃；已交付的数据无法追回。
7. 不删除审计；后台重启、多实例请求和重新开启不能恢复历史权限或会话。seed 对新权限仅注册，不给超级管理员自动补权；内置 admin 内建资格独立保留。

### 6.5 授权适配与会话安全

- Bearer 永远证明真实操作者；X-App-Switch-Session 为附加的受控身份凭证，仅对允许的 performance API 发送，服务端核验 operator、app、有效期及撤权状态。
- 任意携带切换凭证的业务请求若凭证无效则明确拒绝，不静默回退 admin。Portal 普通 API 不消费目标身份；切换不能额外赋予其访问资格。
- 切换分支使用可信 employee_no 定位快照/任务，再复用现有身份、范围、对象授权和状态校验；所有使用 portal_user_id、display_name、subject_id 的相关路径须列清并验收，不能只修一条工作台查询。
- 切换后的菜单、路由、字段、按钮、聚合、详情、导出不能使用操作者的 role_grants / permission_codes；不得启用 dev admin preview。目标员工确有业务管理授权时，仅其自身有效授权可生效；不能通过同名猜测绑定。
- 控制面检查切换资格与被切换业务面相分离；不嵌套身份切换。操作者可选择新员工，后端仍按原操作者鉴权，审计链不丢失。
- 当前 TARGET_POLICY 允许目标本来有权的写操作，不按 POST 一概禁止；通知独立按 LOG_ONLY / CONTROLLED_TEST 控制，原业务接收方始终禁投。
- 导出若异步执行，执行前再次核验，下载也须校验同一资格；旧下载地址不可绕过撤权。

## 10. 消息测试最终规则（2026-10-28）

### 10.1 已确认业务行为

- 开发和生产均支持目标员工权限内真实操作；业务落库与通知投递分别反馈。消息静默不等于业务沙箱，站内任务和结果可见性仍会依实际操作改变。
- **始终禁止向原业务接收人及业务群投递**；不是只屏蔽被切换员工。admin、样例、汇总、异步任务和重试均受此限制，不提供恢复原接收方实发的选项。
- 默认仅记录；admin 可开放受控测试投递并维护核验后的测试接收方，普通操作者不能任意填写接收地址。
- **每次测试单独生成一份结果汇总；受控投递开启且接收方合规时发送一条独立汇总通知。消息样式验证只发送一条样例。**一轮样式测试合计最多两条；不验证样式时只有汇总一条；默认仅记录模式均保存预览而不外发。
- 全员启动等批量通知仍逐条判断触发、解析原接收人和生成内容，不因只发一条样例而跳过其余员工。500 人的启动通知也只投递一条样例加一条汇总，不把 500 条转发给测试人员。

### 10.2 批次与结果汇总

- 一次测试按明确的业务通知触发事件建立 test_run_id，例如一次绩效启动；不是每个员工、分页或内部接口调用。主动重新发起的新测试才是新批次；网络重试、队列分片及多实例执行仍属原批次。
- 汇总独立于样例，在批次完成或明确失败后生成，包含环境、批次/业务对象、实际操作者、目标员工、原计划人数、生成成功/失败/未完成数、原接收方拦截数、样例生成/投递状态和安全的明细入口。
- 生成成功不等于实际送达；未完成/失败不能写成全部通过。样例失败仍可由独立汇总报告；汇总投递失败仍在页面保留结果，不自动把整次业务操作判失败。
- 样例和汇总按批次分别持久化去重，发送前预占唯一名额；重复点击/重试不复制批次或额外发送。回执不确定时记录待核对，不盲目补发，不能未经验证保证外部 exactly-once 送达。

### 10.3 投递和隔离保护
