# PM-T008 UI Interaction（草案）

## 工作台 `/performance/workbench`

- 顶部项目筛选框：展示当前用户作为被评估人、评价人、360°执行人、校准人或复议处理人参与的全部项目；每项显示周期名称、周期起止时间和项目状态。同一项目多种身份合并为一个选项，默认项目、排序和身份标识待确认。
- 流程时间轴：节点名称来自“绩效模板 → 流程设置”维护的环节名称（项目启动时保存为节点名称快照），不按节点类型生成固定名称，不用执行人标签替代名称；按模板顺序保留全部节点及同名节点。时间使用项目维护的节点起止时间，溢出时可横向滚动。结果查看、结果复议不展示在此处，但不能据此隐藏“我的绩效”或任务数据。
- 结果卡片：结果发布后，在工作台独立展示“查看绩效结果”卡片，包含结果查看说明和“查看”按钮；点击跳转至“绩效评估 → 查看绩效结果”。该卡片不属于“我的待办”，结果发布前不展示。
- 我的待办：分“待完成”和“已完成”两个标签，数据来自任务查询 API；多种参与身份的任务合并展示，并按流程节点聚合为一条。节点条目显示节点名称和数量，例如“上级评价（待评价 5 人）”；点击后进入该节点对应的人员列表。未完成任务即使逾期仍在“待完成”，逾期通过标签/提示体现；只有实际完成后才进入“已完成”。结果查看不进入任务列表。未开放任务展示语义待 Q2 确认。必须有加载态、空态、错误态和无权限态。
- 快捷入口：按已确认的流程身份/权限展示入口；具体入口名称、目标路由、显示条件和空态待 Q6 确认，不能用菜单现状推断业务授权。
- 复议处理待办：结果发布后，只有被评估人提交复议申请，才在待办中出现复议处理节点；未提交复议时不展示该节点。处理人沿用模板执行人优先、项目兜底人员次优规则。
- 公告：一期只展示占位面板，不提供新增、编辑、删除或发布操作。

## 工作台与绩效评估共享项目上下文

- 工作台与绩效评估共用当前 `project_id`；URL 中明确传入的 `project_id` 优先，否则读取共享状态。
- 任一页面切换项目后，立即同步共享状态和当前 URL；进入另一页面时沿用同一项目/周期。
- 工作台、绩效评估和任务填写之间的站内跳转使用 Vue Router，不触发整页刷新。
- 从任务填写页返回时，绩效评估先恢复缓存的项目、分类和已选节点，不显示重新加载态；随后静默刷新服务端状态。
- 浏览器刷新后允许通过本地保存的 `project_id` 恢复选择，但业务数据仍必须重新从 API 获取。
- 已启动项目在“起止时间”重新保存节点时间后，评估页重新进入时静默刷新当前项目的节点状态；工作台时间轴与任务截止时间从项目当前配置查询，不读取冻结节点时间作为当前状态。

## 后台启动反馈

启动按钮进入提交中状态。成功提示应明确项目状态和任务生成结果；失败时保留编辑页并展示错误原因。当前代码成功文案为“项目已启动”，待 PM-T008 实现时改为真实生成结果，但不得在实现前宣称已完成。

## “我的绩效”边界

“我的绩效”流程保留绩效结果查看环节。该环节不出现在工作台顶部流程时间轴，也不进入“我的待办”。结果发布后工作台展示独立结果卡片，点击跳转到绩效评估的查看绩效结果页面。



## 绩效评估总览（用户补充规则）

绩效评估页面按加载的绩效模板动态展示四类节点：

1. **我的绩效**：工作总结环节、执行人为被评估人的评估型环节、360°邀请环节、绩效结果查看环节。
2. **给他人的评估**：仅在当前用户因他人邀请而产生 360°评估任务时展示对应评估型环节。
3. **我团队的绩效**：360°确认环节、校准环节、执行人为实线上级或虚线上级的评估型环节、结果沟通环节。
4. **其他事项**：结果复议处理环节。

页面标题使用实际加载的绩效模板名称，节点名称使用模板节点名称，不由前端写死。节点状态只展示三类：

- `待完成`：当前节点已进入时间窗口且未逾期；
- `未开始`：当前节点尚未进入开始时间；
- `已逾期`：当前节点已超过截止时间。

节点的执行人类型和 360°任务记录共同决定其归属，不能仅按节点展示名称猜测。无已启动项目时展示空态；模板加载失败时展示错误态和重试操作。

本页面属于新工作台、多状态任务流和信息架构变更，需先在 `specs/002-performance-management/ui-blueprints/PM-T008-workbench.md` 创建独立蓝图，并为目标任务生成独立 PNG。蓝图需覆盖默认、项目切换、待完成、已完成、空、加载、错误、无权限和公告占位状态；确认前不得正式 UI 实现。
