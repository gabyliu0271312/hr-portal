## 1. 背景与目标

后台“项目设置”完成配置并点击启动后，项目不仅变为“进行中”，还按项目成员和流程节点生成个人任务。工作台读取任务记录，为当前用户提供参与项目筛选、节点时间、待完成/已完成任务及快捷入口。

本功能接续 PM-T003 已定义的配置和启动入口，不另建一套项目系统。PM-T003 原先“启动只改状态、不生成任务”的阶段边界由本功能扩展，但本文件不代表相关代码已经实现。

## 3. 范围与非范围

范围：项目启动到任务记录落库、工作台查询及分区展示、复议执行人优先级、项目/任务权限过滤、历史快照保护及错误反馈。

非范围：具体工作总结/评价/校准表单、分数计算、结果内容发布与详情页、复议申请/处理表单、团队详情页、飞书通知、公告内容及后台。已存在业务页可作为受权限保护的入口目标；不存在的目的页不得用虚假成功跳转代替。

## 4. 角色与数据边界

- 周期管理员或授权项目管理员沿用 PM-T003 启动权限；普通用户不获得后台项目配置权限。
- 被评估人是项目成员来源；任务执行人不一定等于被评估人，须按节点执行规则解析。
- 当前用户只能读取与自身身份和对象范围匹配的项目、任务；管理权限不自动产生个人待办。
- 周期/项目快照一旦用于已开始业务，实时花名册或模板变化不得静默改写历史记录；快照具体引用与启动前冻结时点见 Q5。

## 5. 设计约束（待技术契约冻结）

- 沿用启动接口；不得保留一个只改状态的旁路绕开任务生成。
- 状态迁移、被评估人结果固化、流程执行上下文和任务落库须保持一致。建议单一事务、唯一约束和项目级并发锁，失败不留下半启动数据。
- 重复启动不得重复生成任务；确定的响应语义、历史 STARTED 项目处理方式由 API 契约冻结。
- 任务生成与任务开放分离：未来节点可以预生成记录，但何时进入待办、可否操作须符合时间窗口及前置业务状态，不能因生成就全部开放。
- 任务完成只由对应业务操作成功持久化后驱动，禁止前端任意勾选完成。
- 复议优先解析模板执行人；仅在无有效结果时使用项目兜底人员，不默认同时分配两组人。

## 6. 影响分析

| 层级 | 影响 |
|---|---|
| 后端/API | 扩展启动、增加当前用户项目/节点/任务查询；保持对象授权 |
| 数据 | 评估项目成员、流程执行快照、任务及唯一性；复用既有领域对象，不重复建表 |
| 前端 | 工作台筛选、时间轴、待办、快捷入口、公告空面板；我的绩效保留结果查看 |
| 迁移 | 实施前确定实际迁移 head、旧数据策略、升级/降级方案 |
| 审计 | 启动人、项目、快照版本、生成数量、失败和重试；不记录敏感评价正文 |
| 外部系统 | 无；不得发送飞书消息或启动新采集 |
