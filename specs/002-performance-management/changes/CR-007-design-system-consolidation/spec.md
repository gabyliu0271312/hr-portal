# CR-007 绩效 UI 设计系统收敛

- 状态：实施中
- 关联范围：绩效管理现有页面与共享组件
- 类型：UI 体系治理
- 不改变业务流程、权限、API、数据库和路由信息架构

## 背景

绩效模块已经存在容器、弹窗、按钮、表单控件和 Token，但页面仍保留多套局部实现。相同视觉结构在不同页面使用不同的圆角、间距、阴影、按钮状态和错误提示，导致后续新页面难以默认继承平台风格。

## 目标

1. 将稳定的页面 Surface、弹窗、Footer、按钮、表单状态和交互状态提炼为三层 Token。
2. 让绩效共享组件成为新页面的默认实现入口。
3. 收敛标准弹窗、Drawer、全屏业务壳的内容滚动和底部操作区契约。
4. 收敛主按钮、次按钮、文字按钮、危险按钮、图标按钮的 default/hover/focus/active/disabled/loading 状态。
5. 收敛必填标记、invalid 边框、错误文本、提示文案和无障碍关联方式。
6. 保留业务专属控件和页面专属布局，不把所有业务结构强行合并为单一组件。

## 非目标

- 不改变业务数据和提交逻辑。
- 不修改后端、数据库、权限、API 或路由。
- 不新增业务页面或改变既有信息架构。
- 不以 Token 替代弹窗和表单组件的布局行为。
