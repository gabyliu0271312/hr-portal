# CR-011 UI 交互：已完成评估详情抽屉

## 1. 页面/角色/入口

- 页面：既有 `/performance/review` 成员列表。
- 角色：现有权限模型允许查看对应评估任务的管理者/处理人；不扩大后端授权范围。
- 入口：列表中已完成且支持回看的评估成员行。

## 2. 布局与交互

- 抽屉贴视口右侧，无遮罩；宽度初值 1000px、最小 720px、最大为视口宽减 148px（窄视口自动适配）；独立 localStorage 键保存上次宽度。
- 左缘为 1px 视觉边界，41px 透明交互区，中央 20px SVG 三点图标；hover/focus/drag 呈品牌蓝。支持 Pointer Events、键盘箭头、Home/End、ESC、失焦/取消清理。
- Header 展示现有 API 返回的受权限裁剪人员快照信息、翻译入口、复制深链接和关闭；header 后面紧接横向任务页签。翻译服务尚未接入时明确提示原文保留，不发送敏感评价内容到外部服务。
- 正文采用灰色浏览底、白色评估内容面板；显示环节标题、提交/截止通知与只读模板 schema/answers。页签只来自详情 API 配置的 `reference_tabs`，未提交/无可见内容沿用明确空态/提醒权限。
- 复制 URL 包含项目、节点和 task id；首次加载及刷新时仅在路由参数完整且任务仍可读取时恢复详情。关闭返回列表并删除抽屉参数。
- 窄屏抽屉最大宽度适配视口，不触发 body 横向滚动；所有本地存储访问可失败而不阻断页面。

## 3. 明确不改

不新增模板字段、权限、后端任务状态、历史数据补写、流程/评估业务规则；不从当前组织/花名册重算已启动周期数据；不因参考图缺少 API 字段而臆造页签或提交人。

## 4. 二次明确的精确实现方式（覆盖§2冲突项）

CR-011-T02 采用已采集脚本的鼠标文档级事件/50ms节流、300ms resize防抖、Lockr命名空间和语言分栏缓存、width=720/initialWidth=1000配置；评估详情 keyboard=false，不自动移动焦点；进入300ms、退出200ms，退出完成后销毁；URL采用rootReviewId/activeTab，activeTab与当前及引用节点ID对应。保留本地授权任务API、真实模板schema/answers/reference_tabs，不假造飞书服务接口。翻译仍缺少可实现的服务证据和接入配置，继续明确提示、不上传评价原文。
