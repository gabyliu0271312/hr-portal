## 一、结论摘要：360°反馈为什么「展示与别的环节一致」

飞书**没有任何「360°反馈专用渲染器」**。360°反馈在查看绩效结果 / 参考区里的展示，与综合评级、价值贡献等评估内容**走同一条链路**：

```
查看绩效结果 stage.readTemplates = [绩效结果模板, 360°反馈模板(ref)]
        ↓
permission 表按 (stage, template, item, entry) 声明：
  360°反馈模板      → read
  360°反馈(item)     → read
  留言(item)         → read
        ↓
同一渲染器（Field → 真实控件），permission=read 即只读渲染
```

关键证据（`behaviors.json`）：

| 声明 | 值 |
|---|---|
| `stage`(查看绩效结果) `readTemplates` | `[绩效结果模板, 7704327027180175361]` |
| `7704327027180175361`（360°反馈（自愿评估）） | `name="360°反馈（自愿评估）", templateItems=[], ref=7699791836252209167` |
| `7699791836252209167`（真实 360°模板） | `templateItems=[prompt, 360°反馈(question), 留言(question)]` |
| `permission` 360°模板级 | `mode=read` |
| `permission` 360°反馈 entry | `mode=read` |
| `permission` 留言 entry | `mode=read` |
| `entrySetting`（360°模板在该环节） | **无记录** → viewType 缺省 = edit（照常渲染） |

**所以查看绩效结果里的 360°反馈 = 360°模板（prompt 说明 + 360°反馈 + 留言）按 permission=read 渲染**——与综合评级等完全同构，只是数据不同。

## 四、对我们实现的启示（阶段 3 落地依据）

1. **查看绩效结果环节**：我们 `result_view` 节点的 `content_slot='view'` 内容里，如果含「360°反馈」引用（reference_kind=node 指向 360°反馈环节），应渲染成 **360°模板条目（说明 + 360°反馈 + 留言）的只读态**——与综合评级等同一渲染器（`PerformanceTemplateRenderer(mode=readonly)`），而不是特殊组件。
2. **配置参考内容区**：参考区「360°反馈」页签（REA 实测展示「360°评估详情」：已评估信息条 + 评估维度/员工关系/人员类型表头 + 详情视图 + 空评估条目表单区）——这是**360°评估的详情视图**，与普通引用不同。需要按 `out/domspec1x/参考区-360反馈-直接上级评估.json` 像素级还原。
3. **一致性根源**：只要「查看绩效结果」和「配置填写内容」共用同一渲染器 + 声明表，360°反馈的展示就天然一致——这是飞书架构的自然结果，我们阶段 1+2 已对齐。
