# REA 模板预览 · DOM 参数与还原对照（100% 像素级基线）

> 本文件是「模板预览」三栏与 OKR 卡片的**唯一参数来源**。全部数值来自 REA 真实页面 DOM 的
> `getBoundingClientRect()` + `getComputedStyle()`，不使用截图估算。

## 4. 基线口径（重要）

- REA 侧数据在 **dpr=1** 重新采集：`node capture-1x.js`（复用已登录 Chrome 的 9333 调试端口）→ `out/domspec1x/*.json`，覆盖全部 11 环节。
- 上一版基线是 `deviceScaleFactor: 2` 抓取，边框显示 0.666667px、卡片高 64.33；本地 dpr=1 时浏览器把 0.667px 吸附为 1px、卡片 65。**用 dpr=2 数据对比 dpr=1 渲染会产生 0.3~0.7px 的假偏差**，本版全部结论以 dpr=1 为准。
- 校验脚本：`node compare3.js <环节名>`（文本级，按位置近邻配对；同一文本在 REA 被原生 `select` 复制的 option 节点不参与对齐）、`node final-check.js`（骨架锚点）。

## 7. 本轮修正（dpr=1 基线）

1. **字体栈**：`.ptp` 显式声明 REA 的 `LarkHackSafariFont…` 栈 + `font-feature-settings: "tnum"`，并让 `.performance-item-title` / 「全部内容」/ 「添加」继承，否则 O 标签 32.2 vs 35.7、详情按钮 103.2 vs 101.2。
2. **左栏**：320 + 独立 1px 分割线；「全部内容」按 REA 的 invisible 占位盒 64×26、文字左内缩 4、色 `#1f2329`、无图标。
3. **说明（prompt）**：预览按 REA 的 `ud__notice` 规格渲染——盒高 66（padding 9/16）、radius 6、bg `#f0f4ff`、标题 14/22 600、正文 14/22、均 `#1f2329`、图标 16 与正文距 8。
4. **富文本填写项**：预览盒 144 高（工具栏 36 + 内容 100 + 边框）、字段名与盒距 8、工具栏内缩 4/4 且图标步距 32、内容区左内缩 8；预览不再显示「请输入内容」占位。
5. **「添加」按钮**：`settings.allowMultiple` 的内容在预览显示 54×22 的「添加」（图标 14 + 距 4 + 左内缩 4），字段区与按钮距 4。
6. **评级胶囊等宽**：REA 7 个胶囊全部 60.4 宽（= 最宽标签 34.4 + 内缩 26）、连接线 34.7；改为脚本度量最宽标签后下发 `min-width`，胶囊与连接线位置与 REA 逐值相等。
7. **评级项字段名行与档位行距 8**（原 12）。
8. **OKR 标签**：`O` / `KR` 与序号拆成两个文本节点（与 REA DOM 一致）。
9. **邀请表单**：引导行为单文本节点（`#1f2329`，无高亮）；表格行分隔线改内阴影，避免 border 吃掉 1px 导致文字下移。
10. **说明正文逐行渲染**：REA 按源码换行把正文拆成多个块（每行一个 div），改为逐行 `div` 渲染，多行说明的文本节点与行高与 REA 一致。
11. **中栏参考内容改为只读结果态**：条目按 `view` 渲染（值占位「这里展示用户填写的内容」，评级渲染为评级标签），并且参考内容不再包含被引用环节的「说明」块（REA 实测）。
12. **评测胶囊等宽**改为脚本度量最宽标签（避免额外文本节点污染 DOM 与快照）。

## 8. 已知差异（非样式）

- 结果页 / 复核页等环节的专属内容类型（结果标签、单选组、自定义块）本系统暂无对应渲染器，需先补数据模型。
- 富文本编辑器高度按字段持久化（工作总结 144 / 价值贡献 166），预览统一取 144。
- 空态插图（`ud__empty` 120×120）为 REA 内联资源，用近似 SVG 占位。
- 「更多参考 / 团队统计」骨架未按 DOM 抓取（模板未配置该引用）。
