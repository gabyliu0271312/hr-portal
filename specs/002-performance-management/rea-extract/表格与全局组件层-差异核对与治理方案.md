# 表格 / 白容器 / 全局组件层：差异核对与治理方案

> 对照对象：REA「创梦人力 · 组织 → 序列」实测（`rea-extract/out/capture-jf/`，报告见 `REA组织架构序列页-架构提炼报告.md`）
> 我方对象：`hr-portal/frontend/src/components/performance/PerformanceManagementTable.vue`（705 行）及其消费者
> 本轮产出：差异清单 + 审计数字 + 目标架构 + 迁移步骤；未改任何业务代码

---

## 0. 三句话结论

1. **不一样，而且不止一处**：滚动归属、表头底色、行高/分隔线、固定列方向与阴影、白色容器的圆角与阴影——五项全部有差；本质是"el-table 内滚动"与"页面级外层滚动"两套模型混用。
2. **白容器没有单一来源**：同一个"白色卡片"在代码里有 3 种写法（组件内 `.table-surface`、消费者自写 `section.member-list-panel`、el-table 裸白底），圆角 8/8-8-0-0、阴影 3 种规格。
3. **命名问题的根因不是懒，是缺层**：`PerformanceManagementTable` 是 002 绩效模块内长出来的唯一表格实现，`components/common/` 只有 8 个组件、19 处引用，且 DataTable/PageTitle/SearchInput 与 Performance 版重复。217 个 `Performance*` 组件里，真正带业务语义的不到一半。

## 1. 表格差异逐项核对（锁定 / 白容器 / 表头 / 行）

### 1.1 锁定（固定列）——方向、阴影、能力三重不一致

| 项 | 我方实现 | REA 实测 | 判定 |
|---|---|---|---|
| 固定方向 | 原生模式只实现**左固定**：`column.fixed` → `is-fixed-left` + 累加 `left` 偏移（`PerformanceManagementTable.vue:89-107、445-454、693-697`）；`PerformanceTableColumn.fixed?: boolean` 也没有 right 语义 | **右固定**：操作列 `position: sticky; right: 0`（`ud__table-cell-fix-right ud__table-cell-fix-right-first`），表头与单元格同时粘住 | ✗ 方向对不上 |
| 右侧固定列 | 仅 el-table 模式由 `el-table-column fixed="right"` 承担（部门面板 `PerformanceDepartmentListPanel.vue:100`），不受组件自控 | 无阴影，只有正常行分隔线 | ✗ 不可控 |
| 固定列阴影 | ① 左固定滚动后显示 1px 竖线 + 三层极淡投影（`:694-695`）；② el 模式由 element-plus 默认 `--el-table-fixed-right-column` 投影（`is-scrolling-left .el-table-fixed-column--right.is-first-column:before`） | **无任何投影/竖线** | ✗ 我方"更重" |
| 横向滚动时的表头同步 | 原生模式手写 `headerWrap.scrollLeft = body.scrollLeft`（`:149-151`） | 表头随容器同一滚动，无需同步 | 实现不同、结果可等价 |

> 结论：做像素级还原，需要给原生表格补 `fixed: 'right'` 支持（sticky right + 无阴影），并把 el 模式的默认投影关掉。

### 1.2 白色容器（格式确实不一样，而且有三套）

| 来源 | 规格 | 位置 |
|---|---|---|
| A. 组件内 `.table-surface`（仅 `viewportSurface && !useNativeTable` 时挂） | padding 20、`--performance-content-surface-radius`、`box-shadow: 0 1px 4px rgba(31,35,41,.05)`、`overflow: hidden` | `PerformanceManagementTable.vue:600-609`；`tokens.css:66-69` |
| B. 页面模式（`scrollMode='page'`） | **组件不提供白壳**，由每个消费者自己写：`section.member-list-panel { border-radius:8px; background:#fff; box-shadow: rgba(31,35,41,.03) 0 4px 16px 4px, rgba(31,35,41,.02) 0 4px 8px, rgba(31,35,41,.02) 0 2px 4px -4px; padding:0 20px 20px }` | `ProjectMemberListPanel.vue:281`（另有 15 个文件同类硬编码） |
| C. REA 目标 | padding 20、**radius `8px 8px 0 0`（仅上圆角）**、**`box-shadow: none`**、`min-width: 980px`、页面底色本身为白、卡片直接在滚动容器里 | 实测 `measure-jf-detail.json` |

差异：**圆角**（全圆 vs 仅上圆）、**阴影**（有 vs 无）、**padding 归属**（组件 vs 消费者）、**卡片与滚动容器的关系**（卡片内滚 vs 卡片整体滚）。三者叠加后，视觉上"卡片感"完全不同。

### 1.3 表头 / 行 / 分隔线

| 项 | 我方原生模式 | 我方 el 模式（部门现用） | REA | 判定 |
|---|---|---|---|---|
| 表头底色 | `#fff`（`,header 644/689`） | `#fff`（`:644` 覆盖 `--el-table-header-bg-color`） | **`#f2f3f5` 常驻** | ✗ 最显眼的一处 |
| 表头 hover | `#f5f6f7` | 同 | 无（常驻灰） | ✗ |
| 表头高度 | 47px | 46.67px | 46px | ≈ |
| 表头下边框 | `1px rgba(31,35,41,.15)`（`:679` 的 border-top + `:689` 的 border-bottom） | el 默认 | **0（none）** | ✗ 多一条线 |
| 行高 | 52px（`:687`） | **48px**（`:654`） | 51px | ✗ el 模式差 3px |
| 行分隔线 | `rgba(31,35,41,.08)`（`:687`） | el 默认浅 | `rgba(31,35,41,.15)` | ✗ 偏浅一半 |
| 空值 | 空字符串 | `--` | `--` + `#bdbfc4` | 需统一 |
| 树形 | 不支持 | 不支持 | 18×18 展开钮 + 每级 14px 缩进 | 缺能力 |

### 1.4 滚动 / 分页

- 我方：`scrollMode` 默认 `inner` →`el-table :max-height="tableMaxHeight"`（默认 600，`:337-344`），滚动条在表体内部；`page` → 原生表格 + 自绘横向滑块 `feishu-hscroll`（`:682-685`），纵向滚动交给父容器。
- 部门面板当前是 `scroll-mode="inner"` + `max-height=600`（`PerformanceDepartmentListPanel.vue:74-75`）→ 与 REA"外层唯一滚动 + 表格全高"是两种模型。
- 分页：我方默认渲染内置分页（`:552-575`），REA 无分页。
- **组件已具备 `page` 模式**，切换成本低；真正要补的是"外层滚动壳"（见 §3 的 `UiEntityListPage`）和原生表格的样式对齐。

## 3. 目标架构（三层 + 命名规范）

```
src/styles/tokens.css        语义 token 单一来源：--ui-*（--performance-* 保留为别名过渡期）
src/components/ui/           全局原子层（禁止业务词、禁止 Performance 前缀）
   UiButton UiIconButton UiTextButton UiTag UiSearchInput UiPageTitle
   UiTable UiTableToolbar UiPagination UiEmpty UiPopover UiCheckbox UiDialog UiSurface
src/components/patterns/     组合层（可含"列表页/表单页"这类模式，不含绩效语义）
   UiEntityListPage：标题 + 描述 + 工具栏 + 表格 + 外层滚动壳（承载 REA 骨架）
   UiFormPage / UiDetailPage
src/components/performance/  业务适配层：只保留有业务语义的组件（周期/模板/校准/申诉…）
```

命名与准入规则（建议写入 `AGENTS.md` / UI 规范）：
1. 全局层统一 `Ui` 前缀，文件放 `components/ui/`，**不得**出现 `Performance`、`Ucp`、`Allocation` 等业务词。
2. 一个组件只有被 **≥2 个业务域**真实引用，才允许上移到 `ui/`；单域专用留在业务目录。
3. 新代码不得新增 `Performance*` 前缀的通用控件（按钮/输入/表格/tag/弹窗壳/标题）。
4. token 只用 `--ui-*` 语义层；`--performance-*` 冻结不再新增，作为 alias 保留到迁移完成。
5. 禁止在业务组件里硬编码颜色/阴影/圆角；白卡统一走 `UiSurface`。
