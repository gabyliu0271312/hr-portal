# 「头像+姓名」组件复用评估 & 催办铃铛像素对齐

> 承接《REA360°评估率弹窗-DOM与接口提炼报告.md》§5 复用评估。
> 本次深挖：「头像+姓名」是否已是全局复用组件？「我的团队→上级评估→成员列表」的催办铃铛现状？如何按 REA 采集的像素参数统一为同一组件？
> 结论前置：**`PerformanceMemberIdentity.vue` 就是现成的「头像+姓名」全局组件，已在 4 处复用；但 avatar 像素与飞书 360° 弹窗不一致，催办按钮缺铃铛图标**。统一路径见 §4。

## 1. 「头像+姓名」现有组件与复用点

### 1.1 组件本体：`PerformanceMemberIdentity.vue`

```vue
<template>
  <div class="member-identity">
    <span class="member-avatar" aria-hidden="true">{{ displayName.slice(-1) }}</span>
    <span class="member-name">{{ displayName }}</span>
  </div>
</template>
```

样式由 token 驱动（[tokens.css](frontend/src/styles/tokens.css)）：

```css
--performance-member-avatar-size: 32px;      /* 圆形头像直径 */
--performance-member-avatar-background: #e5eaf5;
--performance-member-avatar-color: #3b5b92;
--performance-member-avatar-font-size: 13px; /* 头像内首字 */
--performance-member-name-gap: var(--spacing-3); /* 12px，头像与姓名间距 */
```

头像 = 圆形色块 + **姓名末字**（`displayName.slice(-1)`），姓名 14px/22 继承表格字号，右侧省略号截断。

### 1.2 复用点（4 处，全部直接 import 同一组件）

| 使用处 | 场景 | 覆盖（local override） |
| --- | --- | --- |
| `ProjectMemberListPanel.vue:305` | **项目成员列表**「姓名」列 | 无 |
| `PerformanceReminderPanel.vue:54-56` | **上级评估催办**「被评估人/催办对象/直属上级/HRBP」列 | `:deep(.member-avatar)` 24px / 20px |
| `PerformanceReview360FeedbackPanel.vue:283` | 360° 反馈「姓名」列 | 无 |
| `PerformanceReview360InvitePanel.vue:210` | 360° 邀请「姓名」列 | 无 |

> ✅ **结论：已是全局复用组件**，不是散落的近似实现。成员列表、360°反馈/邀请、催办列表全走这一个组件。

## 3. 关键判断：是否「确保是同一个组件」

**现状已经是同一个组件**（`PerformanceMemberIdentity` 4 处复用），但存在两处像素不一致：

1. **催办面板的 avatar 用局部覆盖 24px/20px**（`PerformanceReminderPanel.vue:394,396`），360° 弹窗标签却是 20px——同一人名字段在不同页面头像尺寸漂移，破坏一致性。
2. **催办按钮缺铃铛图标**：REA 采集的飞书是「铃铛+催办」文字按钮，hr-portal 是纯文字「催办」，且是 selection-bar 勾选后触发，不是行内即时按钮。

### 需要用户决策的点（§4 给出方案）

- **头像尺寸统一基准**：360° 弹窗标签 20px 是「紧凑标签」场景；成员列表/上级评估表可能是 32px「宽列表」场景。是否**统一为同一 token**（如新增 `--performance-member-avatar-size-sm: 20px` 并让弹窗/催办用，还是全局改成 20px）？
- **真实头像 vs 姓名末字**：飞书 360° 弹窗是真实员工头像；hr-portal 现为姓名末字色块。若要求像素级一致，需接入头像数据源（员工头像 URL），这超出纯 CSS 调整。

## 4. 统一方案（单一组件 + token 对齐）

### 4.1 保持单一组件，消除局部漂移

`PerformanceMemberIdentity.vue` 加一个 `size` prop（`'md' | 'sm'`，默认 `md`），avatar 尺寸/字号/间距走 token：

```css
/* tokens.css 新增 */
--performance-member-avatar-size-md: 32px;   /* 列表默认 */
--performance-member-avatar-size-sm: 20px;   /* 弹窗/催办紧凑标签，对齐 REA */
--performance-member-name-gap-sm: 6px;        /* 对齐飞书标签间距 */
```

```vue
<span class="member-avatar" :class="`member-avatar--${size}`" aria-hidden="true">{{ displayName.slice(-1) }}</span>
```

调用处：
- 成员列表/360°反馈/360°邀请（列表行）→ 保持 `md`（32px）
- 催办面板被评估人列 → 改 `<PerformanceMemberIdentity size="sm">`（20px），**删掉 24/20px 局部覆盖**
- 360° 弹窗 person 标签（新建展示组件）→ `size="sm"`，与催办面板、飞书弹窗完全一致

### 4.2 催办按钮统一为「铃铛+催办」文字按钮

REA 采集的飞书催办是 `ud__button--text--primary`（BellOutlined + 文字）。hr-portal 已有 `BellOutlinedIcon.vue`（与飞书 SVG **完全相同**）。统一为新的 `PerformanceRemindButton`（或直接在现有催办入口加图标）：

```vue
<button class="remind-button" type="button">
  <BellOutlinedIcon /><span>催办</span>
</button>
```

样式对齐 REA：文字按钮、54×22px、圆角 6px、文字 `#1456F0`、铃铛 1em 前置 12px。
现有 selection-bar「催办」按钮 → 同样加 `BellOutlinedIcon` 前缀，保持同一组件形态。

### 4.3 真实头像（可选，像素级终极对齐）

飞书用真实头像；hr-portal 用姓名末字。若产品要求「弹窗标签与飞书一模一样」，需给 `PerformanceMemberIdentity` 加 `avatar-url` prop（fallback 姓名末字），并在成员接口带出头像字段。此为数据层改动，需评估接口字段支持。

## 5. 结论与建议

| 项 | 结论 |
| --- | --- |
| 「头像+姓名」是否全局组件 | ✅ 已是 `PerformanceMemberIdentity`，4 处复用 |
| 是否同一组件 | ✅ 是；但像素未对齐（头像 32/24/20px 漂移、缺铃铛图标） |
| 建议动作 | ① 组件加 `size` prop + token ② 催办入口统一 `BellOutlinedIcon + 催办` 文字按钮 ③ 弹窗 person 标签复用 `size="sm"` |
| 需用户决策 | 头像尺寸统一基准（32/20）、是否接真实头像数据源 |

> 本次仅评估，未改代码。方案 4.1/4.2 为纯前端展示层改动，可在确认后一次落地并跑 vitest 验证。
