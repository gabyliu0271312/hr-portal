# 绩效管理 Spec 002 启动入口

## 1. 适用范围

本目录管理 HR Portal 中绩效管理这一长期建设的业务规格、交互蓝图、架构决策、功能任务和变更记录。

绩效是模块化单体中的独立业务应用：复用 HR Portal 的登录态、应用入口和员工实时花名册来源，但独立维护绩效角色、权限、周期、流程、结果和申诉规则。

## 2. 开发前必读

每次绩效开发开始前，先读取：

1. 本文件。
2. `overview.md`、`integration.md`、`permission-model.md`、`data-model.md`、`workflow-design.md`。
3. 当前功能目录下的 `spec.md`、`atomic-tasks.md`、`ui-interaction.md` 或相关蓝图。
4. 相关架构决策 `decisions/ADR-*.md`。
5. 任务涉及任何 UI 时，追加读取根目录 `AGENTS.md` 要求的 Spec 012 UI 规范；涉及 UCP、数据接入、数据资产、Pipeline、Webhook 或外部系统时，再追加读取 Spec 011/012 相关文档。

## 3. 需求进入规则

先判断需求类型：新功能、既有功能增强、Bug 修复、权限调整、数据迁移、UI 调整、架构调整或外部系统集成。

- 新的业务能力：在 `features/PM-xxx-name/` 建立功能规格。
- 已有功能的小范围变更：优先修改原功能目录；跨功能变更记录在 `changes/CR-xxx-name/`。
- 架构和长期约束：记录到 `decisions/ADR-xxx-name.md`。
- 纯 Bug、测试或部署问题：不强制创建完整功能规格，但必须关联已有任务或变更记录。

未经过“已确认”的需求，不直接修改业务代码。

## 4. UI 蓝图门禁

新页面、复杂表单/向导、多角色工作台、多状态流程或信息架构调整，必须先生成并确认绩效专属 UI 蓝图，再开始正式 UI 开发。蓝图放在本目录的 `ui-blueprints/`，`specs/011-universal-connector-platform/ui-blueprints/` 只作为示意和交互表达参考。

小范围字段、文案、校验、样式或既有页面 Bug，可以只更新对应 `ui-interaction.md`，不要求重新生成完整 HTML 蓝图。

## 5. 开发启动确认

开始编码前，在回复中明确：

- 当前 Spec、功能目录和原子任务编号；
- 已读取的规格和蓝图；
- 本次修改范围与明确不修改范围；
- 是否涉及 UI、数据库迁移、权限、UCP 或外部系统；
- 已确认的假设、未解决的阻塞问题；
- 计划执行的测试和验收证据。

## 6. 完成定义

原子任务只有在代码、迁移、UI、测试和验收证据均完成后才能标记 `[x]`。最终交付必须列出修改文件、测试命令与结果、UI 验证、未完成任务、风险和后续部署事项。
