# ADR-003：模板驱动绩效评估公共基座

- 状态：已确认
- 日期：2026-09-17
- 范围：绩效评估运行页、模板任务入口、答案适配、提交后展示与共享视觉基座
- 决策类型：前端架构与业务契约边界

## 1. 背景

工作总结已完成模板驱动填写、保存、提交、重开和完成态展示。但其页面壳、入口策略、完成提示、只读答案和视觉值若继续以任务页面私有实现演进，会导致上级评价、项目评价、360°评价、校准和结果相关页面复制相同结构。

现有模板配置侧已经采用共享内容模型与显式 renderer context；运行侧需要采用相同原则，同时保护已启动项目的任务、模板和答案快照。

## 2. 决策

绩效评估运行页采用：

```text
公共页面壳
+ 显式 task entry registry
+ 模板 section/field renderer registry
+ 统一答案 adapter
+ 公共完成态容器
+ 任务/角色专属策略
```

### 2.1 公共化边界

必须公共化：

- 评估页白卡、左右边界、滚动策略、loading/error/empty；
- 标题与时间可见性规则；
- 完成提示、编辑入口和 readonly 容器；
- section/field 的模板驱动循环；
- rich text/rating/tag-with-followup 的稳定 renderer；
- 重复 section 答案访问和 mutation；
- 稳定视觉 token。

### 2.2 个性化边界

必须保留在任务/角色专属策略：

- 任务生成、处理人、权限和匿名性；
- 评分计算、校准调整、结果发布和申诉动作；
- 未来未冻结的 field type；
- 节点特有的上下文、审计与错误码。

### 2.3 入口规则

入口只由 `entry_mode + task_kind + task_id` 决定。节点名称不是稳定路由判别键；当前工作总结名称正则仅允许在迁移期兼容层存在，并在所有已注册 task kind 完成迁移后删除。

## 3. 后果

### 正面

- 新模板任务优先通过 registry 接入，不复制白卡和基础 field DOM；
- 完成态视觉修复一次即可覆盖所有使用公共壳的节点；
- 编辑、提交、重开和只读展示使用同一答案协议；
- 前端能够在缺少新任务业务细节时受控拒绝，而不是错误落到工作总结页面。

### 代价

- 需要先重构工作总结为首个适配实例，短期代码量增加；
- 公共 contract 变更需要前后端和测试同步；
- 所有未来 task kind 必须在接入前登记 renderer 和 entry strategy。

## 4. 非决策

本 ADR 不决定未来评分、匿名评价、校准或申诉的具体答案 schema；这些由对应功能规格冻结后接入 registry。
