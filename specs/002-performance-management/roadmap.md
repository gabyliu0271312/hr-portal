# 绩效管理分期实施建议

## 1. 第一期目标

第一期目标不是做通用 BPM，而是做一个配置型绩效专用流程系统。

核心能力：

- 独立绩效应用入口
- HR Portal 入口权限接入
- 绩效人员来自员工实时花名册
- 绩效周期配置
- 流程模板配置
- 时间节点驱动
- 工作内容总结
- 员工自评
- 上级评价
- 项目评价
- 多级校准
- 强制分布三档控制
- 结果发布
- 员工查看结果
- 每周期一次申诉
- 审计记录

## 1.1 后续执行策略

后续开发遵循 [ADR-002：业务骨干优先与分级 UI 还原策略](decisions/ADR-002-business-first-ui-fidelity.md)，不再把全系统像素级前端还原作为所有业务开发的前置条件。

### 开发顺序

采用纵向业务切片，每个切片同时完成必要的后端、后台配置、用户端页面、权限、测试和真实验收：

```text
业务规则与领域边界
-> API、权限、快照和审计
-> 最小可运行的前后台闭环
-> 关键用户页面视觉收口
-> 低频后台页面像素细节
```

第一条优先闭环为：

```text
周期创建
-> 模板绑定
-> 周期启动
-> 周期人员/流程快照
-> 员工工作总结
-> 员工自评
-> 上级评价
-> 结果发布
-> 员工查看结果
```

### UI 完成等级

- 管理员后台默认先达到 P0 业务可用和 P1 结构/设计系统一致；
- 员工填报、评价和结果查看页面优先达到 P1，并在业务稳定且证据完整后进入 P2 像素级还原；
- P2 视觉缺口不得阻塞无关的后端、权限、持久化和业务闭环任务；
- 只有完整采集证据、运行时 rendered contract 和截图 diff 齐备时，才可宣称像素级通过；
- 高风险管理员操作（删除、发布、锁定、校准）即使不做 P2，也必须保证确认、权限、错误恢复和审计完整。

### 阶段推进规则

- 当前阶段优先完成能支撑第一条端到端闭环的任务；
- 后台模板、评估题和评估规则页面达到 P0/P1 后先冻结，未采集的低频 P2 状态后移；
- fixture 或 mock 只能作为并行开发手段，不能作为真实功能完成依据；
- 业务、API、数据库或权限规则发生变化时，先更新对应 Spec 和任务契约，再修改代码；
- 未确认的问题继续维护在 `open-questions.md`，AI 不得自行猜测。

## 2. 阶段 1：基础应用骨架

建设内容：

- 新增绩效前端布局 `PerformanceLayout`
- 新增绩效路由 `/performance/*`
- 新增绩效后端模块 `/api/v1/performance/*`
- 新增 HR Portal 入口权限 `performance.app`、`performance.admin`
- 新增绩效人员映射基础能力

验收标准：

- 用户可从 HR Portal 进入绩效管理
- 无权限用户不能进入绩效管理
- 绩效后台入口按权限展示

## 3. 阶段 2：人员与周期

建设内容：

- 从员工实时花名册同步绩效人员
- 建立绩效人员主档
- 建立身份映射
- 创建绩效周期
- 生成周期人员快照

验收标准：

- 可创建绩效周期
- 可选择参与人员范围
- 周期启动后人员快照不受后续花名册变化影响

## 4. 阶段 3：流程模板与节点任务

建设内容：

- 流程模板管理
- 节点类型配置
- 节点时间窗口配置
- 最晚提交时间配置
- 周期启动后生成节点快照和任务
- 项目启动并按被评估人和流程节点生成个人任务
- 工作台项目筛选、流程时间轴和我的待办

验收标准：

- 工作内容总结和员工自评可以配置为独立节点
- 时间重合时可同时开放
- 可分开提交
- 节点配置快照固化

## 5. 阶段 4：评价能力

建设内容：

- 工作内容总结
- 员工自评
- 上级评价
- 项目评价
- 项目成员与项目权重
- 节点权重计算

验收标准：

- 员工可提交工作内容总结
- 员工可提交自评
- 直属上级可评价下属
- 项目负责人可评价项目成员
- 多项目评价可按配置参与最终结果计算

## 6. 阶段 5：校准与强制分布

建设内容：

- 部门/组织校准
- 公司级校准
- 校准调整分数和等级
- 强制分布配置
- 不控制、软控制、强控制三档
- 低于人数下限不控制

验收标准：

- 校准人可以按组织范围校准
- 校准可调整最终等级或分数
- 调整过程可追溯
- 强制分布规则按配置生效

## 7. 阶段 6：发布与申诉

建设内容：

- 结果发布
- 员工结果查看
- 申诉提交
- 申诉处理
- 申诉最终反馈等级、分数和说明
- 申诉结果覆盖最终结果

验收标准：

- 发布后员工可查看最终结果
- 每周期每人最多申诉一次
- 申诉关闭后最终结果以反馈为准
- 员工不可见校准说明

## 8. 阶段 7：飞书 SSO

建设内容：

- 飞书 SSO 登录
- 通过手机号或邮箱匹配绩效人员
- 匹配成功后签发系统 token
- 匹配失败提示

验收标准：

- 用户可以从飞书工作台独立进入绩效管理
- 匹配不到人员时有明确提示

## 9. 后续增强

后续可考虑：

- 飞书消息提醒
- 飞书待办
- 项目评价更复杂权重算法
- 申诉多步骤处理
- 结果修正/复核节点
- 管理员特殊纠错
- 绩效看板和分析报表
