# AI 数据质量治理扩展规划

## 1. 文档定位

本文是 `018-data-quality-dependency-governance` 的扩展规划，解决基础质量规则需要逐个数据资产人工配置、规则规模扩大后维护成本高，以及数据异常难以提前发现的问题。

本文不替代 `spec.md`、`ui-interaction.md`、`atomic-tasks.md` 和 `testing-acceptance.md`，而是在既有质量状态、依赖传播、报表门禁和生产脱敏设计之上，增加自动画像、规则模板、AI 规则推荐和历史异常检测能力。

核心原则：

1. 确定性规则负责生产门禁，AI 不直接替代质量规则引擎。
2. 平台基线和规则模板负责自动覆盖，避免逐资产重复配置。
3. AI 负责发现、推荐、解释和辅助定位，正式规则及阻断策略必须可审核。
4. 生产环境只向 AI 传递元数据、聚合指标、脱敏样例和哈希，不传递工资、员工号、客户名等明文。
5. 所有自动建议和人工确认都必须可追溯、可撤销、可重放。

## 2. 现状与问题

当前质量规则主要以表、字段、关系等资产为对象创建。该模型适合执行和状态存储，但如果所有数据表、字段和关系都要求管理员逐条创建规则，会产生以下问题：

- 新增数据表后需要重复配置基础规则；
- 同一业务域的规则无法批量复用；
- 规则严重级别和阈值容易出现人为不一致；
- 规则覆盖率无法量化；
- 只配置静态规则，难以及时发现行数、分布、延迟和匹配率异常；
- AI 如果直接扫描明细或直接写入阻断规则，会带来隐私、误报和不可审计风险。

因此，系统需要从“人工逐资产配置”升级为：

```text
平台基线规则
    + 资产模板继承
    + AI 规则建议
    + 历史指标异常检测
    ↓
正式质量规则与质量状态
    ↓
数据集聚合
    ↓
报表门禁
```

## 3. 目标与非目标

### 3.1 目标

- 对已登记数据资产自动生成最小安全质量基线；
- 通过业务域和资产标签批量继承规则模板；
- 使用 AI 根据元数据和画像结果推荐质量规则；
- 使用统计基线和异常检测发现历史趋势变化；
- 生成脱敏的异常解释、可能原因和建议动作；
- 将 AI 建议与正式规则、质量状态、报表门禁明确分层；
- 支持规则覆盖率、建议采纳率、误报率和异常闭环统计；
- 保持现有 `table/field/relation/dataset/report` 状态传播和报表门禁模型不变。

### 3.2 非目标

- 不允许 AI 直接读取生产明细并输出原始值；
- 不允许 AI 未经审核直接创建 `block` 规则；
- 不允许 AI 直接修改关系业务键或自动删除重复数据；
- 不用大模型替代确定性 SQL 检查；
- 不在每个报表复制一份表级或关系级规则；
- 不建设第二套质量菜单、调度中心或告警中心；
- 不把异常检测结果直接等同于业务事实错误。

## 4. 规则适用模型

### 4.1 平台基线规则

平台基线针对所有满足条件的已登记资产自动适用，不要求管理员逐资产创建。

| 资产或元数据 | 默认检查 | 默认策略 |
|---|---|---|
| 主键、技术 ID | 非空、唯一 | `block` |
| 数据库唯一约束 | 唯一 | `block` |
| 已登记期间字段 | 非空、`YYYYMM` 格式、期间可解析 | `block` |
| 明确声明的枚举约束 | 枚举合法性 | `warn`，业务确认后可升级 |
| 外键/关系元数据 | 关联完整性、关系基数 | `warn`，关键关系确认后可升级 |
| 普通可选字段 | 不自动添加 `not_null` | 不适用 |

平台基线必须遵守元数据事实，不能仅根据字段名称猜测主键、期间字段或必填字段。

### 4.2 业务规则模板

模板按业务域、资产标签、表命名模式或登记元数据匹配。建议首批支持：

- 月度员工表模板；
- 月度薪资表模板；
- 成本分摊表模板；
- 组织架构表模板；
- 关系因子表模板。

模板内容包括：

- 匹配条件；
- 规则类型和字段映射；
- 默认严重级别；
- 默认阈值；
- 适用期间策略；
- 是否需要人工确认；
- 例外和排除条件。

模板只生成规则实例或规则建议，不复制到每个报表。多个报表共享同一数据集时，共享同一份质量结果。

### 4.3 AI 推荐规则

AI 推荐只能基于脱敏元数据和聚合画像，输出草稿，不直接进入生产门禁。

推荐输入：

- 表名、字段名、字段类型和字段注释；
- 主键、唯一键、外键和登记期间字段；
- 行数、空值率、唯一率、基数和长度分布；
- 枚举值数量及哈希后的候选样例；
- 关系两侧匹配率和重复率；
- 历史质量状态和人工反馈。

推荐输出：

```json
{
  "asset_type": "field",
  "asset_code": "emp_monthly_salary.employee_id",
  "rule_type": "unique",
  "rule_config": {"column": "employee_id"},
  "suggested_severity": "block",
  "confidence": 0.98,
  "evidence": ["字段命名符合员工标识语义", "历史唯一率为100%"],
  "requires_review": true
}
```

AI 推荐页面必须支持：接受、修改后接受、拒绝、忽略本次、永久忽略和查看依据。

## 5. 自动画像与指标基线

### 5.1 画像指标

对已登记资产按期间生成最小画像：

- 行数和分区行数；
- 非空率；
- 唯一率；
- 不同值数量；
- 数值最小值、最大值和分位数；
- 字符串长度分布；
- 日期最小值、最大值；
- 枚举值数量；
- 关系匹配率、重复键数、缺失键数；
- 同步完成时间和数据延迟。

画像只保存聚合值和受控哈希样例，不保存整行样例。

### 5.2 历史基线

异常检测必须按资产、字段、指标和期间建立历史基线。建议规则：

- 首次接入只生成画像，不直接判定异常；
- 至少积累多个有效期间后再启用趋势检测；
- 季节性指标优先比较去年同期或同业务周期；
- 新增业务期间、节假日、组织大调整等情况支持人工标记；
- 基线调整必须记录原因、操作人和生效时间。

### 5.3 异常状态

异常检测结果建议独立于确定性质量状态保存：

- `detected`：模型检测到异常，待确认；
- `confirmed`：管理员确认异常；
- `accepted`：管理员确认是业务合理变化；
- `resolved`：已处理并重新检查；
- `ignored`：在有效期内忽略。

在管理员确认之前，AI 异常默认只产生 `warning` 风险提示，不直接阻断报表。

## 6. AI 诊断与根因辅助

AI 诊断输入只允许使用：

- 质量规则结果；
- 画像指标及历史变化；
- 表、字段、关系和数据集血缘；
- 同步批次、期间和任务日志摘要；
- 脱敏后的错误码和状态。

AI 诊断输出应包含：

1. 异常摘要；
2. 影响期间；
3. 影响资产、数据集和报表数量；
4. 可能原因，按置信度排序；
5. 建议检查步骤；
6. 建议重试、接受风险或升级规则的动作；
7. “证据不足”提示。

示例：

```text
问题：emp_monthly_salary.pay_month 的非空率从 100% 降至 94.2%
影响期间：202607
可能原因：
1. 上游工资文件缺失期间字段；
2. 字段映射配置发生变化；
3. 新增记录未填充期间值。
建议：检查同步批次字段映射，并重新执行该期间质量任务。
```

AI 不能声称已确认未被数据证据支持的根因，不能建议直接删除生产数据。

## 7. 状态、门禁与安全边界

### 7.1 状态优先级

确定性规则和人工确认结果优先于模型建议：

```text
failed + block  >  failed + warn  >  warning  >  pending  >  passed
```

AI 异常在未确认前最多影响风险提示，不改变确定性规则的最终状态。

### 7.2 报表门禁

- 表、字段和关系规则只配置一次，结果向数据集和报表传播；
- 报表仅配置期间字段语义，不复制质量规则；
- 数据集只有一个期间字段时允许自动推断；
- 数据集有多个期间字段时，报表配置 `quality_period_field`；
- 未来可增加数据集默认期间字段，报表只对特殊情况覆盖；
- 报表运行和导出只读取缓存状态，不实时扫描底层明细。

### 7.3 脱敏约束

禁止向 AI 或接口响应传递：

- 工资、奖金、补贴金额；
- 员工号、姓名、身份证号、手机号；
- 客户名称和业务敏感编码；
- 原始 SQL 错误文本和数据库异常堆栈。

允许传递：

- 计数、比例、状态和期间；
- 字段代码和资产 ID；
- 固定长度不可逆哈希样例；
- 错误码和脱敏摘要；
- 数据血缘和任务追踪 ID。

## 8. 推荐数据模型扩展

在现有质量模型之上，建议新增以下概念，具体表名以后续 migration 设计为准：

### 8.1 `quality_profile_metrics`

保存资产、字段、期间的聚合画像指标：

- `asset_type`、`asset_id`、`asset_code`；
- `period`、`metric_name`、`metric_value`；
- `baseline_value`、`deviation_score`；
- `source_sync_batch_id`、`computed_at`；
- `profile_version`。

### 8.2 `quality_rule_templates`

保存业务模板：

- 模板编码和业务域；
- 匹配条件；
- 规则定义；
- 默认严重级别和阈值；
- 版本、生效时间和启用状态。

### 8.3 `quality_rule_recommendations`

保存 AI 推荐草稿：

- 推荐规则配置；
- 置信度；
- 推荐依据；
- 模型版本和提示版本；
- 审核状态；
- 审核人、审核时间和审核意见。

### 8.4 `quality_anomalies`

保存历史异常及闭环：

- 指标和资产；
- 期间和基线版本；
- 偏差值和异常分数；
- 当前状态；
- 人工反馈和处理记录；
- 关联质量运行、同步批次和报表影响范围。

## 9. UI 规划

在现有“数据仓库 → 数据治理 → 数据质量”页面增量增加：

1. **自动画像摘要**：行数、非空率、唯一率、关系匹配率和延迟；
2. **AI 建议规则**：建议内容、置信度、依据、接受/拒绝；
3. **模板管理**：查看业务模板、适用资产数和版本；
4. **异常列表**：异常分数、影响期间、影响资产和处理状态；
5. **诊断助手**：展示脱敏解释和建议动作，不展示原值；
6. **覆盖率统计**：基线覆盖率、模板覆盖率、审核通过率、误报率；
7. **人工反馈**：确认异常、接受风险、忽略、重新检查和关闭。

默认页面顺序建议：

```text
质量仪表盘
  → 规则与模板
  → AI 建议
  → 异常列表
  → 按期间质量状态
  → 诊断详情
```

## 10. 调度与运行流程

```text
资产登记/同步完成
  → 自动画像
  → 应用平台基线
  → 匹配业务模板
  → 生成 AI 推荐草稿
  → 人工确认正式规则
  → 运行确定性规则
  → 运行历史异常检测
  → 保存质量状态与异常记录
  → 聚合 dataset/report
  → 报表读取缓存门禁
```

同一资产、期间和同步批次必须幂等。画像和异常检测失败不能覆盖已经存在的确定性质量结果，应分别记录任务状态并支持补偿重试。

## 11. 验收标准

### 11.1 自动基线

- 新登记带主键的数据表自动生成非空和唯一建议或正式基线；
- 已登记期间字段自动生成期间格式检查；
- 普通可选字段不会被批量错误生成为必填；
- 基线规则可查看来源、版本和适用范围。

### 11.2 模板继承

- 同一业务模板可匹配多张数据表；
- 新资产匹配模板后可生成待审核规则；
- 修改模板有版本记录，不破坏历史运行结果；
- 资产可配置例外和排除原因。

### 11.3 AI 推荐

- 推荐结果包含置信度、依据、模型版本和审核状态；
- 未审核推荐不会进入报表阻断；
- 审核接受后生成正式规则，拒绝后可追踪原因；
- AI 输入和输出日志不包含敏感明文。

### 11.4 异常检测

- 至少有历史基线后才执行趋势异常判断；
- 支持季节性、业务调整和已知事件标记；
- 异常支持确认、接受、解决、忽略和重新检查；
- 模型异常不会覆盖确定性规则失败。

### 11.5 报表与安全

- 表/字段/关系规则只配置一次即可被多个报表复用；
- 同一数据集单期间字段时，报表可自动推断期间字段；
- 多期间数据集支持报表级字段覆盖；
- 接口、数据库、日志和 AI 请求中不出现工资、员工号、客户名等原值；
- 门禁只读缓存状态，不在报表查询期间扫描底层关系。

## 12. 分阶段实施建议

### Phase 1：自动画像与基线

- 画像指标表和采集任务；
- 主键、唯一键、期间字段基线；
- 规则覆盖率和来源展示；
- 不接入大模型，不改变现有门禁策略。

### Phase 2：业务模板

- 月度员工、薪资、成本分摊、组织模板；
- 模板匹配、继承、例外和版本；
- 批量审核和批量启停。

### Phase 3：AI 规则推荐

- 元数据和画像输入；
- 规则推荐草稿、置信度和审核流；
- 模型版本、提示版本和反馈记录；
- 默认只生成 `warn` 建议，不直接生成 `block`。

### Phase 4：异常检测与诊断

- 历史指标基线；
- 行数、非空率、唯一率、匹配率和延迟异常；
- 脱敏诊断助手；
- 异常闭环和报表影响范围。

### Phase 5：治理度量

- 覆盖率、误报率、采纳率、平均处理时长；
- 模板命中率和 AI 建议质量；
- 模型漂移和基线重建；
- 质量治理月度报告。

## 13. 与现有 018 需求的关系

本文新增能力必须复用现有设计：

- 复用 `WarehouseQualityRule`、`WarehouseQualityRun` 和 `WarehouseQualityStatus`；
- 复用同步后质量任务和质量队列；
- 复用依赖索引和 dataset/report 状态聚合；
- 复用现有质量页面，不新建第二个质量中心；
- 复用现有脱敏和哈希样例规范；
- 复用现有报表门禁策略。

本规划只扩展规则来源、画像、异常和 AI 辅助能力，不改变“同步后按影响期间检查、状态缓存、报表只读门禁”的核心闭环。
## 14. 当前系统实现现状与差距

本节用于区分当前代码已经具备的能力与本文规划的后续扩展，避免把规划能力误认为现成功能。

| 能力 | 当前状态 | 已实现内容 | 仍缺少或待增强 |
|---|---|---|---|
| 基础质量规则 | 已实现 | 支持 `not_null`、`unique`、`enum`、`date_format` 等规则执行 | 尚未根据元数据自动生成平台基线 |
| 关系质量检查 | 已实现 | 支持关系基数检查、重复键计数、缺失键计数和哈希样例 | 尚未使用 AI 自动发现关系或推荐基数 |
| 同步后质量调度 | 已实现 | 同步成功后按实际期间创建质量任务，支持持久化补偿队列 | 大规模场景下仍需持续优化依赖查询和队列吞吐 |
| 依赖索引 | 已实现 | 支持关系依赖索引、重建和按表反查受影响关系 | 尚未建立完整的画像和 AI 推荐依赖模型 |
| 并发控制 | 已实现 | 状态 upsert、质量运行去重、任务抢占和重复事件幂等 | 仍需持续补充多实例压力和故障恢复验收 |
| 质量状态传播 | 已实现 | 按表、关系、数据集、报表和期间保存并聚合状态 | 尚未纳入画像指标和 AI 异常状态 |
| 报表质量门禁 | 已实现 | 支持无状态、`pending`、`failed/block`、`failed/warn` 和 `warning` 策略 | 尚未支持数据集默认期间字段继承和批量报表配置 |
| 生产脱敏 | 已实现 | 运行结果保存计数、状态和哈希样例，移除质量明细样例 | AI 请求、模型输出和诊断审计仍需统一治理 |
| 质量管理 UI | 已实现 | 支持规则列表、质量状态、期间筛选、影响范围、诊断抽屉和索引重建 | 尚未加入 AI 建议、画像趋势和异常处理工作台 |

### 14.1 当前可使用能力

当前系统可以直接使用以下能力：

1. 在数据质量页面创建和维护基础质量规则；
2. 对已配置的表、字段和关系执行质量检查；
3. 在同步成功后按实际期间触发受影响质量任务；
4. 通过持久化队列进行质量任务补偿和失败重试；
5. 查看按期间的质量状态、重复键、缺失键和哈希样例；
6. 查看受影响数据集、报表及诊断摘要；
7. 由报表门禁读取缓存质量状态并按策略允许运行、提示风险或阻断。

### 14.2 当前不能直接承诺的能力

以下能力属于本文后续规划，当前不能作为已经交付的产品能力对外承诺：

- 新增数据资产后自动生成完整质量规则；
- AI 自动识别主键、期间字段或关联关系；
- AI 自动批准或启用阻断级规则；
- 基于历史数据自动学习并持续调整质量阈值；
- AI 自动完成质量问题根因定位和修复；
- 自动生成业务域质量模板并批量继承；
- 基于 AI 反馈自动修改生产质量策略。

### 14.3 后续验收顺序

后续扩展应按以下顺序验收：

```text
自动画像
  → 平台基线
  → 业务模板
  → AI 推荐与人工审核
  → 历史异常检测
  → 脱敏 AI 诊断
  → 治理度量与持续反馈
```

每个阶段都必须继续满足现有 018 需求的期间边界、状态缓存、并发幂等和生产脱敏要求。
