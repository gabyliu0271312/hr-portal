# START HERE：数据质量依赖校验与调度

## 文档目的
本目录定义“同步完成后按影响范围执行数据质量检查，并将结果复用到数据集和报表”的产品、技术、UI、测试和原子任务要求。本期只编写规格，不代表代码已经实现或生产已经部署。

## 开发启动确认
实际开发前必须阅读本文件、`spec.md`、`ui-interaction.md`、`atomic-tasks.md`、`testing-acceptance.md`，检查 `git status`，并补读既有数据仓库/UCP契约。目标是增量增强现有数据质量入口和通用调度，不新建第二套质量或调度中心。

## 扩展规划

AI 数据质量治理的自动基线、业务模板、AI 规则推荐、历史异常检测和脱敏诊断规划见 i-data-quality-governance.md。该文档是本目录现有同步后质量治理需求的扩展，不替代原有规格。

## 核心原则
1. 一张源表一个期间一次校验。
2. 同一数据集复用一次校验结果。
3. 多张报表共享同一份数据集质量状态。
4. 报表运行时只读取缓存状态，不扫描关系键。
5. 同一 `table + period + sync_batch_id` 只允许一个质量任务运行。
6. 生产结果只保存计数、状态和哈希样例，不保存工资金额、员工号或客户明文。
