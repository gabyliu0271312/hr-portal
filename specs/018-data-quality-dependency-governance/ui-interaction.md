# 数据质量依赖校验 UI 交互说明

## 1. 页面入口
复用 `数据仓库 → 数据治理 → 数据质量`，路由 `/warehouse/quality`；不新增独立调度中心。报表页只显示轻量质量状态条。

## 2. 规则列表
```text
┌ 数据质量 ───────────────────────────────────────────────┐
│ [规则类型▼] [资产类型▼] [状态▼] [关键词____] [查询] [新建规则] │
├ 通过 12 | 警告 2 | 阻断 1 | 待检查 3                       ┤
├ 规则 | 资产/关系 | 期间策略 | 级别 | 最近状态 | 影响报表 | 操作 ┤
│ N:1基数 | dataset:15/relation:251 | 同步期间 | 阻断 | 失败 | 1 | ... │
└────────────────────────────────────────────────────────┘
```
字段：规则类型、资产/关系、声明基数、期间策略、严重级别、启用状态、最近检查时间、影响数据集/报表数。操作：查看、编辑、手动检查、定时配置、启停、历史。状态：passed绿、warning橙、failed/block红、pending蓝、未检查灰。

## 3. 新建/编辑关系规则
```text
┌ 新建关系基数规则 ─────────────────────────┐
│ 数据集*       [选择数据集]                 │
│ 关联关系*     [选择关系]                   │
│ 左表/别名     dwd_emp_monthly_allocation   │
│ 右表/别名     dwd_annual_bonus_estimate... │
│ 左侧键        cost_period, code            │
│ 右侧键        month_to_rename, factor_code │
│ 声明基数*     [N:1 ▼]                       │
│ 期间字段      [cost_period ▼]              │
│ 严重级别*     [阻断 ▼]                      │
│ 缺失策略      [警告 ▼]                      │
│ [保存并检查] [保存] [取消]                  │
└───────────────────────────────────────────┘
```
数据集/关系/字段全部来自后端元数据，禁止手填任意表名和 SQL。关系选择后默认回填连接键和基数。配置变更后旧结果标为 pending。

## 4. 诊断详情
```text
┌ 关系质量详情 ──────────────────────────────┐
│ dataset=15 · relation=251 · 期间 202607     │
│ 失败/阻断 · 检查时间 ...                    │
│ 声明基数 N:1 · 实际最大匹配 2               │
│ 右侧重复键 1 · 左侧缺失键 1                  │
│ 影响数据集 1 · 影响报表 1                    │
├ 诊断样例（仅哈希）                           │
│ duplicate_key_hash: 1d72...                 │
│ missing_key_hash: 5fd0...                   │
├ [重新检查] [运行历史] [重建索引]              │
└───────────────────────────────────────────┘
```
不得展示原始键、员工号、客户名、金额、secret/token；无权限时只显示无权限。

## 5. 定时配置与报表状态条
复用 `ScheduleConfigDialog`，`kind=quality_run`、`business_id=rule_id`。计划是兜底机制，不代表每次报表刷新都会检查。

报表状态条：
- passed：正常运行；
- warning：允许运行，顶部显示风险；
- pending：提示正在检查，默认不可导出；
- failed/block：禁止运行/导出，提供查看详情入口；
- 状态接口失败：不得展示为通过，按策略 fail closed。

## 6. UI 状态验收
必须覆盖 `loading`、`empty`、`forbidden`、`pending`、`warning`、`failed`、`error`、`stale`，并保证按钮防重复、状态颜色一致、敏感字段脱敏。
