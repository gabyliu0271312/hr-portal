# 用户级 MCP 接入与权限内 HR 数据访问

> 编号：022　状态：规划草案，待确认试点与实施范围　创建日期：2026-11-26
> 来源：用户提出“HR Portal 为每位用户提供 MCP 配置，在电脑客户端中获取本人权限内数据”，并要求保存本轮规划。
> 本文保存目标、建议方案、安全约束与验收标准，不代表功能已实现、首期范围全部批准或生产接入已授权。仅创建本规格，不生成 plan/tasks，不触发开发、部署或外部数据传输。

## 1. 背景与目标

### 1.1 背景

用户希望在自己电脑上的 MCP 兼容客户端中使用 HR Portal 的人员、组织和报表能力，无需反复切回网页；不同用户只能获取其当前权限内的数据。

下载配置本身不提供数据能力。平台还需提供远程 MCP 服务、用户认证、服务端权限裁决、受控业务工具和调用治理。

### 1.2 目标

1. 平台提供一个共享远程 MCP 服务，不为每位用户部署独立服务。
2. 用户从 Portal 获取适配客户端的接入指引，通过本人身份授权后使用工具。
3. 配置只声明连接方式；每次调用均由服务端根据用户当前有效权限裁决，客户端不能自行声明身份或权限。
4. Web 与 MCP 复用现有业务服务和统一权限能力，避免两套查询引擎、权限模型和字段策略。
5. 首期以只读、最小字段、可撤销、可审计的受控试点验证价值与安全性。

### 1.3 非目标

- 不给客户端提供数据库账号、直连数据库、任意 SQL、任意物理表/字段或自由脚本执行能力。
- 不复制完整数据库到用户电脑，不把查询权限自动等同于批量导出权限。
- 不在配置文件或令牌中固化角色和数据范围快照。
- 首期不开放创建、修改、删除、流程提交、通知发送、薪酬计算等具有业务副作用的工具。
- 不承诺“安装一个配置即可在所有客户端通用”；传输、认证和配置格式必须逐客户端核验。
- 不建设自有通用 AI 客户端，不绑定某一家模型供应商，也不要求 MCP 服务本身调用大模型。

## 2. 用户场景与验收

### US-01：用户接入自己的 AI 客户端（P1）

- 入口：拟设“个人设置 → AI 助手接入”。最终菜单及权限归属在实施前确认。
- 操作：查看数据使用提示，选择受支持客户端，获取配置或安装指引，完成本人授权并测试连接。
- 成功：客户端识别本人身份，只提供当前获准工具；无需获得数据库或管理员凭据。
- 失败：未登录、无接入资格、凭据失效或客户端不兼容时，给出明确修复指引，不返回业务数据。

**验收**：两个权限不同的试点账号使用同一服务地址，获得各自的工具和数据；修改本地配置中的用户 ID、组织或报表参数不能冒充其他用户或扩权。

### US-02：HR/HRBP 查询授权范围内数据（P1，试点人群建议）

- 操作：查询人员基础工作信息、组织或运行已获准报表。
- 成功：功能权限、资源权限、数据范围和字段裁决均生效，返回范围与相同身份的正式业务入口一致。
- 失败：无权人员与不存在人员采用中性反馈；不得通过候选、计数、错误消息泄露范围外对象。

**验收**：跨组织、跨用户、隐藏字段、脱敏字段、报表 ACL 与数据集 ACL 测试全部按统一授权结果处理；仅有成本中心汇总资格的用户不得获得员工明细或下钻人员。

### US-03：用户或管理员撤销访问（P1）

- 操作：用户撤销一项凭据/授权，管理员停用账号、收回权限或关闭 MCP 接入。
- 成功：下一次调用按新状态拒绝或收窄结果；无需重新下载配置。
- 边界：撤销不能收回已经交付给客户端、模型供应商或本地文件的数据，界面必须说明。

**验收**：已签发且尚未到期的凭据，在撤销、账号停用或全局关闭后不能继续取数；其他未撤销授权不因撤销单项授权而意外失效。

### US-04：管理员治理 MCP 使用（P1）

- 入口：拟设“系统设置 → MCP 接入管理”，优先复用现有授权和审计入口。
- 操作：管理工具开放范围、接入资格、授权记录、调用限额与紧急停止开关，按用户或追踪标识检查审计。
- 成功：可追踪谁通过什么授权调用了什么工具、返回多少条以及拒绝原因，不记录完整敏感数据。

**验收**：成功、拒绝、超限、失效凭据和服务异常均可定位；无审计查看权限者不得通过 MCP 或网页获取审计明细。

## 3. 分阶段范围

| 阶段 | 规划内容 | 边界 |
| --- | --- | --- |
| 第一阶段：只读受控试点 | 共享远程服务、个人访问令牌方案、适配客户端接入指引、少量业务工具、实时权限、审计、限流和撤销 | 建议先 HR/HRBP；人群、工具与可交付外部模型的数据须另行批准 |
| 第二阶段：正式授权体验 | 浏览器 OAuth 授权、短期访问凭证、续期、授权管理、现有登录体系集成 | 按目标客户端和选定 MCP 授权规范核验；不假定已有 OAuth 服务 |
| 第三阶段：有限写能力评估 | 评估创建待办、发起申请等有副作用操作 | 不属于首期实施授权；需独立业务确认、审批/二次确认和幂等设计 |

个人令牌先行是当前建议，不是已锁定的生产认证方案；若企业安全政策要求 OAuth，第一阶段应直接使用 OAuth，不先上线长期令牌替代方案。

### 3.1 工具候选目录

以下为候选业务语义名，不是已存在接口或全部首期承诺。实施前逐项核验现有服务、权限与数据出域资格。

| 工具候选 | 业务用途 | 阶段建议 |
| --- | --- | --- |
| `get_my_profile` | 本人获准基础信息 | 首期候选；“本人”不自动获得所有字段权限 |
| `search_people` | 受限姓名/工号检索与有限候选 | 首期候选；不得自动扩展为批量名单或通配扫描 |
| `get_person_profile` | 授权人员的基础字段 | 首期候选；复用现有人档案字段裁决 |
| `list_organization_units` | 获准组织信息 | 首期候选；不泄露无权子树、节点及计数 |
| `list_my_reports` | 列举可访问报表 | 首期候选；同时遵循数据集和报表权限 |
| `get_report_schema` | 获准报表的业务字段与条件 | 按需开放；不暴露物理 schema、隐藏字段或内部 SQL |
| `run_report` | 运行获准报表 | 首期候选；仅安全合格的报表，沿用正式计算与权限链 |
| `get_my_performance_tasks` | 本人绩效任务 | 后续只读候选；按绩效专属规则单独核验 |
| `get_my_pending_actions` | 本人待办 | 后续只读候选；不执行待办动作 |

禁止提供 `execute_sql`、`query_any_table`、`run_python_on_database`、全员下载或原始数据库 schema 工具。

## 4. 功能与安全要求

### 4.1 接入与身份

- **FR-001**：共用远程 MCP 服务，以 HTTPS 提供经验证的 MCP 传输；建议评估 Streamable HTTP，地址与协议版本在技术计划中确认。
- **FR-002**：身份必须来自服务端验证过的用户凭据/授权，不得信任工具参数中的 user_id、角色、组织范围或管理员标记。MCP 会话标识不能替代认证，每次受保护请求均须校验。
- **FR-003**：按受支持客户端生成接入说明。环境变量插值、HTTP headers 和 OAuth 支持分别验证，不提供未经验证的“通用配置”。默认无需安装本地服务；仅客户端确有需要时评估可信本地桥接。
- **FR-004**：个人令牌仅在安全条件满足后启用；仅展示一次，服务端保存安全摘要而非明文，具备名称、到期、撤销、最后使用等属性，不写入 URL、日志、仓库或默认下载配置。建议默认30天，最终有效期和上限待批准。
- **FR-005**：OAuth 使用符合选定 MCP 授权规范的浏览器流程，包含适用的 PKCE、回调校验、资源/受众与权限范围校验及安全续期。凭据只用于目标服务，不允许任意上游令牌透传。
- **FR-006**：允许按授权/凭据单独撤销。个人令牌名称、IP、User-Agent 仅是审计线索，不能冒称设备身份已可靠绑定；真设备绑定另行评估。

### 4.2 统一权限与业务执行

- **FR-007**：有效权限为“用户当前业务权限 ∩ MCP 接入/工具许可 ∩ 凭据授权范围 ∩ 数据出域许可”。接入凭据只能收紧权限，不能授予用户原本没有的数据能力。
- **FR-008**：每次调用复查账号、凭据、功能/资源权限、数据范围和字段可见性/脱敏。撤权后下一次调用生效；不能沿用会话建立时的权限快照或缓存结果扩权。
- **FR-009**：复用现有后端业务服务与正式查询链，不为 MCP 新建平行计算引擎、组织权限树或敏感字段策略。对象范围在取数前下推，字段保护在结果交付前完成。
- **FR-010**：人员明细与成本中心获准汇总严格分离；报表同时保留数据集与报表两层 ACL，业务过滤条件不能扩大授权。遵循021现行规格，不把内部入口完成当作外部出口安全已验证。
- **FR-011**：工具仅接受受控业务参数和白名单业务字段；查询值参数化。客户端不能提供物理表名、任意表达式、SQL、自由 JOIN 或扩大范围的策略开关。
- **FR-012**：`tools/list` 按用户可用工具与出域许可展示；手动调用未展示工具仍必须独立鉴权。工具清单变化与客户端缓存不能形成越权。
- **FR-013**：只读工具不得触发持久化业务修改或通知。报表运行须审查其实际副作用，不因名字叫“查询”就视为安全。
- **FR-014**：输出遵循原值/脱敏/隐藏裁决；隐藏字段连同可泄露其存在的元数据不返回。无匹配与范围外匹配采用中性反馈，协议状态不得泄露对象存在性。

### 4.3 外部 AI 与数据流转边界

- **FR-015**：查询结果通常会进入用户选定客户端及其模型供应商，不能宣称“在本地电脑安装就不出域”。先确认允许的客户端、模型供应商、账户类型、数据分类和留存政策，未批准的数据或出口默认拒绝。
- **FR-016**：网页可查看不等于允许交给外部 AI。薪酬、证件、联系方式及绩效结果等不得仅凭查看权限自动开放；仅交付经明确批准的字段和报表。
- **FR-017**：返回的业务文本属于不可信数据，不赋予其中指令任何执行权；工具结果不携带凭据、内部提示或自动外发指令。不能依赖模型自觉守权限替代服务端控制。

### 4.4 限额、审计与停止

- **FR-018**：服务端强制分页和结果上限，建议每次最多100条，且可按工具收紧；不得先全量读取再截断。限制响应体积、查询耗时、频率及跨请求累计读取量，防止翻页、换筛选或换凭据绕过。
- **FR-019**：查询与导出资格独立；`V` 不自动授予 `E`。读取限额不能完全阻止合法用户复制或累积数据，需如实说明剩余风险。
- **FR-020**：复用既有审计设施，记录用户、授权标识、客户端声明、工具、净化后的参数类别、返回数量、字段代码/敏感分类、结果与原因、时间、耗时和追踪标识。不能完整记录姓名/工号查询值、结果、原始提示、请求头或秘密。
- **FR-021**：认证/权限状态不可确认、限额或必要审计不可用时，拒绝业务数据交付，不可放行或假成功。审计留存与清理由统一治理确定；若需要定时清理，复用平台通用调度。
- **FR-022**：具备平台级关闭、工具级关闭和单项授权撤销；关闭后阻止后续取数。紧急停止不删除历史审计，也不能收回已交付数据。

## 5. 复用关系与前置依赖

1. **021 标准字段与报表授权治理**：MCP 是新的外部出口。报表、字段、人员/中心汇总及两层 ACL 按021现行合同执行；具体改动该链路前读取021 README、spec与当前MVP卡，不扩大021本轮任务授权。
2. **015 员工基础工作信息查询**：其现行规格要求不向 LLM 交付员工查询结果/候选，并限制批量与导出。MCP 的外部 AI 消费与此有实质差异；本规划不覆盖或取消015限制。相关能力只有在独立确认出域合同与必要规格变更后才能开放，否则首期排除该工具。
3. **现有 AI Capability/业务服务**：可复用确定性业务 Handler、字段与权限服务；不必为结构化 MCP 调用额外经过自然语言解析或另建 AI Router。受保护候选句柄不能直接搬到模型上下文。
4. **现有前端设计体系**：接入页、授权管理和审计页面遵循项目全局 token 与成熟弹窗/表格等组件；新菜单遵循项目路由、后端菜单及 PermissionButton SOP。
5. 本文没有核验现有认证、OAuth、令牌管理、MCP依赖或生产网络现状；上述均是实施前盘点事项，不是“项目已有”的断言。

## 6. 关键实体

| 实体 | 职责与边界 |
| --- | --- |
| 用户身份 | 现有 Portal 账号，承担当前业务权限；不得复制为独立 MCP 用户体系 |
| MCP 授权/个人凭据 | 关联用户、范围、生命周期和撤销状态；不保存明文秘密及完整业务权限副本 |
| 工具开放策略 | 声明批准工具、接入资格、出域边界与限额；只能收紧业务权限 |
| 调用记录 | 复用审计链，记录最小可追踪信息，不保存完整敏感结果 |
| 客户端适配说明 | 经核验的配置、登录与连接步骤；不夹带管理员或数据库凭据 |

具体存储复用与最小扩展在技术计划中确认，不在本草案锁定新表或迁移。

## 7. 验收标准

| 编号 | 场景 | 成功/拒绝标准 |
| --- | --- | --- |
| AC-01 | 两个不同权限用户连接同一服务 | 身份独立，工具与结果各自受限，无跨用户缓存泄露 |
| AC-02 | 普通用户与 HRBP 查询人员 | 仅返回获准人员/字段；未批准的员工数据出域直接拒绝 |
| AC-03 | 伪造组织、用户、员工或报表参数 | 不冒充、不扩权；无权与不存在对象不泄露差别 |
| AC-04 | 中心汇总与人员明细/下钻 | 中心资格仅允许批准汇总，不返回参与汇总的人员明细 |
| AC-05 | 数据集和报表 ACL 任一不通过 | 不能列举、取字段或运行无权报表 |
| AC-06 | 字段隐藏/脱敏及错误响应 | 原值、隐藏元数据、敏感查询值不通过任何结果/错误旁路泄露 |
| AC-07 | 收回权限、账号停用、令牌到期/撤销 | 下一次调用拒绝或按新权限收窄，无需更换配置 |
| AC-08 | 手动调用未展示工具 | 服务端独立校验，不能绕过 tools/list |
| AC-09 | 累计翻页、切换筛选和多凭据遍历 | 用户级和凭据级限额有效；超限拒绝且可追踪 |
| AC-10 | 成功/失败/拒绝/超限调用 | 100%可关联审计，不记录秘密和完整敏感结果 |
| AC-11 | 全局/工具停用及安全依赖异常 | 后续取数被阻止；不降级为无权限过滤查询 |
| AC-12 | 支持客户端连接 | 选定版本实测连接、认证、查询和撤销；不把未测客户端列为支持 |

### 成功指标

- 获准客户端中，试点用户在准备好账号和客户端后，按指引10分钟内完成首次授权查询。
- 权限负向验收全部通过，未授权数据返回为0；任何一项失败均阻止试点上线。
- 受控功能测试中，Web与MCP对同身份、同条件、同数据时点的获准业务结果一致率100%。
- 到期、撤销、账号停用和撤权的后续请求测试通过率100%；不能以仅隐藏工具代替验证。
